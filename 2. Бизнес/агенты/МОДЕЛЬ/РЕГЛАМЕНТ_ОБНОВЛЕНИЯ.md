# Регламент обновления данных агента `@модель`

Цены и рейтинги в кэше **не подтягиваются автоматически** из интернета. Перед рекомендациями в чате проверяйте поле `last_updated` в [`_ДАННЫЕ/models_cache.json`](_ДАННЫЕ/models_cache.json).

## Чеклист (5–10 минут)

1. **Резервная копия** (из каталога `агенты/МОДЕЛЬ/`):
   ```bash
   python3 scripts/backup_cache.py
   ```
2. **Сверка с источниками** — тарифы и актуальность моделей:
   - см. [`_КОНТЕКСТ/источники_данных.md`](_КОНТЕКСТ/источники_данных.md);
   - типичные точки сверки: сайты провайдеров (Anthropic, Google, OpenAI, DeepSeek), при необходимости OpenRouter.
3. **Правки JSON** (по смыслу):
   - [`_ДАННЫЕ/models_cache.json`](_ДАННЫЕ/models_cache.json) — цены (`price_input` / `price_output`), метрики, новые/снятые модели, `refresh_note`, при необходимости `sources`;
   - [`_ДАННЫЕ/fast_track_rules.json`](_ДАННЫЕ/fast_track_rules.json) — ключевые слова и целевая модель для Fast Track;
   - [`_ДАННЫЕ/metadata.json`](_ДАННЫЕ/metadata.json) — `last_updated`, блок `update_dates` под ваши источники.
4. **Проверка**:
   ```bash
   python3 scripts/validate_cache.py
   ```
   Код выхода должен быть `0`.
5. **Коммит** (если используете git) — только после успешной валидации.

## Что не входит в этот регламент

- Автоматическая выгрузка рейтингов с LMSYS/OpenRouter без отдельной настройки (скрипты, ключи, частота). При появлении — оформить отдельной задачей.
- Расширенные файлы из старых чертежей README (`recommendations_cache.json`, `эвристики.json` и т.д.) — только если вы их заведёте вручную.

## Команда в чате

`@модель обнови информацию о моделях` — может помочь составить план и список ссылок, но **не заменяет** правку JSON и `validate_cache.py`.
