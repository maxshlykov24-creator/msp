## 1. Целевой процесс (кратко)

Дима выставляет флажок напротив нужных строк в существующей Google Sheets → система автоматически создаёт отгрузки (`Demand`) в МойСклад с нужным SKU, кол-вом и атрибутами → Серёжа видит список задач в МойСклад, назначает ответственных сборщиков, меняет статусы → все остатки на складе актуальны в реальном времени → ШК на товар и короб печатаются из МойСклад в один клик.

---

## 2. Целевая схема по зонам

### Учёт («МойСклад»)

**Документооборот:**
- `PurchaseOrder` (Заказ поставщику) → создаётся Димой перед закупкой
- `Supply` (Приёмка) → Серёжа закрывает по факту; система фиксирует расхождение
- `Demand` (Отгрузка) → создаётся автоматически из Google Sheets по флагу; 1 Demand = 1 короб = 1 SKU
- Остатки обновляются автоматически по всем документам

**Склады:**
- `Основной склад (Белград)` — хранение RUSbrend + Gripon (единый физический склад)
- `Фулфилмент` — отдельный склад или признак контрагента для клиентского товара

**Разделение RUSbrend / Gripon:**
- Атрибут номенклатуры `Магазин` = `РУСбренд` / `Гриппон`
- Фильтрация остатков по этому признаку

**Статусы отгрузки:**

| Статус | Смысл |
|--------|-------|
| `Новая` | Создана скриптом, не назначена |
| `В сборке` | Серёжа назначил ответственного |
| `На проверке` | Сборщик завершил, ждёт проверки Серёжи |
| `Проверено` | Серёжа проверил содержимое короба |
| `Отправлена` | Уехала с курьером |
| `Отменена` | Ручная отмена |

> **Зачем два статуса вместо "Готова":** сборщик не может сам финализировать короб — это исключительно роль Серёжи. Снижает ошибки упаковки.

**Номенклатура:**
- ~90 позиций из матрицы: артикул, наименование, OZN-баркод, вес, упаковочная единица (кол-во в коробе)
- Атрибут `Магазин` (РУСбренд / Гриппон / Фулфилмент-клиент)
- Атрибут `Тип_короба` (S / M / L) — для шаблона этикетки

**Шаблоны печати:**
- Шаблон этикетки на **товар** (баркод + артикул + наименование)
- Шаблон этикетки на **короб** (артикул + кол-во + магазин + дата)

### Интеграция (Google Sheets → МойСклад)

- **Инструмент:** Google Apps Script, прикреплённый к таблице "Склад Белград"
- **Триггер:** `onChange` — Серёжа ставит флажок в столбце I (правее "Итого коробов") в листе "План работы"
- **Действие скрипта:**
  1. Читает строку: артикул, магазин, кол-во коробов (H)
  2. Находит товар в МойСклад по артикулу → берёт кол-во в коробе из атрибутов
  3. Создаёт N отгрузок (N = кол-во коробов из H) со статусом `Новая`; записывает ID сразу после каждого создания
  4. Записывает ID созданных отгрузок в столбец J
- **Источник истины по номенклатуре:** МойСклад (кол-во в коробе — из атрибута, не дублируется в Sheets)
- **Аутентификация:** МойСклад API токен в Script Properties (не в коде)
- **Кто ставит флаг:** Серёжа (в ближайшем будущем — полностью его зона)

## 3. Метрики успеха

| Метрика | Как измеряем | Baseline | Цель через 30 дней |
|---------|--------------|----------|--------------------|
| Расхождения при приёмке зафиксированы в системе | Кол-во Supply с отклонением | 0 (не фиксировались) | 100% поставок оформлены через Supply |
| Отгрузки без записи в МойСклад | Кол-во отгрузок без Demand | 100% | 0% |
| Время Серёжи на печать этикеток | Субъективная оценка | baseline ~30 мин/день | -50% |
| Инциденты "короб не уехал" | Кол-во возвратов паллеты | ~1-2/мес | 0 (цель) |
| Актуальность остатков | Совпадение МойСклад vs. физический счёт | нет данных | <2% расхождение |

## 4. Фазы (согласовано с ТЗ)

### MVP (Вариант 1, ~2-3 нед.)

1. Настройка МойСклад: аккаунт, организация, склады, номенклатура (импорт ~90 SKU)
2. Настройка статусов Demand, шаблонов печати
3. Google Apps Script: триггер + создание Demand по флагу
4. Регламент для Серёжи и сборщиков (1-2 страницы, пошагово)
5. Тестовый прогон 1 неделя в боевом режиме + отладка

### Phase 2 (после MVP, по запросу)

- Заказ поставщику (PurchaseOrder) из МойСклад → автосверка с фактом приёмки
- Более детальная аналитика остатков по магазинам (RUSbrend vs Gripon vs Фулфилмент)
- Уведомления в Telegram при смене статуса отгрузки

### Phase 3 (Вариант 2, отдельный проект)

- Мини-сервис сканирования: Серёжа сканирует ШК всех коробов перед погрузкой
- Автосверка с планом поставки → статус "Подтверждена" в МойСклад
- Исключение риска "не догрузили короб"

### Будущие возможные доработки (вне утверждённого scope)

- **ШК Ozon в каждой отгрузке:** интеграция Google Таблица ↔ МойСклад, чтобы быстро проставлять (или подтягивать) штрихкод Ozon на уровне документа **Отгрузка** (`Demand`) — например доп. поле на отгрузке + заполнение из строки плана / выгрузки из ЛК Ozon через скрипт, без ручного переноса в каждую карточку. Детали (источник ШК, момент появления в цепочке FBO) — при постановке задачи.

## 5. Ограничения и допущения

- МойСклад **не заменяет** Ozon ЛК — поставка в Ozon по-прежнему создаётся там; МойСклад ведёт внутренний учёт
- ЗП-таблица ("Белград") **не переносится** в МойСклад в рамках Варианта 1
- Google Apps Script запускается от имени Google-аккаунта с доступом к Sheets; API-токен хранится в Script Properties
- Если МойСклад недоступен — скрипт пишет ошибку в служебный лист; ручной повтор
- Gripon и RUSbrend в одном аккаунте МойСклад — разделение через атрибут, не через организацию
