# Справочник amoCRM (выжимка для ТЗ)

**Официальная документация:** https://www.amocrm.ru/developers/content/crm_platform/api-reference  

Используй этот файл как **ориентир по смыслу сущностей**; точные имена полей и возможности — только по актуальной доке и по факту аккаунта клиента.

---

## Модель данных (основное)

| Сущность | Назначение (кратко) |
|----------|---------------------|
| **Leads** | Входящие заявки / лиды до конвертации (если схема с лидами включена) |
| **Contacts** | Люди; телефоны, email, кастомные поля |
| **Companies** | Организации; реквизиты, связь с контактами |
| **Leads → merge** | Конвертация в контакт + сделку (классический сценарий) |
| **Customers / transactions** | Повторные продажи (если используется продуктовая линия Customers) |
| **Catalog elements** | Каталог для связки товаров со сделками (при настройке) |
| **Pipelines & statuses** | Воронки и статусы сделок |
| **Custom fields** | Поля с типами (текст, число, список, дата и т.д.) |
| **Tasks / Notes** | Задачи и примечания; часто для регламентов, не для интеграции «тяжёлых» данных |
| **Events / webhooks** | Подписка на изменения для интеграций |

Точный набор сущностей зависит от тарифа и настроек аккаунта — **не утверждать** наличие функции без проверки у клиента.

---

## API и авторизация (общее)

- Доступ по **OAuth 2.0** и долгоживущим токенам (см. раздел авторизации в документации).
- Базовый URL содержит **поддомен** аккаунта клиента.

---

## Лимиты и надёжность

- В документации указан лимит порядка **7 запросов / сек** на интеграцию (актуализировать при изменении правил платформы).
- При массовых операциях — батчинг, очередь, уважение к `429` / заголовкам retry (если применимо).

---

## Webhooks

- Настройка **хуков** на события (создание/изменение сущностей) — типичная точка входа для middleware.
- **Дубликаты и повторная доставка:** закладывать идемпотентность на стороне приёмника.

---

## Типовые ошибки проектирования

- Путаница **лид vs сделка** и момент конвертации — дубли в МС при неверном триггере.
- Жёсткая привязка к статусам без учёта **нескольких воронок** и прав ролей.
- Игнорирование **обязательных полей** на переходе — сделка не переводится, интеграция «молчит».
