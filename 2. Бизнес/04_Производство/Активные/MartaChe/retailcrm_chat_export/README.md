# Выгрузка переписки (Telegram-бот) из RetailCRM — МАРТАче

Цель: сохранить всю историю чатов из RetailCRM (модуль «Telegram (чаты)» / MG-бот) перед отказом
от подписки RetailCRM и переходом на Wazzup. После отключения тарифа переписка в интерфейсе
RetailCRM станет недоступна — API-выгрузка отдельно от подписки на сам тариф чатов **не гарантирована**,
поэтому делать это нужно **до** отключения/понижения тарифа.

## Почему через API, а не через кнопку в интерфейсе

- В разделе «Диалоги» есть кнопка «Выгрузить таблицу», но она отдаёт **сводные метаданные** диалога
  (статус, даты, канал, клиент), а не текст каждого сообщения построчно.
- Стандартный REST API v5 не даёт массовый экспорт текстов переписки.
- Полный текст переписки живёт в Message Gateway (MG) — сервисе чатов RetailCRM. Достать её можно
  только через **MG Bot API** (`GET /chats`, `GET /messages`), который создан для ботов, работающих
  внутри чатов RetailCRM.
- Сам Telegram-бот (Bot API Telegram) историю не хранит — full history есть только в БД RetailCRM/MG,
  поэтому альтернативы вида «выгрузить из Telegram Desktop» здесь не работают (это не личный номер).

## Как это работает (коротко)

1. `register_bot.py` — регистрирует в аккаунте RetailCRM служебный «bot»-модуль (`integration-modules/{code}/edit`
   с `integrations.mgBot`). В ответ приходит `token` и `endpointUrl` MG Bot API.
2. `export_chats.py` — этим токеном тянет:
   - `/customers` — карточки клиентов (имя, телефон, username);
   - `/chats` — список чатов (кто, какой канал, когда создан);
   - `/messages?chat_id=...` — все сообщения по каждому чату (пагинация по времени, обход и вперёд, и назад,
     с дедупликацией по `id` — точный порядок сортировки в доке не описан однозначно, поэтому подстраховываемся).
3. Результат кладётся в `data/`:
   - `data/raw/chat_<id>.json` — сырой дамп (на случай миграции/повторной обработки);
   - `data/dialogs/<id>_<телефон_или_имя>.html` — читаемая переписка (дата, отправитель, текст, вложения);
   - `data/index.csv` — сводная таблица: клиент, телефон, канал, кол-во сообщений, даты первого/последнего.

## Важное допущение (гипотеза, не проверено вживую)

Не подтверждено, увидит ли новый bot-модуль **исторические** чаты сразу после регистрации, или только новые.
Если `export_chats.py` вернёт 0 чатов/сообщений при регистрации — до того как писать код-фиксы, проверьте:

- В RetailCRM: **Настройки → Интеграции / Чат-центр → Боты** — не появился ли зарегистрированный бот
  в списке и не требует ли ручного включения / выдачи доступа к чатам.
- Если доступа к истории через бота нет — план Б: письмо в поддержку RetailCRM с прямым запросом
  «выгрузите нам полный экспорт переписки (JSON/CSV) по всем диалогам за всё время перед отключением
  тарифа чатов» — так тоже часто делают.

## Запуск

```bash
cd "Бизнес/04_Производство_внедрений/Активные/MartaChe/retailcrm_chat_export"
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# заполнить RETAILCRM_API_URL и RETAILCRM_API_KEY (обычный API-ключ v5 с правом
# редактирования интеграционных модулей — Настройки → Администрирование → Пользователи → API-ключи)

python register_bot.py
# скрипт допишет в .env строки RETAILCRM_MG_BOT_TOKEN и RETAILCRM_MG_BOT_ENDPOINT

python export_chats.py
```

Скрипт можно безопасно прерывать и перезапускать — уже выгруженные чаты (по наличию `data/raw/chat_<id>.json`)
пропускаются, если не передан флаг `--force`.

## Безопасность и хранение (важно)

Папка `data/` **не должна попадать в git** (в ней телефоны и переписка реальных клиентов — ПДн).
`.gitignore` в этой папке уже это перекрывает. После выгрузки:

- Перенести `data/` на защищённый внешний носитель / приватное облачное хранилище (не в общий vault-репозиторий),
  либо зашифровать архивом с паролем.
- В `.env` — реальный API-ключ и токен бота, тоже не коммитить (см. `.gitignore`).
- Индекс (`data/index.csv`) можно (после проверки) держать без ПДн в отдельной версии для внутреннего учёта,
  если понадобится — но по умолчанию считаем весь `data/` чувствительным.
