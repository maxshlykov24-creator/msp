# Шаг 14 — откат названий МойСклад (name ↔ аналитика)

## Цель

Вернуть **юридическое длинное** наименование в поле `name`, а **короткое** (после шага 3) — в доп. поле **«Название для аналитики»**. Товары, которые изначально не переименовывались (группа B), получают в аналитику копию текущего `name`, если поле пустое.

## Поле в API (подтверждено токеном 2026-05-20)

| UI / API name | ID | Тип |
|---------------|-----|-----|
| **Название для аналитики** | `e38352f9-5473-11f1-0a80-1b76001567a6` | string |

Сейчас в каталоге: **0** заполненных (все целевые SKU пустые).

Константа: `config.py` → `ATTR_IDS["Название для аналитики"]`.

## Входные данные

Файл: `detensor/data/nomenclature_original.csv`

Колонки (после нормализации):

- `article` — артикул (как в `product.article` / доп. поле «Артикул»)
- `name_long` — исходное длинное наименование для `name`

Источники:

1. **Предпочтительно:** экспорт владельца  
   `20260519215507_admin@spine-shop_1208229526 - Sheet0.csv`  
   → скопировать в репо (см. `data/README.md`) и прогнать `scripts/normalize_nomenclature_csv.py`.
2. **Резерв:** `nomenclature_original_from_snapshot.csv` — 84 строки из `all_products.json` (снимок до шага 3). Совпадает с `RENAME_MAP` 84/84, MISS=0.

## Группы SKU

| Группа | Условие | `name` | «Название для аналитики» |
|--------|---------|--------|---------------------------|
| **A** | `article ∈ RENAME_MAP` (84 шт.) | ← `name_long` из CSV | ← `RENAME_MAP[article]` (короткое) |
| **B** | `article ∈ TARGET_ARTICLES` \ A (5 шт.: NIGHT.*) | не менять | ← текущий `name`, если аналитика пуста |

Исключения папок: как в `ms_client.EXCLUDED_ROOTS` (Сырье, ТИМ) — не трогаем.
