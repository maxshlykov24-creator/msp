# Cloud Agent instructions (vault msp)

Репозиторий — личный vault + MS Product. Рабочая ветка: **`main`**.

## Структура

- `_ПРОФИЛЬ/` — владелец: профиль, стиль работы, открытые вопросы
- `_СИСТЕМА/` — устройство системы: MBTI, словарь, логика дерева, именование, версия, якорь inbox, синхронизация
- `_СКИЛЛЫ/` — инструменты команды (`agent-creator`)
- `_ВХОДЯЩЕЕ/` — единый инбокс: `новое/` → `_к_проверке/` → `_обработано/`
- `1. ЛИЧНОЕ/` — личный профиль (private)
- `2. БИЗНЕС/` — клиенты, проекты, `_код/` сервисов
- `3. АГЕНТЫ/` — системные промпты, контекст и логи ИИ-команды
- `99_АРХИВ/` — снятое с маршрута, не удаляется
- `.cursor/rules/` — тонкие правила с триггерами; `alwaysApply: true` у шести дисциплинарных правил (`00-ядро`, `10-источники`, `11-верификация`, `13-логи`, `15-границы`, `16-обращение`) и у кнопки Ио `ceo.mdc`; алиасы `сео.mdc` / `ио.mdc` и остальные кнопки — `false`

## Push

- Push **напрямую в `main`** (`workOnCurrentBranch: true`)
- Не создавать ветки `cursor/...` без явного запроса
- Не коммитить `ДОСТУПЫ*.md`, `.env`, `*.m4a`

## Перед запуском облачного агента

Дерево должно быть чистым. Cursor перед запуском делает `git stash --include-untracked`: 2026-09-03 так ушли 1235 незакоммиченных файлов, накопленных за две недели, — ветку агента в `main` не влили, стэш не применили.

Страховка стоит на трёх слоях, но она не отменяет проверку:

- хук `beforeSubmitPrompt` (`.cursor/hooks/vault-snapshot.sh`) коммитит незакоммиченное перед задачей агента;
- launchd-агент `com.msp.vault-sync` коммитит и пушит каждые 15 минут;
- Протокол 0 требует сказать вслух, если успешного push нет сутки или вне git больше 50 путей.

Если ветка агента всё же создана — влить её в `main` или применить стэш **до** следующей задачи. Незакоммиченный слой в этом vault копится быстро: карты смыслов, транскрипты, документы клиентов.
