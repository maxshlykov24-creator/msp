## 1. Концепция

Приложение-касса — быстрый UI поверх **amoCRM** (сделка = заявка) и каталога **МойСклад**. Свой лёгкий бэкенд — для денежных проводок, сертификатного баланса, очереди Эдвина и сверки смены.

**Сущность «Заявка»** = сделка amoCRM с парой **Тип воронки → Вид**:
- **Оффлайн:** Продажа, Продажа компании, Сертификат (пластик), Аренда, Отложка, Обещание, Не слив, Слив.
- **Онлайн:** Сертификат (электронный), Доставка (СДЭК).
- **Дефекты:** Брак, Химчистка, Перешив, Перепутан размер.
- **Возврат/обмен:** Возврат, Обмен (привязка к исходной заявке).

Поля по виду — динамические (конфиг). Базовые автоматики: номер сделки (amoCRM), клиент по телефону (amoCRM), товары (МойСклад), этап «Успех» → отгрузка/списание в МойСклад.

## 2. Стек

- **Фронт:** Vite + React + TypeScript + Tailwind (прототип уже на нём — переиспользуется как боевой фронтенд).
- **Бэкенд:** Python (FastAPI) — единый стиль с другими сервисами MS Product; БД PostgreSQL.
- **Интеграции:** amoCRM API v4 (long-lived token), МойСклад JSON API 1.2, СДЭК, Telegram Bot API.
- **Хостинг:** VPS (как ms-webhook / loyalty-service), либо Vercel для фронта + VPS для бэка.

## 3. Фаза MVP — рабочая касса `[Medium]`

Цель: продавец оформляет ключевые заявки быстрее, чем сейчас; всё пишется в amoCRM.

1. **Каркас + роли** `[Low]` — вход по роли (консультант/call/РОП), выбор магазина и консультанта.
2. **Список заявок** `[Low]` — из сделок amoCRM, поиск (имя/телефон/№), фильтры по этапу/магазину, карточка заявки.
3. **Каталог товаров** `[Medium]` — поиск по МойСклад (название/артикул), остаток по складам, добавление в корзину; скан штрихкода (камера на телефоне).
4. **Продажа** `[Medium]` — корзина, скидка %/₽, подарок (100%), доставка строкой; мульти-оплата (нал/карты/счета по справочнику), авто-остаток и **сдача**; статус оплаты; этап «Успех» → отгрузка в МойСклад.
5. **Отложка / Обещание / Слив / Не-слив** `[Low–Medium]` — поля и этапы по ТЗ; слив с «Встреча назначена» + дата, перенос полей при смене вида.
6. **Запись в amoCRM** `[Medium]` — маппинг полей (Канал, Цель, Адрес магазина, Резерв до, Платная отложка и т.д.), создание/обновление сделки, перевод этапа.
7. **Адаптив** `[Low]` — десктоп-first + телефон.

**DoD MVP:** консультант на боевом amoCRM проводит продажу, отложку, слив; сделки и поля корректны; отгрузка при «Успехе» создаётся.

## 4. Фаза 2 — деньги и сервисы `[High]`

1. **Журнал платежей (ledger)** `[High]` — проводки оплаты/доплаты/сдачи; итог синхронизируется в поле сделки `Статус оплаты`; кнопка «Доплата».
2. **Сертификаты** `[High]` — реестр (номер, номинал, баланс, тип, гость, срок), оплата сертификатом, авто-гашение, связь «продал ↔ использовал», «Успех» при балансе = 0; просрочка → Провал.
3. **Аренда** `[Medium]` — услуга 6 500, товары без цены, даты (план/факт могут различаться), фото паспорта обязательно, этапы.
4. **Очередь Эдвина (Telegram-бот)** `[Medium]` — «сдача/возврат не выдано» → задача в бота; отметка «отправил»; авто-перевод «не выдано» → «выдано» на след. день.
5. **Закрытие смены + сверка** `[Medium]` — факт vs система по способам оплаты; блок выхода без сверки.
6. **Уведомления о продажах** `[Low]` — в 2 группы (Бауманская/Пятницкая), урезанная инфа.

---

## 5. Фаза 3 — расширение `[Medium–High]`

- **Доставка СДЭК** `[Medium]` — форма с авто-реквизитами отправителя, накладная, статусы Отправлен/Доставлен.
- **Возвраты / обмены / дефекты** `[High]` — привязка к исходной заявке, фотофиксация, брак → авто-перемещение на склад Брака, контроль возврата из ателье/химчистки.
- **Продажа компании / юр.лица** `[Medium]` — счёт, «счёт оплачен/выдано», УПД (если тянет интеграция — иначе техдолг).
- **Статистика/KPI** `[Medium]` — конверсия по консультантам/магазинам, магазин vs call-менеджер; исключать заказы без онлайн-участия.
- **Сплит-комиссии** `[High]` — совместные продажи, перевод между шоурумами, % за чужую отложку.
- **Ведомость Сары** `[Low]` — реферал = бонусы, учёт выплат.
- **Печатные бланки (PDF)** `[Low]` — аренда, отложка (с залогом).
- **Чеклисты/напоминания** `[Low]` — ежедневный чеклист консультанта; истечение отложки/аренды/сертификата.

## 6. Edge cases (фиксировать в реализации)

- Гонка остатков: товар, проданный другим консультантом, при добавлении в корзину.
- Резерв при отложке (поле `Резерв до`) и авто-снятие по сроку.
- Возврат: исходная заявка из «Успех» → «Провал» при полном возврате (подтвердить логику).
- Частичная оплата + сертификат + сдача одновременно.
- Смена вида заявки с переносом заполненных полей (слив → не-слив).

## 8. Допущения и техдолг

- amoCRM — источник истины по сделкам/этапам; касса не плодит вторую базу.
- УПД-автоматизация зависит от возможностей интеграции МойСклад/amoCRM — пометить как риск.
- СДЭК через действующую партнёрку (Yooogi/cdek-amocrm) — уточнить API-доступ.
- Прототип использует мок-данные; форма данных приближена к реальным ответам API для бесшовной замены.
