# ТЗ: Миграция МойСклад → новый аккаунт (ВАН ПАК)

**Дата:** 2026-05-19  
**Исполнитель:** агент (Cursor) + владелец (~45 мин руками)  
**Срок:** 1 день, ~3–3.5 часа активной работы

---

## 1. Цель и контекст

Перенести аккаунт МойСклад клиента Wangpack на новый домен. Старый аккаунт остаётся как архив. Переносится всё: справочники, документы 2026, настройки. Документы до 2026 не переносятся — вместо них создаётся документ «Ввод остатков» на 01.01.2026.

**Старый аккаунт:** `i.korneva@wangpack.ru`, токен `b047463b41ff7d77010fbad1002240fb9d959ebe`  
**Новый аккаунт:** создать, токен — передать в чат агенту

---

## 5. Подводные камни и решения

| # | Камень | Решение в скрипте |
|---|--------|-------------------|
| 1 | UUID не переносятся | Строить `old_uuid → new_uuid` маппинг на каждом шаге |
| 2 | Остатки до 2026 не в документах | GET `/report/stock/all` из старого → POST `enter` в новый |
| 3 | Документы создаются черновиками | Передавать `"applicable": true` при POST |
| 4 | Нумерация теряется | Передавать поле `name` явно при создании |
| 5 | 26 кастомных атрибутов у заказов | Создать атрибуты ПЕРВЫМ шагом, сохранить их маппинг |
| 6 | `customentity` атрибуты (Канал продаж, Способ поставки, Способ оплаты) | Сначала перенести справочники customentity, потом ссылаться |
| 7 | Rate limit 45 req/sec | `time.sleep(0.02)` между пачками, retry на 429 |
| 8 | `employee`-тип атрибутов (Ответственный) | Маппить по имени сотрудника после инвайта |
| 9 | Тариф: >5 пользователей = платный | Оплатить ДО инвайта 6-го пользователя |
| 10 | Шаблоны форм | Только через UI: скачать `.xlsx/.docx`, загрузить в новый |

## 8. Скрипт

`scripts/migrate.py` — запускается агентом после получения токена нового аккаунта.

```bash
# Установка зависимостей
pip install requests tqdm

# Запуск
NEW_TOKEN=<токен_нового_аккаунта> python scripts/migrate.py
```

Скрипт пишет лог в `scripts/migrate.log` и файл маппинга `scripts/uuid_map.json`.
