# Базовые настройки МойСклад (чеклист гигиены)

> Применять на каждом новом проекте до нишевой настройки.
> Проверено на практике (Ван Пак, 2024).

---

## 6 правил кассы для команды

Проверено на практике (Mansband, 2025). Вводить как обязательный регламент перед обучением команды.

1. **Нет телефона — нет клиента.** Без номера система не фиксирует контрагента.
2. **Никаких физических движений без документа.** Нет документа — нет действия.
3. **Любое действие — сразу в системе.** Не откладывать. Данные всегда актуальны.
4. **Продажа засчитывается только при Отгрузке + Входящем платеже.**
5. **Аренда — только с фото паспорта** в файлах связанной отгрузки.
6. **Смена не закрыта без сверки баланса.** Выход из аккаунта только после сверки.

## Блок 0 — Настройки вне документов

| # | Настройка | Зачем |
|---|-----------|-------|
| 0.1 | **Запрет удаления заказов и счетов** | Удаление ломает нумерацию; вместо удаления — статус «Отменён» или «Ошибочный заказ» |
| 0.2 | **Разделить «Отменён» и «Ошибочный заказ»** | Раздельная аналитика: где отказ клиента, где ошибка менеджера |
| 0.3 | **Обязательные поля при смене статуса** | Нельзя перейти на следующий этап без заполнения ключевых полей (канал продаж, способ доставки, оплата) |
| 0.4 | **Бизнес-процессы с ограничением этапов** | Менеджер не может выбрать лишний / неактуальный статус |
| 0.5 | **Права по ролям** | Менеджер видит только свои заказы; склад — только складские разделы; себестоимость — только руководство |
| 0.6 | **Приоритетность автоматически по сумме** | Дорогие заказы всегда в фокусе без ручной расстановки |
| 0.7 | **Постоянные фильтры по ролям** | У каждой роли свой преднастроенный вид: менеджер видит активные заказы, склад — на сборке |
| 0.8 | **Запрет отгрузки в минус** | Отгрузка при отрицательных остатках = ошибки в аналитике и хаос на складе |
| 0.9 | **Обязательный канал продаж** | Без него аналитика по источникам не работает |
| 0.10 | **Префиксы к номерам заказов и счетов** | Разделение по организациям / типам документов без путаницы |
| 0.11 | **Группа сотрудников в системе** | Общий чат для обсуждения ошибок и неудобств — не телефон, а система |

## Паттерн временных ограничений в статусах

Логика та же, что в amoCRM: менеджер получает сигнал первым, руководитель — если не среагировал.

| Статус | Время | Действие |
|--------|-------|----------|
| Новый | +1 день | Уведомление менеджеру |
| В резерве | +7 дней | Уведомление менеджеру (по умолчанию, можно переопределить в поле) |
| Согласован / Ожидаем оплату | +7 дней | Уведомление менеджеру |
| На сборке | +2 дня | Уведомление складу |
| Заказ собран / Ждёт отгрузки | +2 дня (не считая выходных) | Уведомление складу и менеджеру |
| Частично отгружен | +5 недель | Уведомление менеджеру |
| Отсрочка платежа | За 3 дня до срока | Уведомление менеджеру + РОПу |
| Просроченная отсрочка | В день просрочки | Уведомление РОПу |

## Глоссарий МойСклад (для обучения команды клиента)

Проверено на практике (Mansband, Ван Пак). Использовать при обучении (Шаг 3 методологии).

| Термин | Определение |
|--------|-------------|
| Разделы | Верхний уровень: Закупки, Продажи, Товары, Контрагенты, Склад, Деньги |
| Подразделы | Внутри разделов: Заказы покупателей, Отгрузки, Входящие/Исходящие платежи, Возвраты, Перемещения |
| Контрагент | Карточка клиента. Обязательны: Имя и Телефон |
| Канал продаж | Источник = откуда пришёл клиент. Обязательное поле |
| Остаток | Общее количество товара, включая резервы |
| Резерв | Бронирование — вычитается из остатка |
| Доступно | Остаток − Резерв = реально доступное для продажи |
| Заказ | Заказ = Сделка. Все в разделе Заказы покупателей |
| Статус | Статус = Этап. Текущий статус работы с клиентом |
| Входящий платёж | Фиксация поступления денег. Кому, сколько, каким способом |
| Отгрузка | Физическая передача товара → списание с остатков |
| Возврат покупателя | Документ-отмена Отгрузки → товар обратно на склад |
| Баланс | Итог взаиморасчётов: сумма Заказа − сумма Входящих платежей |
| Связанные документы | Цепочка: Заказ → Платёж → Отгрузка → Возврат |
| Флажок Проведено | Активный статус документа. Только при нём учитываются деньги и товар |

## Аудит расходов на CRM и склад (чеклист для клиента)

Предлагать каждому клиенту после 3–6 месяцев работы.

**Что делаем:**
1. Список всех подписок + дата окончания
2. Разбивка: МойСклад / amoCRM / интеграции
3. Среднее в месяц по каждой категории
4. Выявление дублей и неиспользуемых подписок
5. Оптимизация: пакетные тарифы, годовые скидки, замена дорогих решений
