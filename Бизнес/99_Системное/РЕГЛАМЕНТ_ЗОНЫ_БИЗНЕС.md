# Регламент зоны `Бизнес/`

> Единые правила для людей и ИИ: что создавать, куда складывать, когда нужен README. Глобальные договорённости по работе в Cursor — в [`.cursorrules`](../../.cursorrules) и [`СИНХРОН_С_АССИСТЕНТОМ.md`](../../СИНХРОН_С_АССИСТЕНТОМ.md).

---

## Модель «офисного здания»

Одна карта: метафора **не заменяет** нумерацию операционных зон (`01_`…`08_`), а объясняет, зачем нужны уровни и README. Вторая параллельная оргструктура в vault не вводится.

| Метафора | Где в `Бизнес/` |
|----------|-----------------|
| Главный вход, распределение потока | [`00_Inbox`](../00_Inbox/README.md) → раскладка по этажам |
| Этаж (функция компании), до 9 основных зон | `01_` … `08_` — операционные «отделы»; [`99_`](README.md) — системный слой (профиль, регламенты, скрипты, обучение), не конкурирует с `01_`–`08_` |
| Типовые отделы (соответствие) | Администрация / цели → `01_`; Финансы → `02_`; Продажи → `03_`; Производство (внедрения, проекты) → `04_`; Маркетинг → `05_`; Продукт и упаковка → `06_`; Поддержка клиентов → `08_`. *Префикс `07_` в нумерации зон зарезервирован под будущую схему ИИ-агентов по материалам курса; отдельной папки `07_*` на диске пока нет.* |
| Кабинет (подразделение, клиент, тип работ) | Подпапка на этаже **с `README.md`** (например `04_/Активные/КЛИЕНТ/`, `04_/Шаблоны_ТЗ/`) |
| Шкаф (класс документов) | Ещё один уровень **только** если в одном кабинете реально смешиваются разные классы (например отчётность: ДДС / ОПиУ) и их путают; иначе — файлы в кабинете или префиксы имён |
| Документы | Файлы в кабинете / шкафу |
| Вывески, индексация для людей и ИИ | `README` на этаже (корень зоны) и в каждом новом кабинете; периодически — ICQ (§6) |

**Правило глубины:** не создавать вложенность «на вырост». Новый уровень — если без него нельзя за несколько секунд ответить: «куда кладу этот файл?» и «кто за эту зону отвечает?».

---

## 1. Входящий поток

- Файл по работе или клиенту **без явного адреса** — сначала в [`../00_Inbox`](../00_Inbox/README.md).
- После наполнения — раскладка: список → целевая зона → перенос (вручную или с помощью ИИ по контексту).

---

## 2. Новая логическая папка (внутри `Бизнес/`)

Под **логической** имеется в виду отдельная категория работ (новый клиент, новый тип артефактов), а не одиночный `.md` рядом с остальными в уже описанной зоне.

**Обязательно:**

1. Создать **`README.md`** в этой папке со структурой:
   - краткий тезис в первой строке после заголовка (зачем папка);
   - **О папке** — назначение;
   - **Содержимое** — что хранить (список или таблица);
   - **Как использовать** — правила пополнения и обновления;
   - **Связи** — ссылки на соседние зоны, [`ПРОФИЛЬ_ПРОЕКТА.md`](ПРОФИЛЬ_ПРОЕКТА.md), при необходимости корень [`РАСШИРЕННЫЙ_КОНТЕКСТ.md`](../../РАСШИРЕННЫЙ_КОНТЕКСТ.md).

2. Добавить папку в таблицу «Содержимое» в [`../README.md`](../README.md), если это **новая верхнеуровневая** зона (`01_`…`08_`, `99_`, при необходимости `агенты/`); для вложенных — достаточно README и ссылки из родительского README.

Расширенный шаблон описания папки для ИИ: [`Обучение_MAC/СКРИПТ_README.md`](Обучение_MAC/СКРИПТ_README.md).

---

## 3. Проекты внедрения (клиенты)

- Действовать по [`../04_Производство_внедрений/Активные/README.md`](../04_Производство_внедрений/Активные/README.md): отдельная подпапка, **`README.md`** с сутью, статусом и следующим шагом, при необходимости — ТЗ, схемы, заметки.

---

## 4. Исключения (README не обязателен отдельно)

- Одноразовый черновик или один файл внутри уже описанной папки — без новой подпапки и без отдельного README на каждый файл.
- Технические каталоги без смысловой нагрузки (например кэш скриптов) — по усмотрению; если ИИ должен их понимать, один README на каталог всё же лучше.

---

## 5. Контекст для ИИ

- Типовой набор: `@Бизнес` или конкретная папка + [`ПРОФИЛЬ_ПРОЕКТА.md`](ПРОФИЛЬ_ПРОЕКТА.md) (контекст **компании**).
- Личные договорённости с ассистентом, стиль диалога и границы объёма — в [`СИНХРОН_С_АССИСТЕНТОМ.md`](../../СИНХРОН_С_АССИСТЕНТОМ.md); не смешивать с корпоративными README.
- При смене ниши, стека или модели монетизации **компании** — обновить профиль и при необходимости соседние README.

---

## 6. Контроль качества (ICQ)

Раз в 4–8 недель или после крупного пополнения зоны — прогон по [`Обучение_MAC/ПРОМПТ_ПРОВЕРКИ_ДЗ.md`](Обучение_MAC/ПРОМПТ_ПРОВЕРКИ_ДЗ.md) с контекстом `Бизнес/` (цель ≥ 80%). Подробнее в [`README.md`](README.md) раздел «Контроль качества контекста».

---

## 7. Артефакты ИИ и папки `_ai/`

- В операционных зонах (`01_`–`06_`, `08_`) используются подпапки **`_ai/`** — черновики, отчёты и сводки, сгенерированные ИИ по задачам этой зоны. Имена файлов: `YYYY-MM-DD_Тип_описание.md`.
- Единая схема конфигов корпоративных ИИ-агентов, межагентный обмен и продуктовые шаблоны — **по материалам курса**; самодельную параллельную структуру не вводить без явного решения владельца.
- Передача контекста между зонами — через `00_Inbox`, README зон и согласованные регламенты; отдельной «шины» до появления согласованной схемы нет.
- В корне `Бизнес/` папка [`агенты/`](../агенты/README.md) — только вспомогательные правила Cursor из обучения (например `@модель`); это не слой «агентов компании».
