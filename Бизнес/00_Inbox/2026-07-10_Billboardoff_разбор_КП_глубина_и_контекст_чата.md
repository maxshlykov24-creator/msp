## 3. Что внутри презентации Billboardoff (факт по слайдам)

Структура близка к эталону Keris (обложка → боли → цели → flow → 3 модуля → план/DoD → детали → дашборд → «почему приживётся» → оплата/расходы → финал).

### Ставка и позиционирование
- Kicker: **«Не внедрение amo · Контур продления»**
- Герой: единое окно контроля / продление без потерь
- Акцент: без новой пачки CRM-виджетов; критичная логика контроля на сервере MS Product

### Боли (слайд «Что мешает»)
1. Нет контроля — переписка/звонки не в одном месте; о проблемах узнают от клиентов  
2. CRM не живёт — месяцами не ведут; таблицы и блокноты  
3. Риск потери базы — 3 из 4 менеджеров новички, старых клиентов ведут вслепую  
4. **~80% денег — продление**; поток на памяти менеджера; новичок может испортить клиента 5 лет

### Цели этапа 1
1. Всё в одной карточке (Max, звонки, почта)  
2. Продление как процесс (у сделки всегда следующий шаг)  
3. Контроль на своём сервере (SLA / эскалация)  
4. Оплата видна в сделке (№ счёта из 1С + статус из Точка Банк)

### Flow TO-BE
Клиент пишет → карточка amo → бот-контроль (SLA/эскалация) → продление (задача на шаг) → оплачено (счёт + Точка).  
Примечание: счета остаются в 1С — в amo только статус.

### Три модуля
| Модуль | Суть | DoD (кратко) | Цена в слайде |
|--------|------|--------------|---------------|
| 1 Единое окно | Коммуникации + бот SLA | Max/звонки/почта; SLA; без пачки виджетов | **TBD** |
| 2 Продление | Задачи по месяцу; оплата к сделке | Следующий шаг; № счёта; Точка; «петля без мусора» | **TBD** |
| 3 Контроль | Доказательства; хозяин CRM | Доказательства этапов; дашборд 6 KPI; хозяин обучен | **TBD** |

Опция вне цены: ИИ-контроль качества 100% звонков/переписок.

### Детали, похожие на созвон (не шаблон)
- Max, 1С, Точка Банк, F5 (триггеры снимаем на сервер, остальной F5 без изменений)
- «Утро Сергея — один экран»
- amoCRM оплачено до **30 августа** — логика старта до конца окна
- Хозяин CRM — не Сергей, назначен и обучен
- 4 недели привычки: мягкий старт → задачи → планёрка из amo → правила
- Бонус: 1 месяц amoCRM; оплата по сдаче DoD

### Дашборд (mock)
- Верх: доход текущие/новые/сумма, конструкции, действующие, новые клиенты — пометка «цифры иллюстративные»
- Низ (ближе к ставке): просрочен SLA, эскалация >2ч, пропущенные; цикл продления (счёт / ждут оплату / макет-печать / без следующего шага = 0); задачи на планёрку по менеджерам

## 4. Итоговый вердикт чата

### Коротко
**Фокус есть. Пустой продажи нет. Глубины решения — наполовину.**

| Вопрос | Оценка | Комментарий |
|--------|--------|-------------|
| Владелец чувствует «меня услышали»? | ~7/10 | Продление, новички, 80%, F5/1С/Точка, Сергей, «CRM умерла» |
| Владелец понимает, *что* получит и за сколько? | ~5/10 | TBD, нет недель, нет 3 платежей |
| Мы понимаем, *как* решить? | ~5–6/10 | Боль поймана; петля продления — эскиз, не спецификация |
| Продажа ради продажи? | **Нет** | Это **недожатое решение**, упакованное как КП |

Тревога «поверхностно» **частично верна** (коммерция + механика продления).  
Гипотеза «просто нет фокуса» — **нет**: ставка «контур продления» есть и её нельзя размывать.

Сравнение с эталоном Keris: структура слайдов близка; у Keris закрыты цена/сроки/модули с содержательным DoD и текстовое `ПРЕДЛОЖЕНИЕ.md`. У Billboardoff — сильный тизер идеи без закрытой сделки и без AS-IS на бумаге.

## 5. Разбор вопросов: этапы / обзор / кривые / слабые стороны

| Элемент | Нужен? | Сейчас | Что делать |
|---------|--------|--------|------------|
| **Фокус** | Корень | Есть (продление) | Не размывать «ещё продажи / конструкции» |
| **Обзор AS-IS** | Да | Почти нет — сразу TO-BE | 1 слайд: как сейчас → где рвётся его словами |
| **Этапы/модули** | Да | Есть каркас, цены TBD | DoD + цена + срок; не «недели ради недель» |
| **Кривые конверсии** | Только с данными | Правильно почти нет | Не выдумывать %; 1–2 метрики успеха этапа 1 из их реальности |
| **Слабые стороны** | Да | Частично («почему не умрёт») | Добавить: неизвестное до аудита, границы, что ломает результат без Хозяина CRM |

### Конкретные дыры в HTML
1. **Коммерция не закрыта** — TBD / нет срока / нет графика платежей / нет гарантии срока (эталон Keris).  
2. **Нет AS-IS** — владелец не видит доказательство «вы видели мой день».  
3. **Продление названо, не спроектировано** — нет явной петли вида:  
   `за N дней до конца → счёт → оплата → макет → печать → (монтаж?) → следующий цикл`.  
   Mock намекает; правила и «что такое следующий шаг» не зафиксированы.  
4. **Дашборд размывает ставку** — верхние vanity KPI vs нижний блок (SLA / без шага / оплаты) — низ в точку, верх приглушить или убрать.  
5. **Модуль 3 самый водяной** — «доказательства / дашборд / хозяин» без чеклиста уровня М1.  
6. **Границы** — «1С не трогаем» есть; нет явного «что НЕ входит» и списка неизвестного (канал Max, карта воронки as-is, объём F5).

## 6. Что цепляет владельца (оставить)

- Позиционирование не «внедрение amo», а контур продления  
- 80% денег / новички / клиент 5 лет  
- Max, 1С, Точка, F5, дата оплаты amo  
- «1С не трогаем»  
- Блок «почему CRM не умрёт» + Хозяин CRM  
- ИИ-контроль вынесен за цену этапа 1  
- Оплата за DoD, не «за настройку»

## 7. План доработки (приоритет)

1. Цена + срок (недели) + 3 платежа + формулировка оплаты по DoD (+ гарантия срока по эталону — по решению).  
2. Слайд AS-IS: сейчас → разрыв.  
3. Петля продления Billboardoff: шаги, триггеры, определение «следующего шага».  
4. Дашборд: утренний экран Сергея (SLA, без шага, оплаты, риск продления); vanity — убрать/приглушить.  
5. Слабые стороны / границы / неизвестное — 4–6 строк.  
6. Модуль 3 — конкретный чеклист сдачи, как у М1.

**Не обязательно сейчас:** рисовать кривые конверсии без их цифр.

## 8. BOOP (фиксация из чата)

- **Цель:** КП, после которого Сергей думает «они поняли продление и я вижу, за что плачу» — не «красиво продают CRM».  
- **Препятствие:** идея сильнее спецификации и коммерции; в vault нет `КОНТЕКСТ.md` / AS-IS.  
- **План:** закрыть пункты §7 → затем полировка визуала; параллельно завести папку клиента и выгрузить созвон в контекст.
