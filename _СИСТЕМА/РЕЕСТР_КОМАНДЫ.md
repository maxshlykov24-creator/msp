# Реестр команды

> **SSOT иерархии цифровой организации.** Кто есть в команде, как зовётся, какой папкой владеет.
> Меняет только Архитектор и только после явного «да» владельца.
>
> Развёрнуто 2026-08-19, Модуль 2. Методология курса «Внедрение ИИ в бизнес» © 2026 Денис Леушин.

## Иерархия

```
ВЛАДЕЛЕЦ Максим
└── Ио · CEO (маршрутизатор, точка входа любого чата)
    │
    ├── СЛУЖБЫ (читают всю систему)
    │   ├── Архивариус — файлы, входящее, индекс, именование
    │   ├── Аудитор — светофоры полноты карт
    │   ├── Архитектор — структура организации (спит до запроса)
    │   └── Транскрибатор — расшифровка и раскладка смыслов в SSOT
    │
    ├── БИЗНЕС · MS Product (5 отделов)
    │   ├── Соломон — Стратегия
    │   ├── Руководитель Продаж
    │   ├── Руководитель Производства (техсопровождение внутри)
    │   ├── Руководитель Продукта
    │   └── Руководитель Финансов (единый контур с личным)
    │
    └── ЛИЧНОЕ (7 отделов)
        ├── Руководитель Ритма
        ├── Руководитель Духа
        ├── Руководитель Обучения
        ├── Руководитель Людей
        ├── Руководитель Семьи
        ├── Руководитель Устойчивости
        └── Анатолий — Тело
```

Все 12 руководителей в режиме **«играю»**: людей в подчинении нет ни в бизнесе, ни в личном (карта бизнеса §9). Владелец — единственный исполнитель и приёмщик.

## Как работают алиасы

Каждый агент — файл `.mdc` в `.cursor/rules/` с `alwaysApply: false` и пустыми `globs`. Исключение: `ceo.mdc` у Ио висит `alwaysApply: true`. Алиасы `сео.mdc` и `ио.mdc` остаются `false`. Cursor распознаёт `@имя_файла` в чате сам, дополнительной логики не нужно.

Два способа позвать:
1. **Явно:** `@dept-продажи`, `@соломон`, `@ио`, `@транскрибатор`.
2. **По смыслу фразы:** в `description` каждого правила лежат рабочие формулировки владельца. «Что ответить клиенту на "дорого"» поднимает продажи без `@`.

`@ceo` работает всегда — страховка, даже если у CEO есть имя.

## Реестр скиллов

| Скилл | Кто использует | Триггер | Эффект |
|---|---|---|---|
| `agent-creator` | Ио | «создай агента», «мне не хватает», «хочу делегировать» | Новый сотрудник по контракту готовности |
| `department-builder` | Архитектор | `@архитектор добавь отдел X` | Отдел из карты смыслов плюс правило-кнопка |
| `inbox-classifier` | Архивариус | Новый файл в `_ВХОДЯЩЕЕ/новое/` | Карточка верификации в `_к_проверке/` |

## Зоны влияния

| Агент | Читает | Пишет |
|---|---|---|
| Ио (CEO) | всё | `3. АГЕНТЫ/CEO/`, `_ПРОФИЛЬ/` по согласованию |
| Архивариус | всё | `_ВХОДЯЩЕЕ/`, индексы отделов, `99_АРХИВ/` |
| Аудитор | всё (только чтение) | свои логи |
| Архитектор | всё системное плюс обе карты | `_СИСТЕМА/`, состав отделов |
| Транскрибатор | всё | `.md` по карте путей; SSOT клиента / хвосты после «да» |
| Руководитель отдела | свою папку плюс `_СИСТЕМА/ОБЩАЯ_БАЗА_СМЫСЛОВ.md` | свою папку |

Между руководителями прямой связи нет — только через Ио (правило `15-границы`).

## Маршрутизация задач

| Тип задачи | Кому |
|---|---|
| «разложи это», «куда положить», «найди файл» | Архивариус |
| «проверь карту», «светофор», «отчёт для куратора» | Аудитор |
| «добавь отдел», «объедини», «убери отдел» | Архитектор |
| «напиши ТЗ», «нужна интеграция amoCRM и МойСклад», «инструкция для роли» | Архитектор |
| «транскрибатор», ссылка / аудио / созвон | Транскрибатор через Ио (Протокол 10) |
| «нужен новый сотрудник», «хочу делегировать» | Ио через `agent-creator` |
| Вопрос по конкретной теме отдела | руководитель этого отдела |
| Стратегия, приоритеты, ретро, размытая многошаговая задача | Ио |
