# Чеклист SEO-аудита и QA

Используют: `@сео` (контроль качества); черновики контента даёт исполнитель по **ПАКЕТУ «ТЕКСТ»**.

Отметки: **Pass** / **Fail** / **N/A**. При Fail — краткая формулировка и что делать (правка ТЗ / новый раунд исполнителя).

---

## 1. Техническая база

| # | Пункт | Примечание |
|---|--------|------------|
| 1.1 | Индексация критичных страниц (выборочно по списку URL в ТЗ) | Нужны данные GSC / ручная проверка |
| 1.2 | Robots.txt не блокирует важные разделы | Изменения только с подтверждением владельца |
| 1.3 | Sitemap актуален (структура, последние URL) | |
| 1.4 | HTTPS, редиректы www/non-www согласованы | |
| 1.5 | Canonical на дублях (если есть дубли в ТЗ) | |
| 1.6 | Core Web Vitals / скорость — нет «красной» зоны на главной и ключевых URL | Если данных нет — N/A + запрос выгрузки |
| 1.7 | Мобильная пригодность страниц под пометку в ТЗ | |

---

## 2. On-page

| # | Пункт | Примечание |
|---|--------|------------|
| 2.1 | Title уникален, отражает интент, нет переспама ключом | Лимиты из ТЗ или ~55–65 символов |
| 2.2 | Description призывный и соответствует телу страницы | ~140–160 символов |
| 2.3 | Один H1 на страницу, совпадает с темой кластера | |
| 2.4 | Иерархия H2/H3 логична для скана и интента | |
| 2.5 | ALT у ключевых изображений (если есть медиа в ТЗ) | Без переспама |
| 2.6 | ЧПУ и breadcrumbs по возможности | Если CMS позволяет |
| 2.7 | Разметка schema.org при необходимости (FAQ, Article, LocalBusiness) | Черновик от исполнителя текста или отдельный регламент |

---

## 3. Контент и интент

| # | Пункт | Примечание |
|---|--------|------------|
| 3.1 | Интент кластера закрыт полностью (нет «полухабов») | Сверка с ТЗ семантики / блоком ТЗ_НА_ТЕКСТ |
| 3.2 | Объём достаточен для конкурентности ниши или явно обоснован | Без воды |
| 3.3 | Главный и вторичные ключи по правилам ТЗ (точное/разбавка) | |
| 3.4 | LSI по смыслу раскрыт тему | Не списком «галочка» |
| 3.5 | E-E-A-T: авторство/опыт/конкретика там, где требует ниша | Особенно YMYL / B2B |
| 3.6 | FAQ (если в ТЗ) закрывает длинный хвост вопросов без дубляжа основного текста | |
| 3.7 | CTA соответствует типу страницы (коммерция vs статья) | |
