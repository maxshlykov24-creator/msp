# Подключение Bitrix24

Цель: когда в Bitrix24 завершается звонок с записью — наш сервис получает событие, дотягивает ссылку на запись по API, скачивает её и присылает транскрипт в Telegram.

## Важное отличие от AmoCRM
Событие об окончании звонка (`ONVOXIMPLANTCALLEND`) **не содержит ссылку на запись** — только `CALL_ID`. Ссылку забираем отдельным запросом `voximplant.statistic.get` по этому `CALL_ID`. Поэтому для Bitrix **обязателен входящий вебхук с правами на телефонию**.

## Шаг 1. Входящий вебхук (для чтения записи)
1. Bitrix24 → **Разработчикам** → **Другое** → **Входящий вебхук**.
2. Права доступа: **Телефония (telephony / voximplant)**, **CRM** (для записи комментария обратно — опционально).
3. Скопировать URL вида: `https://ВАШ_ПОРТАЛ.bitrix24.ru/rest/1/abcdef123456/`
4. В `.env`:
   ```
   BITRIX_WEBHOOK_BASE=https://ВАШ_ПОРТАЛ.bitrix24.ru/rest/1/abcdef123456/
   ```

## Шаг 2. Исходящее событие (чтобы Bitrix дёргал наш сервис)
Способ 1 — **исходящий вебхук**:
1. Bitrix24 → **Разработчикам** → **Исходящий вебхук**.
2. Событие: **`ONVOXIMPLANTCALLEND`** (завершение звонка).
3. URL обработчика: `https://ВАШ_ДОМЕН/webhook/bitrix-call`
4. Сохранить.

Способ 2 — **робот/бизнес-процесс** в CRM: на нужной стадии повесить «Исходящий webhook» на `https://ВАШ_ДОМЕН/webhook/bitrix-call`, передав `CALL_ID` сделки.

## Как это работает
1. Звонок завершился → Bitrix шлёт событие с `CALL_ID` на `/webhook/bitrix-call`.
2. Сервис отвечает 200 и в фоне вызывает `voximplant.statistic.get` по `CALL_ID`.
3. Из ответа берёт `CALL_RECORD_URL`, телефон, длительность, id сделки.
4. Скачивает запись, расшифровывает, шлёт транскрипт в Telegram.

## Проверка
- Сделайте звонок через телефонию, привязанную к Bitrix24.
- В логах: `[bitrix] звонок обработан`; в Telegram — транскрипт.
- Если запись ещё не готова в момент события — в логах `ссылка на запись не найдена`. Запись в Bitrix появляется с небольшой задержкой; при необходимости можно вешать событие на стадию чуть позже либо добавить повтор.

## Частые проблемы
- **`BITRIX_WEBHOOK_BASE не задан`** — заполните входящий вебхук в `.env` (шаг 1).
- **Нет прав** — у входящего вебхука должно быть право на телефонию.
- **Запись не скачивается** — ссылки телефонии часто доступны только с российского IP (см. `ЗАПУСК.md`).
