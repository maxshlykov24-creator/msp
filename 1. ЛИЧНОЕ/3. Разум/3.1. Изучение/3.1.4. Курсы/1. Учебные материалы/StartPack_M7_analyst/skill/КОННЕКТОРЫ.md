# Коннекторы · как подключить источник данных

Пять способов завести данные в аналитика — от «кинул файл» до «подключи что угодно по API». Бери самый простой, который закрывает задачу. Усложняешь только когда упёрся.

---

## ① CSV drag&drop — самое простое
Выгрузил отчёт из CRM / 1С / рекламного кабинета в CSV или Excel → кинул файл прямо в Cursor → агент его читает.

1. В CRM/1С/кабинете жми «Экспорт» → CSV (или XLSX).
2. Перетащи файл в окно Cursor (или положи в папку проекта).
3. Скажи: «проанализируй эту таблицу» — агент разбирает схему, нормализует, кладёт в `_ДАННЫЕ/raw/`.

Для разового разбора этого хватает. Минус — данные замёрзли на момент выгрузки.

---

## ② Google Sheets «Опубликовать в вебе» → CSV-URL — БАЗА ДЛЯ ТЕБЯ
Ноль настройки API. Таблица сама отдаёт свежие данные по ссылке. С этого начинаем.

Пошагово (реальные пункты меню Google Таблиц):
1. Открой таблицу → **Файл → Поделиться → Опубликовать в интернете**.
2. Вкладка **«Ссылка»**.
3. В левом выпадающем списке выбери **нужный лист** (не «Весь документ», а конкретный — так чище).
4. В правом выпадающем выбери формат **«CSV»** (значения, разделённые запятыми).
5. Жми **«Опубликовать»** → подтверди.
6. Скопируй ссылку — она вида `https://docs.google.com/spreadsheets/d/.../pub?gid=0&single=true&output=csv`.
7. Дай ссылку агенту: «вот данные по продажам, тяни отсюда». Он читает по URL (`curl` / `WebFetch`).

Важно: ссылка **всегда отдаёт свежие данные**. Поэтому работает и для разового анализа, и для live — обновил таблицу, агент при следующем запросе видит новое. Менять ничего не надо.

---

## ③ MCP-коннектор google-sheets — АПГРЕЙД
Когда таблиц много и публиковать каждую лень (или они приватные).

1. Одна **OAuth-авторизация** коннектора в Cursor: **Settings → MCP / коннекторы** → подключаешь google-sheets → разрешаешь доступ к аккаунту.
2. Дальше агент читает **любые таблицы аккаунта по названию**, без всякой публикации.
3. Инструменты: `get_sheet_data` (данные листа), `get_multiple_spreadsheet_summary` (сводка по нескольким таблицам сразу).

Плюсы: приватные таблицы, много листов, ничего не публикуешь наружу. Минус: разовая настройка авторизации.

---

## ④ Яндекс Метрика — трафик и конверсии
Прямой Python к API Метрики. Паттерн готов — `80_СИСТЕМА/СКИЛЛЫ/metrika-аналитик/scripts/metrika.py`.

1. Токен Метрики и ID счётчика → в `.env` (не в репозиторий).
2. Агент тянет через `/stat/v1/data`: трафик, источники, конверсии по целям, воронку.
3. Команды-образцы: `summary` (сводка), `sources` (источники), `funnel` (воронка), `goal_reaches` (цели), `compare <p1> <p2>` (сравнение периодов).

Это маркетинговый блок дашборда (CPL по каналам, органика, динамика заявок).

---

## ⑤ Любой сервис с API — «подключи что угодно»
Marketplace-аналитика (Wildberries / Ozon), amoCRM / Bitrix, рекламные кабинеты — принцип один:

> Есть API → даёшь агенту **документацию эндпоинта** + **ключ в `.env`** → он сам пишет коннектор (Python, как `metrika.py`), тянет данные, нормализует в `_ДАННЫЕ/`.

1. Найди в сервисе раздел API / «для разработчиков», получи токен.
2. Скинь агенту ссылку на доку нужного эндпоинта (что отдаёт, какие параметры).
3. Положи ключ в `.env`.
4. «Напиши коннектор к <сервис>, тяни <такие-то данные>» — агент пишет скрипт по образцу.

Так подключается практически всё, у чего есть API.

---

## Статичная таблица vs Live-подключение
Один и тот же аналитик работает в двух режимах — выбираешь под задачу.

- **Статичная** — кинул файл (①) или разовую таблицу → разовый анализ. Просто, для одноразовых разборов: «глянь, что по этой выгрузке». Данные замёрзли.
- **Live** — агент привязан к источнику: CSV-URL (②), MCP (③), API Метрики/сервиса (④⑤) → **каждый запрос тянет свежие данные**. Сюда же — бот по расписанию, который сам собирает отчёт утром/еженедельно (см. `../bot-preset/`).

Правило простое: разовый разбор — статичная; регулярная отчётность и митапы — live.
