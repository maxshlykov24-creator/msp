# Инструкция — глубокая загрузка бизнеса

> © 2026 Денис Леушин · Курс «Внедрение ИИ в бизнес»

Длительность: 1–2 часа активной работы ученика + автономный разбор материалов (CEO + Архивариус могут работать дальше без присутствия владельца).

## Структура: 4 фазы

```
Фаза 1: ПРИНЕСИ (15-30 мин с владельцем)
   ↓
Фаза 2: РАЗЛОЖИ (Архивариус, автономно)
   ↓
Фаза 3: РАЗБЕРИ (CEO, автономно, спрашивает только пробелы)
   ↓
Фаза 4: СВЕРЬ (15-30 мин с владельцем — финальная проверка)
```

---

## Фаза 1 — Принеси

**Кто ведёт:** CEO.

**Что делает CEO:**

1. Выдаёт владельцу `_СКИЛЛЫ/business-discovery/ЧЕК-ЛИСТ_ИСХОДНИКОВ.md` одной строкой:
   > «Открой `ЧЕК-ЛИСТ_ИСХОДНИКОВ.md`. Кидай по нему всё что есть в `_ЗНАНИЯ/_ИСХОДНИКИ/<категория>/` или прямо в чат — URL, файлами, текстом. Я не перебиваю. Когда закончил — напиши “всё, разбираем”.»

2. **Не задаёт вопросов.** Не комментирует. Только принимает.

3. По мере поступления URL-сайтов:
   - Если есть инструмент `WebFetch` / `curl` — скачивает страницу, кладёт в `_ИСХОДНИКИ/сайт/` как `<домен>_<страница>_ГГГГ-ММ-ДД.md` (текст).
   - Если нет — оставляет URL в `_ИСХОДНИКИ/сайт/URLS.md` списком.

4. Файлы из чата (вложения) → Архивариус кладёт в нужную категорию `_ИСХОДНИКИ/`.

5. Минимум: 5 пунктов из чек-листа (см. «Минимальный набор для старта»). Если меньше — CEO мягко предлагает добавить хотя бы это.

**Сигнал к концу фазы:** владелец пишет «всё».

---

## Фаза 2 — Разложи

**Кто ведёт:** Архивариус.

**Что делает:**

1. Проходит по `_ЗНАНИЯ/_ИСХОДНИКИ/<категория>/`, для каждого файла:
   - Переименовывает по конвенции `ГГГГ-ММ-ДД_короткое-описание.расш`.
   - Если файл попал не в ту категорию — переносит.
2. Создаёт `_ЗНАНИЯ/_ИСХОДНИКИ/INDEX.md` — карта что где лежит.
3. Помечает дубликаты (один и тот же прайс в двух местах) — выгружает списком CEO.
4. Если непонятно куда — спрашивает владельца ОДИН раз пакетом.

**Сигнал к концу фазы:** `_ИСХОДНИКИ/INDEX.md` готов, противоречия отмечены.

---

## Фаза 3 — Разбери

**Кто ведёт:** CEO. Работает автономно, материалы перед глазами.

**Что делает:** заполняет файлы `_ЗНАНИЯ/` на основе исходников. **Каждое утверждение — со ссылкой на исходник** (формат: `[факт]. (источник: _ИСХОДНИКИ/<путь>)`).

### Алгоритм заполнения по каждому файлу:

#### `О_БИЗНЕСЕ.md`
- Что делаем — выжимка из главной страницы сайта + страницы «О нас».
- Миссия — из брендбука, если есть; иначе оставить пробел в `ОТКРЫТЫЕ_ВОПРОСЫ.md`.
- Реквизиты — из договора-шаблона, КП, подвала сайта.
- Цифры — из финансов (если предоставили) или PROFILE.
- Отличия — из позиционирования на сайте + сравнение с конкурентами.

#### `КЛИЕНТЫ.md`
- Сегменты — извлечь из портретов ЦА если есть; иначе восстановить из реальных кейсов и выгрузки CRM.
- JTBD — из транскриптов звонков, отзывов, формулировок «зачем покупают».
- Возражения — из скрипта продажи, переписок, отзывов с критикой.
- Кейсы — копируешь из `_ИСХОДНИКИ/клиенты/` в табличной форме.

#### `ПРОДУКТЫ.md`
- По каждому продукту: цена + что входит из прайса/КП.
- УТП — формулировка с сайта или вывод из сравнения с конкурентами.
- Тарифы — из прайса, дословно.

#### `ПРОЦЕССЫ.md`
- Воронка — из скриншота CRM + скрипта продажи.
- Регламенты — таблица «процесс → документ → ответственный» из `_ИСХОДНИКИ/регламенты/`.
- Узкие места — из выгрузки сделок (где главные «отвалы» по стадиям).

#### `КОМАНДА.md`
- Если есть оргструктура — оттуда. Если нет — из PROFILE + уточнить у владельца.

### Когда файла недостаточно:
- Не выдумывай. Оставь раздел с пометкой `<нужны данные: что именно>`.
- Допиши вопрос в `_ПРОФИЛЬ/ОТКРЫТЫЕ_ВОПРОСЫ.md` с приоритетом.

### Дополнительные файлы (создать, если есть исходники):
- `КОНКУРЕНТЫ.md` — если в `_ИСХОДНИКИ/конкуренты/` ≥ 2 файла.
- `БРЕНД.md` — если есть брендбук или гайдлайн.
- `ВОРОНКА.md` — если есть скриншоты CRM с цифрами.

### Запиши инсайты:

Параллельно CEO дописывает в `_АГЕНТЫ/CEO/ЛОГИ/ИНСАЙТЫ_О_ВЛАДЕЛЬЦЕ.md` 3–5 наблюдений из материалов:
- Где сильные стороны (то, чем владелец явно гордится).
- Где есть пробел между декларацией и реальностью.
- Какие повторяющиеся темы в кейсах / отзывах.
- Кого по факту обслуживают, даже если декларируют другое.

## Фаза 4 — Сверь

**Кто ведёт:** CEO. С владельцем.

**Что делает:**

1. Выдаёт сводку (5–10 строк):
   > «Загрузил X файлов, заполнил Y разделов. Главное что увидел: [3 опоры]. Пробелов: [N штук, в `ОТКРЫТЫЕ_ВОПРОСЫ.md`]. Противоречий: [список или ноль].»
2. Спрашивает: «Где я ошибся?»
3. Проходит по противоречиям ОДНИМ списком — владелец отвечает пакетом.
4. Обновляет `_ЗНАНИЯ/INDEX.md` — финальная карта.
5. Финал: «Готов. База знаний живая. Что разбираем первым по делу?»

---

## Что делать после discovery

CEO предлагает 2–3 первых практических шага на основе увиденного. Например:
- «Видно, что воронка теряет 60% между демо и оплатой → давай соберём агента-Продажника, который пишет КП по шаблону».
- «У тебя 8 регламентов, но нет онбординг-чек-листа для новых клиентов → создадим».
- «3 кейса из 5 — психологи, но ЦА на сайте размыта → стоит заузить позиционирование».

---

## Анти-паттерны

- ❌ CEO в Фазе 1 начинает уточнять и перебивать — собирай сначала, разбирай потом.
- ❌ В Фазе 3 CEO заполняет «общими словами» без ссылки на исходник — нельзя, всё должно быть с источником.
- ❌ Discovery без минимума материалов (просто разговор) — это онбординг, не discovery. Разворачивай на чек-лист.
- ❌ Запускать discovery второй раз через неделю — нет смысла, лучше точечно обновить нужный файл.
