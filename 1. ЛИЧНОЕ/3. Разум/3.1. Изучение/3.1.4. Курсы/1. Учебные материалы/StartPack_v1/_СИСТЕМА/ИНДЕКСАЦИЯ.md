# Индексация — как Архивариус строит карту знаний

> © 2026 Денис Леушин · Курс «Внедрение ИИ в бизнес»

Этот файл — для Архивариуса (и для любопытных). Объясняет правила, по которым `_ЗНАНИЯ/INDEX.md` остаётся актуальным.

## Цель

Любой агент перед задачей открывает `_ЗНАНИЯ/INDEX.md` и за 30 секунд понимает, какие файлы релевантны. Без индекса — лезет в каждый файл по очереди, тратит контекст.

## Правила построения индекса

### 1. Структура — фиксированные 5 категорий + рост по необходимости

**Базовые (всегда есть):**
- О бизнесе
- Клиенты
- Продукты
- Процессы
- Команда

**Дополнительные (создаются по реальной потребности, не впрок):**
- Конкуренты — когда у тебя реально 3+ файла про конкурентов.
- Статистика — когда регулярно поступают отчёты.
- Договоры — когда их > 5 шт.
- Бренд — когда есть гайдлайн / голос / миссия отдельным документом.
- ...и т.д.

### 2. Одна строка на файл

```
- [ИМЯ_ФАЙЛА.md](путь/ИМЯ_ФАЙЛА.md) — одна фраза описания (что внутри, не «зачем»)
```

Описание — не маркетинговое («важный документ о клиентах»), а функциональное («портреты ЦА с JTBD и возражениями»).

### 3. Сортировка

- Внутри категории — **по дате последней правки**, свежее сверху.
- Базовые 5 файлов в верхнем разделе — **фиксированный порядок** (О_БИЗНЕСЕ → КЛИЕНТЫ → ПРОДУКТЫ → ПРОЦЕССЫ → КОМАНДА).

### 4. Когда обновлять

Архивариус обновляет `INDEX.md`:
- После добавления/удаления файла в `_ЗНАНИЯ/`.
- После переименования.
- После значительной правки содержимого (если изменилось 1-строчное описание).

Не обновляет при мелких правках текста внутри файла.

### 5. Метка времени

В шапке `INDEX.md`:
```
> Дата последней правки: ГГГГ-ММ-ДД
```

Обновляется при каждой записи в индекс. Это сигнал «индекс свежий».

## Что НЕ индексировать

- `_ПРИМЕР_ЗАПОЛНЕНИЯ/` — это эталон, не данные владельца.
- Файлы черновиков и временные.
- Архив — у него свой реестр в `_АРХИВ/README.md`.

## Поиск vs индекс

Когда владелец спрашивает «у меня есть что-то про X?»:
1. Сначала Архивариус читает `INDEX.md` — текстовый поиск по описаниям.
2. Если не нашёл — `grep -ril "X" _ЗНАНИЯ/`.
3. Если и так не нашёл — спрашивает у владельца, в каком контексте упоминалось.

Не делай поиск раньше индекса — это переплата контекстом.

## Как индекс попадает в контекст агента

В `.cursor/rules/00-ядро.mdc` стоит правило: «перед каждой нетривиальной задачей перечитай профиль и инсайты». Дополнительно — каждый доменный агент в своём промпте указывает, какие файлы из `_ЗНАНИЯ/` ему нужны (например, Маркетолог читает `КЛИЕНТЫ.md` и `О_БИЗНЕСЕ.md`).

`INDEX.md` — точка входа, чтобы агент мог быстро решить, какой файл из `_ЗНАНИЯ/` дополнительно подгрузить.
