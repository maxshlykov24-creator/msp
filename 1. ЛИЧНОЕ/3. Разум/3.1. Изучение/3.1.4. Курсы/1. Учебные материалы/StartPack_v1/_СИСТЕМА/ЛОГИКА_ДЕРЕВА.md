# Логика дерева — почему такая структура

> © 2026 Денис Леушин · Курс «Внедрение ИИ в бизнес»

Для тех, кто хочет понять «почему так, а не иначе».

## Принципы

### 1. Префикс `_` для системного

Все системные папки начинаются с подчёркивания. В большинстве файловых менеджеров и в Cursor сортировка ставит их **сверху**. Это удобно: системное всегда на виду, рабочее (`ВХОДЯЩЕЕ`, `В_РАБОТЕ`, `ГОТОВО`) — ниже без префикса.

*Альтернатива:* классический подход «нумеровать папки» (`01_ПРОФИЛЬ/`, `02_АГЕНТЫ/`) — отвергнут, потому что вынуждает помнить порядок и ломается при добавлении новой папки в середину.

### 2. Имена на русском

Целевой пользователь — русскоязычный собственник, для которого английские названия — лишний барьер. Исключение: технические файлы конвенций (`README.md`, `LICENSE.md`, `SKILL.md`, `.cursorrules`) — оставляем как принято в opensource, чтобы не ломать инструменты.

### 3. Глубина не больше 3 уровней

`_АГЕНТЫ/CEO/ЛОГИ/РЕТРО/` — это уже 4-й уровень, и это исключение. По возможности — 2-3.

*Почему важно:* глубокая вложенность съедает контекст агента (длинные пути) и владелец теряется при навигации.

### 4. Один файл — одна сущность

`КЛИЕНТЫ.md` — все клиенты в одном файле, не «КЛИЕНТЫ/Психологи.md + КЛИЕНТЫ/Производство.md». Дробим только когда файл реально не читается за раз (>500 строк).

*Почему:* агенту проще загрузить 1 файл, чем bash-собирать 5.

### 5. Чёткое разделение «системное / данные / работа»

| Тип | Папки | Кто меняет |
|---|---|---|
| Системное | `.cursor/`, `_СИСТЕМА/`, `_АГЕНТЫ/`, `_СКИЛЛЫ/`, `_ПОДДЕРЖКА/`, корневые `.md` | Обновления StartPack |
| Данные | `_ПРОФИЛЬ/`, `_ЗНАНИЯ/`, `_АРХИВ/` | Владелец + агенты |
| Работа | `_РАБОТА/` | Владелец, активная операционка |

При обновлении StartPack v1 → v2 сохраняется только средний и правый столбец. Это даёт безопасный апгрейд.

## Альтернативы, которые отвергли

### А. «Один большой `MEMORY.md`»

Идея: всё в одном файле, как Claude `MEMORY.md`. Плюс — простота. Минус — быстро превращается в простыню > 1000 строк, агенты теряют структуру, поиск медленный, владелец не понимает, куда что положить.

### B. «Notion вместо папок»

Идея: всё в Notion, агент через MCP. Плюс — UI, мобильность. Минус — зависимость от облака (нет интернета — нет команды), сложно версионировать, сложно отдать ZIP, лицензия третьего лица, нет автономии.

### C. «Полный BMAD-фреймворк (analyst/pm/dev/architect/qa)»

Идея: взять готовый набор из 8 ролевых агентов. Плюс — продуманная методология. Минус — заточен под софтверную разработку, не под малый бизнес. Перегруз для ученика на старте.

### D. «Только CEO, без Архивариуса»

Идея: CEO делает всё. Плюс — один агент, проще. Минус — CEO быстро деградирует на рутине (раскладке файлов), теряет фокус на стратегии. Принцип «один агент = одна роль» нарушается с первой недели.

## На чьих плечах стоим (атрибуция)

- **Anthropic skill-creator** — формат `SKILL.md` с frontmatter и явными триггерами. Apache 2.0.
- **cursor.directory / awesome-cursorrules** — структура `.cursor/rules/*.mdc` с globs и числовыми префиксами. Сообщество Cursor.
- **BMAD-Method** — идея ролевых агентов с чётким scope, протоколами и эскалацией. MIT.
- **CrewAI** — паттерн «менеджер + исполнители» (у нас CEO + остальные).
- **Anthropic humanizer-ru** — принцип очищения русских AI-текстов (опциональный пресет CEO для исходящего).

Прямого копирования кода или промптов нет — все тексты переписаны под методологию Дениса Леушина и под малый бизнес РФ.

## Как менять структуру

Если ты **уверен**, что папка/файл лишний или нужна новая — обсуди на ретроспективе с CEO. Изменения в системной части (со стороны ученика) — на свой страх. Запиши изменение в `_АГЕНТЫ/CEO/ЛОГИ/ИНСАЙТЫ_О_ВЛАДЕЛЬЦЕ.md` с обоснованием.

При обновлении до v1.1 — твоя кастомизация может конфликтовать с новой версией. Поэтому — лучше **добавлять**, чем переделывать.
