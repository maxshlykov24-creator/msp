# Windows — настройка StartPack за 5 минут

> © 2026 Денис Леушин · Курс «Внедрение ИИ в бизнес»

В StartPack много папок и файлов на русском (это намеренно — для тебя удобнее). На Windows это иногда вызывает проблемы с кодировкой и путями. Ниже — как закрыть всё разом.

## Шаг 1. Распакуй ZIP в правильное место

**Где НЕ распаковывать:**
- ❌ `C:\Users\<твоё-русское-имя>\Документы\Мой бизнес\` — двойная кириллица в пути ломает часть инструментов.
- ❌ Сетевые диски (`Z:\`, `\\server\...`) — Cursor может тупить.
- ❌ Папки с пробелами (`C:\Program Files\...`).
- ❌ OneDrive / Яндекс.Диск / Dropbox — синхронизация конфликтует с быстрыми правками агентов.

**Где распаковать (рекомендация):**
- ✅ `C:\StartPack\` (короткий путь латиницей).
- ✅ `D:\Work\StartPack\`.
- ✅ Любая папка с **латинским путём без пробелов**.

Внутри сама папка `StartPack_v1/` и её содержимое — на русском, это ок.

## Шаг 2. Включи UTF-8 в системе (Windows 10/11)

Это разовая настройка, которая сразу убирает 90% проблем с кракозябрами.

1. Нажми `Win + R` → введи `intl.cpl` → Enter.
2. Вкладка «Дополнительно» → кнопка «Изменить язык системы».
3. Поставь галку **«Бета-версия: использовать Юникод (UTF-8) для поддержки языка во всём мире»**.
4. Перезагрузи компьютер.

После этого PowerShell, cmd, Cursor — все работают с UTF-8 по умолчанию.

## Шаг 3. PowerShell на UTF-8 (если шаг 2 не сделал)

Если не хочешь системную настройку, для каждого нового терминала:

```powershell
chcp 65001
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$OutputEncoding = [System.Text.Encoding]::UTF8
```

Чтобы автоматически — добавь это в `$PROFILE`:

```powershell
notepad $PROFILE
```

(если файла нет — Windows предложит создать, согласись).

## Шаг 4. Cursor — настройки кодировки

В Cursor открой Settings (`Ctrl+,`) → найди `Encoding` → поставь:
- `files.encoding`: `utf8`
- `files.autoGuessEncoding`: `true`

Это уже стоит по умолчанию в свежих версиях, но проверь.

## Шаг 5. Если используешь git (опционально)

```bash
git config --global core.quotepath false
git config --global gui.encoding utf-8
git config --global i18n.commit.encoding utf-8
git config --global i18n.logoutputencoding utf-8
```

Без этого `git status` показывает русские имена как `\320\237\321\200...`.

## Шаг 6. Проверка — всё работает?

Открой PowerShell в папке `StartPack_v1/`:

```powershell
cd C:\StartPack\StartPack_v1
ls
type README.md
```

Должно быть видно:
- Папки `_АГЕНТЫ`, `_ЗНАНИЯ`, `_СКИЛЛЫ` (без `?` или кракозябр).
- Содержимое `README.md` на русском.

Если кракозябры — вернись к шагу 2 (системный UTF-8).

## Типовые проблемы

### «Кириллица в чате Cursor выводится квадратами»
Перезапусти Cursor. Если не помогло — обнови до последней версии (Settings → About → Check for updates).

### «Bash-команды агентов падают с `command not found` или `\320\237`»
PowerShell использует не UTF-8. Сделай шаг 3.

### «PDF / DOCX из `_РАБОТА/ВХОДЯЩЕЕ/` имена показываются криво»
Файл изначально был в кодировке CP1251 (старый Windows). Переименуй вручную — Архивариус подхватит правильно.

### «Архивариус не может найти файл с русским именем»
Запусти `chcp 65001` в терминале перед командой Cursor (или сделай шаг 2 на постоянку).

### «Cursor долго открывает папку (10+ секунд)»
Скорее всего, открыл из OneDrive / Яндекс.Диска — синхронизация мешает. Перенеси в локальный путь типа `C:\StartPack\`.

### «При сохранении файла Cursor спрашивает про BOM»
Отвечай **без BOM** (выбирай `UTF-8`, не `UTF-8 with BOM`). BOM ломает frontmatter в `.mdc` и `SKILL.md`.

## Альтернатива — WSL2 (для технических)

Если ты разработчик и привык к Linux:

```powershell
wsl --install
# после перезагрузки
wsl
sudo apt update && sudo apt install -y locales
sudo locale-gen ru_RU.UTF-8
echo 'export LANG=ru_RU.UTF-8' >> ~/.bashrc
```

Открывай папку через `wsl --cd /mnt/c/StartPack/StartPack_v1`. UTF-8 «из коробки», bash работает идеально с русскими именами.
