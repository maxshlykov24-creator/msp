# Проверка технологий и ИИ-моделей

## Источники

Использовать источники в таком порядке:

1. официальная документация, release notes, pricing и deprecation policy поставщика;
2. официальный репозиторий и security advisories;
3. собственные счета, метрики и тесты бизнеса;
4. независимые обзоры — только как сигнал, не как доказательство.

Для каждого факта хранить ссылку и `verified_at`. Не переносить цену, лимит или статус поддержки из памяти.

## Честное сравнение моделей

Использовать один и тот же обезличенный набор реальных задач. До теста определить критерии и веса. Не выбирать по одному красивому ответу.

| Критерий | Что измерить |
|---|---|
| Качество | доля принятых результатов, фактические ошибки, соблюдение формата |
| Цена | стоимость одинакового объёма принятой работы, включая повторные запросы |
| Скорость | медиана и худшие задержки |
| Надёжность | ошибки API, rate limits, стабильность tool use |
| Возможности | контекст, vision/audio, structured output, tools |
| Ограничения | регион, данные, лицензии, compliance |
| Миграция | переписывание промптов, API, тестов и обучение команды |

Решение:

- `оставить` — текущая технология проходит критерии;
- `протестировать` — альтернатива выглядит перспективно, но данных мало;
- `заменить` — выигрыш подтверждён и миграция окупается;
- `вывести` — продукт устарел, небезопасен или снимается с поддержки;
- `не хватает данных` — честный итог при недостатке источников.

## Стоп-сигналы

- новая модель сравнивается по рекламному описанию, а не на задаче бизнеса;
- цена считается только за токены, без повторов, хранения, API и труда;
- замена ломает structured output, tools, лимиты или качество на русском;
- текущая версия уже EOL/deprecated, но миграционного плана нет;
- библиотека обновляется сразу на production без бэкапа и отката.
