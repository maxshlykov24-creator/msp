# Инструкция: как Cursor разворачивает OpenClaw на твоём VPS

> **Главный принцип:** ты не вводишь команды руками. Ты подключаешь Cursor к своему VPS через **Remote-SSH** и пишешь **один промпт** агенту в чате — он сам ставит Node.js, OpenClaw, разворачивает первого агента, подключает Telegram, поднимает gateway под systemd.

## Шаг 1 · Подключи Cursor к VPS через Remote-SSH

1. В Cursor открой Command Palette: `Cmd+Shift+P` (Mac) или `Ctrl+Shift+P` (Windows).
2. Набери: **Remote-SSH: Connect to Host...**
3. **Add New SSH Host** → введи: `ssh root@<IP_твоего_VPS>` (используй свой IP с Timeweb).
4. Cursor предложит выбрать SSH config — выбери `~/.ssh/config` или создаст новый.
5. Откроется **новое окно Cursor**, подключённое к VPS. В нижнем левом углу будет надпись «SSH: <IP>».
6. **File → Open Folder** → введи путь `/root` или `/opt` → **OK**.
7. Открой встроенный терминал (`Ctrl+\``) — он работает прямо на VPS. Открой чат Cursor (`Cmd+L`) — агент тоже работает на VPS.

⚠️ **Важно:** все следующие шаги — **внутри окна Cursor с подключением к VPS**, не в локальном Cursor.

## Шаг 2 · Перенеси workspace на VPS (один раз)

С локальной машины (новая вкладка терминала, **локального**, не VPS):

```bash
cd "<путь к твоему StartPack>/_АГЕНТЫ/AI-Менеджер_1-й_линии"
rsync -avz --exclude='.env' --exclude='.git' \
  ./ root@<IP_VPS>:/opt/manager-bot/
```

Или прямо в Cursor (`Cmd+Shift+P → Remote-SSH: Upload Folder...` если расширение поддерживает).

## Шаг 3 · Создай `.env` на VPS

В терминале Cursor (который на VPS):
```bash
nano /opt/manager-bot/.env
```

Вставь содержимое локального `.env` (Cmd+V / Ctrl+V). Сохрани: Ctrl+O → Enter → Ctrl+X.

## Шаг 4 · Открой чат агента в Cursor (на VPS) и скопируй блок ниже

Открой Cursor Chat (`Cmd+L` / `Ctrl+L`), переключись в режим **Agent**, скопируй промпт ниже целиком.

---

### 🎯 Команда агенту (копировать целиком)

```
Я подключился к своему VPS Ubuntu 22.04 через Cursor Remote-SSH.

ЗАДАЧА:
Развернуть OpenClaw 2026.5+ + первого агента lead-qualifier (AI-Менеджер 1-й линии) +
подключить Telegram-канал + поставить gateway под systemd чтобы работало 24/7.

ВХОДНЫЕ ДАННЫЕ:
- Папка с workspace и tools уже перенесена в /opt/manager-bot/
- В /opt/manager-bot/.env заполнены переменные:
    OPENROUTER_API_KEY, OPENCLAW_MODEL_PRIMARY, OPENCLAW_MODEL_FALLBACK,
    TG_BOT_TOKEN_LEAD_QUAL, MANAGER_CHAT_ID, WORKSPACE_PATH, TOOLS_PATH
- В /opt/manager-bot/openclaw.config.example.json — шаблон конфига агента
- В /opt/manager-bot/workspace/ — markdown-файлы агента (AGENTS.md, IDENTITY.md и др.)
- В /opt/manager-bot/tools/ — bash-скрипты (escalate.sh, save_lead.sh, kb_search.sh)

ЧТО НУЖНО СДЕЛАТЬ (по шагам, после каждого — проверка результата):

1. УСТАНОВИТЬ Node.js 20+ если ещё не стоит:
   - проверь `node --version` — если v20+ есть, пропусти установку
   - иначе: `curl -fsSL https://deb.nodesource.com/setup_20.x | bash - && apt update && apt install -y nodejs git nano`
   - проверь снова — должно быть v20.x.x

2. УСТАНОВИТЬ OpenClaw глобально через npm:
   - `npm install -g openclaw`
   - проверь: `openclaw --version` (должно быть 2026.5.x или новее)
   - запусти `openclaw doctor` — должны быть зелёные галочки. Если нет — почини
     по сообщениям, потом продолжай.

3. ПРОВЕРИТЬ что workspace и tools на месте:
   - `ls /opt/manager-bot/workspace/` — должны быть AGENTS.md, IDENTITY.md, BOOTSTRAP.md, MODE_LEAD_QUAL.md, HEARTBEAT.md
   - `ls /opt/manager-bot/tools/*.sh` — должны быть escalate.sh, save_lead.sh, kb_search.sh
   - если каких-то файлов нет — скажи мне, я перенесу с локали

4. СДЕЛАТЬ tools исполняемыми:
   - `chmod +x /opt/manager-bot/tools/*.sh`

5. ЗАГРУЗИТЬ переменные из .env (для использования в openclaw configure):
   - `cd /opt/manager-bot && set -a && . ./.env && set +a`

6. НАСТРОИТЬ OpenClaw НЕ через interactive wizard, а через прямые `config set`:
   - НЕ запускай `openclaw configure` (это interactive TTY-wizard, не работает в non-tty режиме).
   - Вместо этого выполни по очереди:
     ```
     openclaw config set agents.defaults.workspace /opt/manager-bot
     openclaw config set auth.providers.openrouter.apiKey "$OPENROUTER_API_KEY"
     openclaw config set agents.defaults.model.primary "$OPENCLAW_MODEL_PRIMARY"
     openclaw config set agents.defaults.model.fallbacks[0] "$OPENCLAW_MODEL_FALLBACK"
     openclaw config set gateway.port 19000
     ```
   - Если какая-то из этих команд упадёт (формат key изменился между версиями) —
     покажи мне ошибку, я подскажу актуальную команду из `openclaw config --help`.
   - Альтернатива: положить готовый `~/.openclaw/openclaw.json` (см. `openclaw.config.example.json`
     в /opt/manager-bot/) — поправить туда ENV-значения и сохранить через
     `mkdir -p ~/.openclaw && cp /opt/manager-bot/openclaw.config.example.json ~/.openclaw/openclaw.json`
     с подстановкой переменных через `envsubst`.

7. ЗАРЕГИСТРИРОВАТЬ агента lead-qualifier:
   - `openclaw agents create lead-qualifier --workspace /opt/manager-bot/workspace --config /opt/manager-bot/openclaw.config.example.json`
   - Проверка: `openclaw agents list` — должен показать lead-qualifier с workspace и model

8. ПОДКЛЮЧИТЬ Telegram-канал:
   - `openclaw channels add telegram --token "$TG_BOT_TOKEN_LEAD_QUAL" --agent lead-qualifier --name "lead-qual-tg"`
   - Проверка: `openclaw channels list` — должен показать telegram → lead-qualifier

9. ПОДНЯТЬ gateway под systemd:
   - `openclaw gateway install --systemd`
   - `systemctl daemon-reload`
   - `systemctl enable --now openclaw-gateway`

10. ПРОВЕРИТЬ что всё работает:
    - `systemctl status openclaw-gateway` — должно быть active (running)
    - `journalctl -u openclaw-gateway -n 50 --no-pager` — должно быть:
        Gateway listening on port 19000
        Agent registered: lead-qualifier
        Channel connected: telegram (@<username>)
        Polling for updates...
    - Если каких-то строк нет — диагностируй по логам и почини

ПРАВИЛА:
- На каждом шаге — выполняй команду, читай вывод, подтверждай мне «шаг N выполнен,
  результат: <короткое summary>».
- Если команда упала — НЕ продолжай дальше. Покажи мне ошибку, я скажу что делать.
- Не выдумывай команды, которых нет в инструкции. Если что-то нужно сверх — спроси.
- В конце — короткое резюме: «gateway работает на порту X, агент Y зарегистрирован,
  канал Z подключён. Открой Telegram, напиши боту @username и проверь».

После того как ты закончишь — я открою Telegram, напишу боту /start и проверю что он
отвечает. Если отвечает — переходим к мастер-тесту моделей и сдаче ДЗ.
```

## Шаг 5 · Жди отчёт агента и финальный тест

Cursor-агент будет писать что делает на каждом шаге. Когда напишет «всё готово» — открой Telegram, напиши своему боту `/start`. Должен ответить.

Если упал на каком-то шаге — агент покажет ошибку. Скажи в чате «**вот ошибка, что делать?**» — он либо починит, либо позовёт тебя руками внести правку.

## Что делать если Remote-SSH не работает

Если Cursor не подключается через Remote-SSH (старая версия / ограничения IT / др.) — используй **fallback**: открой локальный SSH-терминал (`ssh root@<IP>`) и копируй команды из `ДЕПЛОЙ_VPS.md` руками. Это 9 команд, ~10 минут.

Cursor через Remote-SSH — **в 2 раза быстрее и удобнее** (видишь файлы, чат и логи в одном окне), но не критично.

## Дальше — обновления и следующие сотрудники

После деплоя — все обновления тоже **через Cursor-агента**, не вручную.

**Пример обновления workspace** (поправить тон в IDENTITY.md):
```
Скажи в чате Cursor (на VPS):
"Открой /opt/manager-bot/workspace/IDENTITY.md, в разделе «Тон голоса» пятый пункт замени с X на Y.
Это подхватится без рестарта gateway."
```

**Пример добавления второго диалогового агента** (М8 — Эксперт-помощник, не транскрибатор!):
```
"Добавь к gateway агента expert-helper: workspace в /opt/manager-bot/agents/expert/workspace,
TG-токен в $TG_BOT_TOKEN_EXPERT, канал telegram. Используй openclaw agents create + channels add.
Перезапуск gateway не нужен."
```

⚠️ **Транскрибатор (М4), ОКК (М5), Аналитик (М6), SEO (М7) — это НЕ OpenClaw-агенты.** Это batch-скрипты на cron. У них своя инфраструктура — Cursor пишет Python-скрипт по тому же шаблону «один промпт → готовый сотрудник», но не через `openclaw agents create`. Подробно — в материалах М4 и далее.

## Принцип М3-Pro

> **Ты не системный администратор. Ты не Linux-инженер. Ты — собственник, у которого Cursor выполняет работу инженера.** Один промпт → всё сделано. На каждом шаге Cursor показывает что делает и ты понимаешь систему. Это не «магия» — это **делегирование рутины** при сохранении контроля.
