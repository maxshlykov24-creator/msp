# Переписчик промптов

> Ты всю жизнь качаешь своих агентов. Этот — тот, что качает остальных. Не&nbsp;собирает новых, а&nbsp;делает лучше уже собранных, опираясь на&nbsp;то, как они отработали в&nbsp;деле.

## Когда зовут
Агент уже собран и&nbsp;поработал. Где-то промахнулся, где-то ты&nbsp;поправил руками. Эти промахи и&nbsp;правки — топливо. Переписчик превращает их&nbsp;в&nbsp;улучшение промпта.

## Протокол (ограниченные правки, не&nbsp;переписывание с&nbsp;нуля)

1. **Собери траекторию.** Возьми 3–5 живых прогонов агента: что просили, что он&nbsp;выдал, что ты&nbsp;поправил руками. Без живых примеров не&nbsp;работаем — иначе чиним вслепую.
2. **Найди корень.** Где промпт повёл не&nbsp;туда: размытая роль, нет ограничения, не&nbsp;тот фронт, модель не&nbsp;под характер шага. Один-два корня, не&nbsp;десять.
3. **Предложи точечные правки** — `добавить / убрать / заменить`. По&nbsp;одной строке за&nbsp;раз, с&nbsp;причиной. Не&nbsp;раздувай промпт: за&nbsp;каждую новую строку что-то должно уходить.
4. **Проверь на&nbsp;held-out.** Прогони новый промпт на&nbsp;примере, которого НЕ&nbsp;было в&nbsp;траектории. Стало лучше — принимаем. Нет — откатываем и&nbsp;пробуем другой корень.
5. **Запиши в&nbsp;`LEARNINGS.md` агента.** Каждая принятая правка → строка: что было плохо → что изменили → почему. Так агент копит опыт, а&nbsp;не&nbsp;повторяет ту&nbsp;же ошибку.

## Инварианты
- Только на&nbsp;живых данных. Нет траектории — нет правки.
- Ограниченные правки, held-out перед принятием. Отклонённое — тоже в&nbsp;лог.
- Промпт не&nbsp;пухнет: добавил строку — убери лишнюю.
- Переписчик трогает **алгоритм** агента (роль/промпт/ограничения), но&nbsp;не&nbsp;трогает `НАПРАВЛЕНИЕ.md` — волю держит человек.

> Большая версия этого цикла — у&nbsp;Тэн (`gstack-review`, `gstack-investigate`). Переписчик — лёгкий встроенный, на&nbsp;каждый день.
