# Конструктор агентов

> Ты не пишешь ботов. Ты выносишь наружу кусок мышления человека и ставишь модель там, где она сильнее. Полная методология — [`../../_ФРЕЙМ/ФРЕЙМ.md`](../../_ФРЕЙМ/ФРЕЙМ.md).

## Протокол

### Шаг 0 — Открой `НАПРАВЛЕНИЕ` (воля держится у человека)
Прочитай [`../../НАПРАВЛЕНИЕ.md`](../../НАПРАВЛЕНИЕ.md). Там — «зачем» и&nbsp;куда жмём. Это объект человека: читаешь, но&nbsp;никогда не&nbsp;переписываешь. У&nbsp;ИИ нет воли — направление задаёт он. Пусто — попроси заполнить, не&nbsp;угадывай за&nbsp;него.

### Шаг 1 — Достань 4 вещи (без них не собирать)
Спрашивай владельца **по одному вопросу**, ответы записывай:
1. **Что во вводных (SSOT)?** — контекст, правила, его снимок на сейчас. Это **материал, который агенты читают, а не приказ**. За задачей всегда цель глубже формулировки («больше заявок» → чистая прибыль) — но саму цель держит `НАПРАВЛЕНИЕ`, не выдумывай её.
2. **Какие методы решения уже есть?** — как решаешь это руками сейчас, по шагам. Честно: выигрышно / устарело / не даёт результата?
3. **Методы расширения** — поищи в вебе, как делают сильные; нет ли готового скилла; какой инструмент/сервис закроет шаг дешевле живого человека.
4. **Конечная цель** — к чему идём и по какому признаку «готов».

### Шаг 2 — Разрежь на последовательность агентов → собери `КАРТУ`
Каждый агент = четыре параметра:

| Параметр | Что определить |
|---|---|
| **роль** | что делает на этом шаге |
| **модель** | характер шага, НЕ «самую умную». Одна стесняется, одна не лезет вглубь, одна сильна только через людей, одна — в данных |
| **фронт** | через что действует: текст / люди / данные / инструмент |
| **ограничения** | где держать, чего нельзя, где сигналить вместо действия |

Выход шага — не&nbsp;просто список агентов, а&nbsp;**карта последовательности**: кто кого зовёт, в&nbsp;каком порядке, что передаёт. Качество = агенты + промпты + **порядок взаимодействия**. Заполни [`../../_РАБОТА/_ШАБЛОНЫ/КАРТА_ПОСЛЕДОВАТЕЛЬНОСТИ.md`](../../_РАБОТА/_ШАБЛОНЫ/КАРТА_ПОСЛЕДОВАТЕЛЬНОСТИ.md). Меняешь порядок — новая версия карты, не&nbsp;правка на&nbsp;месте.

### Шаг 3 — Собери одного (самый узкий/дорогой шаг первым)
Не строй всю систему сразу. Возьми один шаг, собери агента по шаблону из [`../agent-creator/`](../agent-creator/ИНСТРУКЦИЯ.md) (3 файла: README + SKILL + системный промпт), запусти, проверь на живом примере, выводы верни во вводные.

### Шаг 3.5 — Оспорь сам себя (внутренний диалог) — обязательно
Перед сдачей агент проходит спарринг-критика: запусти второй проход, который **спорит с выходом** — где промахнётся, чего не&nbsp;учёл, на&nbsp;каком примере сломается. Не&nbsp;опция, а&nbsp;шаг. Тяжёлую версию закрывает Тэн (`gstack-review`, `gstack-investigate`).

### Шаг 4 — Качай агента дальше (`переписчик-промптов`)
Агент поработал, где-то ты&nbsp;поправил руками — отдай эти правки скиллу [`../переписчик-промптов/`](../переписчик-промптов/SKILL.md). Он&nbsp;улучшит промпт на&nbsp;живой траектории и&nbsp;запишет урок в&nbsp;`LEARNINGS.md` агента. Ты&nbsp;буквально качаешь своих агентов всё время.

### Шаг 5 — Хочешь по-взрослому → позови Тэн
Для плана, ревью и проверки всей цепочки подключи инженерную команду Тэн — [`../../_ТЭН/НАЧНИ_ТЭН.md`](../../_ТЭН/НАЧНИ_ТЭН.md).

## Инварианты
- Направление (воля, «зачем») держит человек, не агент. `НАПРАВЛЕНИЕ.md` читаешь, не переписываешь.
- SSOT/вводные — материал для агентов, не командир. Не путать с волей.
- Не собирать без 4 вещей.
- Модель — под характер шага, не по «уму».
- Один агент → оспорить → проверка → следующий. Выход — всегда карта последовательности, не россыпь агентов.
- Не пытайся заскриптовать человека целиком. Выносишь наружу повторяемый **алгоритм**; **волю и перепрыг** оставляешь человеку.
- Собрать сотрудника = создать план выполнения задачи (`роль × модель × фронт`).
