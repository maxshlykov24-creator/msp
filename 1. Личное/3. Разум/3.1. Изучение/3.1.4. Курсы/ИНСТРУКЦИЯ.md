## ЧТО ТЫ ПОЛУЧИШЬ ПОСЛЕ ЭТОГО МОДУЛЯ

Паша (твой AI-ассистент) перестанет зависеть от твоего компьютера.

Он будет жить на VPS — работать 24/7, отвечать в Telegram, выполнять задачи пока ты спишь, едешь в машине или проводишь встречи. Полная автономия без привязки к твоей машине.

**Конкретно:**
- Clawbot запущен на удалённом сервере и никогда не гасится
- Общаешься с ним через Telegram с любого устройства
- Он помнит контекст твоего бизнеса (через AGENTS.md)
- Выполняет задачи фоном — пока ты живёшь стратегией

## КАК УСТРОЕНА СИСТЕМА (АРХИТЕКТУРА)

Прежде чем начать — понимай что ты строишь. Это не просто "бот в Telegram".

```
┌──────────────────────┐     WebSocket/API     ┌──────────────────────┐
│     GATEWAY (VPS)    │◄─────────────────────►│  NODE (опционально)  │
│                      │                        │  Pi / Mac / локалка  │
│  🧠 думает           │                        │  🦾 делает           │
│                      │                        │                      │
│  • AI-модель         │    exec / browser /    │  • Браузер (Chromium)│
│  • Telegram-бот      │    screenshot          │  • Скриншоты экрана  │
│  • Cron-задачи       │◄─────────────────────►│  • SSH на серверы    │
│  • Память (AGENTS)   │                        │  • Файлы и скрипты   │
│  • Маршрутизация     │                        │  • Локальные LLM     │
│                      │                        │    (Ollama)          │
└──────────────────────┘                        └──────────────────────┘
    Всегда работает                                  Подключается когда нужен
    300-500 ₽/мес                                    Твой Pi или Mac
```

**Gateway = мозг.** Живёт на VPS 24/7. Принимает команды из Telegram, думает, маршрутизирует задачи.

**Node = руки.** Подключается к gateway и выполняет физические действия: открыть браузер, сделать скриншот, запустить скрипт, подключиться по SSH.

**Этот модуль — только Gateway (VPS).** Этого достаточно для 90% задач: общение, анализ документов, генерация текстов, автоматические брифинги.

Node (Pi или локальная машина) — продвинутый уровень. Для тех, кому нужна браузерная автоматизация или локальные LLM без платы за API.

## ШАГ 2: ПЕРВИЧНАЯ НАСТРОЙКА СЕРВЕРА

Подключаемся к серверу и приводим его в порядок. Это займёт 5 минут.

```bash
# Подключение к серверу (замени IP на свой)
ssh root@ТВОЙ_IP
```

После подключения выполни по порядку:

```bash
# Обновление системы
apt update && apt upgrade -y

# Базовые утилиты
apt install -y curl git nano ufw

# Настройка фаервола (защита сервера)
ufw allow ssh
ufw enable
```

Когда спросит "Command may disrupt existing ssh connections. Proceed with operation (y|n)?" — жми `y`.

### Смена часового пояса (ОБЯЗАТЕЛЬНО)

Европейский VPS по умолчанию живёт в UTC или Europe/Berlin. Если не поменять — крон-задачи будут срабатывать не вовремя. Реальный кейс: рассылка клиентам ушла в 4 утра вместо 9 утра, потому что сервер был в другом часовом поясе.

```bash
# Установить московское время
timedatectl set-timezone Europe/Moscow

# Проверить — должно показать MSK
timedatectl
date
```

Если нужен другой часовой пояс — замени `Europe/Moscow` на нужный (например, `Asia/Yekaterinburg`, `Asia/Novosibirsk`).

> ⚠️ **Частые ошибки:**
> - Если потерял SSH-соединение после `ufw enable` — перезаходи с теми же данными, всё норм
> - Если команды не работают — убедись что ты root (`whoami` должен вернуть `root`)
> - Не пропускай `apt upgrade -y` — на свежих серверах часто старые пакеты с дырами
> - Не забудь сменить timezone — иначе крон-задачи будут срабатывать в неожиданное время

## ШАГ 2.5: TAILSCALE — ЗАЩИЩЁННАЯ СЕТЬ (ОПЦИОНАЛЬНО)

Tailscale создаёт зашифрованный туннель между твоими устройствами. Зачем это нужно:
- Доступ к gateway-дашборду с любого устройства без открытых портов
- VPN Exit Node — весь трафик с Pi или Mac идёт через твой VPS (обход блокировок)
- Безопасное соединение между VPS и Node, если потом добавишь Pi или Mac

Это необязательно для базовой работы Clawbot. Но если планируешь расширять систему или нужен VPN — сделай сейчас, пока сервер чистый.

### Установка на VPS

```bash
# Установка одной командой
curl -fsSL https://tailscale.com/install.sh | sh

# Подключение к сети Tailscale
sudo tailscale up

# Откроется ссылка для авторизации — скопируй в браузер
# После авторизации проверь IP
tailscale ip -4
```

Запомни этот IP — если потом добавишь Node (Pi, Mac), они будут общаться по нему.

### Проверка подключения

```bash
# Статус — должен показать твой VPS в списке машин
tailscale status
```

### Использование как VPN Exit Node

Хочешь чтобы весь трафик с телефона или Pi шёл через твой европейский VPS:

```bash
# На VPS — объявляем себя как Exit Node
sudo tailscale up --advertise-exit-node

# В Tailscale Admin Panel (admin.tailscale.com) — одобри Exit Node для этой машины
# На телефоне или Pi — выбери VPS как Exit Node в настройках Tailscale
```

> ⚠️ **Частые ошибки:**
> - Tailscale просит авторизацию через браузер — это нормально, скопируй ссылку из терминала
> - `This machine is not authorized` → зайди на [login.tailscale.com](https://login.tailscale.com) и одобри устройство
> - Exit Node не работает → убедись что одобрил его в Admin Panel (не только в командной строке)
> - Если не нужен VPN прямо сейчас — просто установи без `--advertise-exit-node`, подключишь позже

## ШАГ 3: УСТАНОВКА NODE.JS И OPENCLAW

Node.js — это движок, на котором работает OpenClaw. Ставим через nvm — это правильный способ.

> 🚨 **ВАЖНО: Если используешь Cursor для настройки — явно укажи задачу**
>
> Cursor иногда вместо установки готового OpenClaw **пишет свой код с нуля**, думая что так лучше. Это неправильно.
>
> Когда просишь Cursor помочь с установкой — пиши именно так:
> **"Установи готовый пакет OpenClaw (`npm install -g openclaw@latest`). НЕ пиши свой код, НЕ создавай Python/Node скрипты. Только установка готового приложения."**

```bash
# Установка nvm (менеджер версий Node.js)
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash

# Применяем изменения в текущей сессии
source ~/.bashrc

# Проверяем что nvm установился
nvm --version
```

```bash
# Установка Node.js 22 (LTS)
nvm install 22
nvm use 22

# Проверка
node --version   # должно быть v22.x.x
npm --version
```

```bash
# Установка OpenClaw глобально
npm install -g openclaw@latest

# Проверка установки
openclaw --version
```

```bash
# Онбординг — первичная настройка с daemon
openclaw onboard --install-daemon
```

Онбординг спросит несколько вопросов — отвечай согласно своим данным. Главное — укажи правильный путь к workspace (`/root/.openclaw/workspace`).

> ⚠️ **Частые ошибки:**
> - `command not found: openclaw` после установки → выполни `source ~/.bashrc` и попробуй снова
> - `node: command not found` → выполни `nvm use 22` снова
> - Если `npm install -g` даёт ошибку прав доступа → ты не root, переключись через `sudo -i`

### Вариант A — OpenRouter (основной, рекомендую)

OpenRouter — агрегатор моделей: один ключ даёт доступ к Claude, GPT-4, Gemini, DeepSeek и 200+ другим. Базовая цена без наценок.

**1. Регистрируйся на [openrouter.ai](https://openrouter.ai)**

**2. Пополни баланс** → Dashboard → Credits (карта, крипто)

**3. Создай ключ** → Keys → "Create Key" → **поставь лимит $10** (защита от случайного сжигания токенов) → скопируй `sk-or-v1-...`

**4. Вставь в конфиг:**

```json
{
  "agent": {
    "model": "anthropic/claude-opus-4-6",
    "apiKey": "sk-or-v1-ТВОЙ_КЛЮЧ_OPENROUTER",
    "apiBase": "https://openrouter.ai/api/v1"
  },
  "agents": {
    "defaults": {
      "workspace": "/root/.openclaw/workspace"
    }
  },
  "channels": {
    "telegram": {
      "botToken": "ТВОЙ_BOT_TOKEN"
    }
  }
}
```

**Модели через OpenRouter** (указывай в поле `model`):

| Модель | Когда использовать |
|---|---|
| `anthropic/claude-opus-4-6` | Сложные задачи, стратегия |
| `anthropic/claude-sonnet-4-5` | Баланс скорость/качество |
| `anthropic/claude-haiku-3-5` | Быстрые рутинные задачи |
| `openai/gpt-4.1` | Альтернатива Claude |
| `deepseek/deepseek-v3` | Дёшево для простых задач |
| `google/gemini-2.5-flash` | Большой контекст, скорость |

> ⚠️ **Частые ошибки с OpenRouter:**
> - Ключ начинается с `sk-or-v1-` — не перепутай с Anthropic (`sk-ant-`) или OpenAI (`sk-...`)
> - `apiBase` обязателен — без него OpenClaw пойдёт напрямую к Anthropic и выдаст ошибку авторизации
> - Модели указываются в формате `провайдер/модель` — например `anthropic/claude-opus-4-6`, а не просто `claude-opus-4-6`

## ШАГ 5: ПОДКЛЮЧЕНИЕ TELEGRAM-БОТА

Создаём бота через BotFather и подключаем к Clawbot.

**1. Создай бота в Telegram:**
- Открой [@BotFather](https://t.me/BotFather) в Telegram
- Отправь `/newbot`
- Придумай имя (например: `Паша Ассистент`)
- Придумай username (например: `pasha_assistant_bot`)
- Получишь токен вида: `123456789:ABCdefGhIJKlmNoPQRsTUVwxyZ`

**2. Вставь токен в конфиг:**

```bash
nano ~/.openclaw/openclaw.json
```

Замени `ТВОЙ_BOT_TOKEN` на полученный токен.

**3. Защита бота — только для тебя:**

По умолчанию OpenClaw работает в режиме "pairing" — неизвестные пользователи получают код-подтверждение. Это уже защита. Дополнительно можно добавить allowlist:

```json
{
  "channels": {
    "telegram": {
      "botToken": "ТВОЙ_BOT_TOKEN",
      "allowFrom": ["твой_telegram_username"]
    }
  }
}
```

> ⚠️ **Частые ошибки:**
> - Токен бота начинается с цифр, а не с "sk-" — не перепутай с API-ключом
> - BotFather даёт токен один раз — сохрани его сразу
> - Если бот не отвечает после запуска — проверь токен, там часто опечатки

Создаём файл:

```bash
mkdir -p ~/.openclaw/workspace
nano ~/.openclaw/workspace/AGENTS.md
```

Минимальный шаблон для вставки:

```markdown
# МОЙ AI-АССИСТЕНТ ПАША

## КТО Я
Меня зовут [ТВОЁ ИМЯ]. Я предприниматель, владею компанией в сфере [СФЕРА].

## ТВОЯ РОЛЬ
Ты — мой личный AI-ассистент. Умный, прямой, конкретный.
Аналогия: гениальный стажёр (IQ 150), который знает всё, но нуждается в моём контексте.

## КАК СО МНОЙ ОБЩАТЬСЯ
- Прямо, без воды
- Сначала суть, потом детали
- Конкретные решения, не просто анализ
- Структурированно: Проблема → Факты → Варианты → Рекомендация

## МОИ ТЕКУЩИЕ ПРИОРИТЕТЫ

3. [Приоритет 3]
```

Сохраняем: `Ctrl+X` → `Y` → `Enter`

**Лайфхак:** Возьми свой профиль из Cursor-проекта (из `_ФУНДАМЕНТ/ЛИЧНОСТЬ/`) и адаптируй под этот шаблон. Паша должен знать тебя так же хорошо, как твой Cursor-агент.

> ⚠️ **Частые ошибки:**
> - Не оставляй шаблонные заглушки вида `[ТВОЁ ИМЯ]` — заполни реально
> - AGENTS.md работает как системный промпт — чем точнее, тем лучше результат
> - Можно добавлять новые разделы по мере работы с Пашей

## ШАГ 7: ЗАПУСК КАК СИСТЕМНЫЙ СЕРВИС (DAEMON)

Daemon — это фоновый процесс, который автоматически запускается при старте сервера. Без него Паша умрёт при перезагрузке.

**Вариант 1: через OpenClaw (если онбординг прошёл успешно)**

```bash
# Запуск gateway (Telegram-соединение)
openclaw gateway --verbose
```

Если видишь `Connected to Telegram` — всё работает. Нажми `Ctrl+C` чтобы остановить тест.

**Вариант 2: через systemd (надёжный daemon)**

Создаём systemd-сервис:

```bash
nano /etc/systemd/system/openclaw.service
```

Вставляем:

```ini
[Unit]
Description=OpenClaw AI Assistant
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/root
ExecStart=/root/.nvm/versions/node/v22.0.0/bin/openclaw gateway
Restart=always
RestartSec=10
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

> **Важно:** проверь точный путь к openclaw: `which openclaw` и замени в ExecStart

Активируем и запускаем:

```bash
# Перезагружаем systemd
systemctl daemon-reload

# Включаем автозапуск
systemctl enable openclaw

# Запускаем
systemctl start openclaw

# Проверяем статус
systemctl status openclaw
```

Если видишь `Active: active (running)` — Паша живёт.

> ⚠️ **Частые ошибки:**
> - Путь к `openclaw` в ExecStart должен быть полным. Найди: `which openclaw`
> - `Failed to start` → проверь логи: `journalctl -u openclaw -f`
> - Если меняешь конфиг — перезапусти сервис: `systemctl restart openclaw`

## БОНУС: OLLAMA — ЛОКАЛЬНЫЕ LLM БЕЗ ПЛАТЫ ЗА API

Ollama позволяет запускать AI-модели прямо на сервере — без API-ключей, без оплаты за токены, без внешних зависимостей. Это полезно если:
- Хочешь снизить стоимость рутинных задач
- Нужна приватность (данные не уходят в облако)
- Тебе нужен Node с Pi или мощным Mac (для Pi 5 8GB подходят небольшие модели)

> ⚠️ **На VPS с 2GB RAM Ollama не запустится нормально.** Минимум — 8GB RAM, комфортно — 16GB+. Этот шаг актуален если у тебя мощный VPS или ты добавляешь Node (Pi 5 8GB, Mac).

### Установка

```bash
curl -fsSL https://ollama.ai/install.sh | sh

# Проверка
ollama --version
```

### Рекомендуемые модели

```bash
# Qwen3 14B — хорошее качество, 9GB на диске
ollama pull qwen3:14b

# DeepSeek R1 8B — reasoning задачи, 5GB на диске
ollama pull deepseek-r1:8b

# Проверить что скачались
ollama list
```

### Подключение к OpenClaw

В `~/.openclaw/openclaw.json` замени модель:

```json
{
  "agent": {
    "model": "ollama/qwen3:14b",
    "apiBase": "http://localhost:11434"
  }
}
```

После изменения перезапусти daemon:

```bash
systemctl restart openclaw
```

### Тест Ollama напрямую

```bash
# Быстрый тест без OpenClaw
ollama run qwen3:14b "Привет! Кто ты?"
```

> ⚠️ **Частые ошибки:**
> - `error: model requires more memory` → не хватает RAM, попробуй модель поменьше (`qwen3:4b`, 2.5GB)
> - Ollama не запускается → проверь: `systemctl status ollama` и `journalctl -u ollama -f`
> - OpenClaw не видит Ollama → убедись что `apiBase` указывает на `http://localhost:11434`
> - Медленные ответы → это нормально для CPU-инференса. Для скорости нужен GPU или Apple Silicon
