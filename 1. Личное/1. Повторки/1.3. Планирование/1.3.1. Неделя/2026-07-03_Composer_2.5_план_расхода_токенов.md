## Как максимально нагрузить Composer 2.5

Модель бесплатная и агентная — логика: не один длинный чат, а **несколько параллельных фоновых агентов**, каждый в своей папке/репозитории (не будут конфликтовать), с точным ТЗ.

## Механика параллельного расхода токенов

1. Запускай задачи **по одной на репозиторий** (или через git worktree для одного репо) — тогда 4–5 фоновых Composer-агентов работают одновременно без конфликтов файлов.
2. Порядок:
   - **№1 и №3** — дёшево, быстро, реально нужно
   - **№2, №5, №8** — среднеразмерные, самодостаточные
   - **№6 и №7** — объёмные, системные (если токенов ещё много)
3. Каждую задачу давай с **явным DoD** («тест зелёный», «отчёт CSV», «README обновлён») — иначе агент упрётся в ревью, а не в токены.

## Приоритеты из реестра (напоминание)

```
1. ХВОСТЫ (старые обязательства) — всегда выше новых задач
2. Клиентские дедлайны / обещанное и горящее
3. Активные внедрения (проекты с прогрессом)
4. Техподдержка (SLA: реакция ≤2ч, старт ≤1 рабочий день)
5. Системное развитие MS Product
6. Операционка
```


Или для параллели — открыть несколько чатов/фоновых агентов, каждый с `@` на этот файл + номер задачи.
