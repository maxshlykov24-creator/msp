Сжатая рамка, без неё правка бота снова уйдёт в фильтры:

1. Агент это вынесенный наружу кусок мышления продавца, не бот, собранный с конца (с инструмента и с запрета).
2. СОТ, несменяемое ядро: кто продавец, какие факты можно говорить, чего нельзя. У этого бота ядро уже написано, см. раздел 2. Новые запреты в коде, которые противоречат ядру, ядро ломают.
3. Задача проходит через ядро. Истинная цель диалога: клиент приезжает в шоурум. Номер, отчёт и цена подчинены этому, а не заменяют ответ на вопрос.
4. Агент задаётся как роль, модель, фронт, ограничения. Сейчас роль размазана: модель пишет одно, код после неё пишет другое.
5. Модель подбирается под шаг. Смена модели и урезание стока не лечат ложь, если код подменяет уже правильный ответ.
6. Пустой ответ после фильтра нельзя заполнять случайным фактом. Пауза и передача человеку лучше выдуманной цены.

## 3. Что наложили поверх контракта и чем это кончилось

С 24 по 30 сентября на ответы модели повесили много фильтров: чужая карточка, НДС, торг, телефон, пустой ответ. Фильтр срабатывает после того, как модель уже написала правильную фразу, и подменяет её.

Опасное место в `bot/main.py`, выкат 2026-09-30 около 12:54 МСК:

- Если в истории уже есть телефон, приглашение приехать вырезается («после контакта убрал дожим»).
- Если после вырезания текст пустой, а у чата есть объявление, подставляется строка «Цена в объявлении …». Журнал: «убрал цену не из объявления этого чата».
- Маркер `[[ЧЕЛОВЕК]]` не доходит до паузы, если телефона в переписке нет (`silent_reason` в `bot/main.py` выходит раньше). Метка стирается, пустота снова заполняется ценой.

Итог: модель отвечает по делу, клиент видит цену или отказ. Потом следующая реплика модели не знает, что клиенту ушла цена, и честно пишет «я этого не писал».

Второе место, `bot/avito_match.py`:

- Карточка клеится к объявлению чата, не к словам клиента. Это верно.
- Год на один и отсутствие пробега в названии объявления всё ещё пропускают чужую машину. Порог «две подходящие карточки не клеить» не спасает, когда в стоке одна похожая модель.
- Карточка без цены продажи и без ссылки автотеки всё равно становится «эта машина в наличии».

Третье место, отчёт:

- В промпте есть метки `[[МЕДИА:фото]]` и `[[МЕДИА:видео]]`. Их код снимает и зовёт человека.
- Метки `[[МЕДИА:отчёт]]` нет. Модель её выдумывает, код отправляет клиенту как текст. Менеджеру сигнал не уходит. Сам файл отчёта бот в Авито и Авто.ру не шлёт.

## 6. Как самому открыть переписки

Живые диалоги лежат только на VPS бота. В репозитории Cursor их нет: локальная папка `workspace/state` это не прод. Браузерный чат без оболочки на компьютере владельца файлы не откроет. Если оболочка есть, читать так. Писать в чаты клиентов и править json на сервере нельзя: только чтение.

Сервер: `root@104.171.136.226`, ключ `~/.ssh/divo_deploy`, каталог `/root/divo-ai-manager`, сервис `divo-ai-bot`. Время в файлах и в `journalctl` это UTC. Москва = UTC+3.

Два слоя, их нельзя путать.

1. Что бот считает историей. Файл `workspace/state/<id>.json`. Авито: `av:` плюс id чата Авито. Авто.ру: `ar:` плюс id комнаты. Внутри `messages` (роли `user` и `assistant`, без времени на реплике), блок `avito` или `autoru` (название, цена, ссылка объявления), блок `crm`. Это не полный экран Авито. Исходящее, которое человек написал из приложения, в этот файл не попадает, см. 4.4.
2. Плоский журнал отправленных и входящих строк, которые бот сам залогировал. `workspace/state/_логи/ГГГГ-ММ-ДД.log`. Колонки через таб: время UTC, id чата, кто (`клиент` или `никита`), текст. Здесь тоже нет чужого исходящего человека и нет сырого ответа модели.

Сырой ответ модели, до фильтров, только в журнале сервиса. Строка `чат <id>: сырой ответ ...`. Рядом будут `после контакта убрал дожим` и `убрал цену не из объявления этого чата`, если сработала подстановка.

Команды, из каталога бота на сервере:

```bash
ssh -i "$HOME/.ssh/divo_deploy" root@104.171.136.226
cd /root/divo-ai-manager

# все реплики одного чата за день, как их видел бот
grep "av:u2i-19BncfafOIWyAUsTdK6wyw" workspace/state/_логи/2026-10-01.log

# объявление и сохранённые реплики
PYTHONPATH=. .venv/bin/python - << 'PY'
import json
from pathlib import Path
cid = "av:u2i-19BncfafOIWyAUsTdK6wyw"
doc = json.loads(Path("workspace/state/%s.json" % cid).read_text())
box = doc.get("avito") or doc.get("autoru") or {}
print(box.get("title"), box.get("price"), box.get("url"))
for m in doc.get("messages") or []:
    print(m.get("role"), (m.get("content") or "").replace("\n", " / ")[:300])
PY

# сырой ответ модели против того, что ушло клиенту
journalctl -u divo-ai-bot --since "2026-10-01 12:40:00" --until "2026-10-01 13:30:00" --no-pager -o cat | grep "19Bncfaf"
```

Карточка стока, которую бот мог приклеить: `workspace/KB/сток/СТОК.md` на том же сервере. Локальная копия в репозитории короче и отстаёт. Склейку смотреть функцией `match_card` из `bot/avito_match.py` по названию и цене из json чата, не по словам клиента.

Заметки в amo это третий, неполный вид: туда бот зеркалит свои реплики Авто.ру с подписью «Бот:». Реплик клиента там может не быть, сырого ответа модели нет. Сделку смотреть после файла чата, не вместо него.
