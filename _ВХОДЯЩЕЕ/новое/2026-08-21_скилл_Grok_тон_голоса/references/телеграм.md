## Как устроена живая связь в Cursor (tg-self)

Это не бот. Вход номером Максима. Сообщения уходят как с телефона.

Путь: `2. БИЗНЕС/08_Системное/_код/tg-self/`

Два рабочих аккаунта (оба = «мой голос»):

- **self** — личный `@maxim_shlykov`
- **work** — рабочий `@MSP_msproduct`
- **learn** — учебный, в этот скилл не входит

Сессии: `tg_self.session`, `tg_work.session`. Не копировать, не коммитить, не класть в облако Grok. Файл сессии = полный доступ к аккаунту.

Ключи приложения: `my.telegram.org` → API development tools → `api_id` и `api_hash` в `.env`. Не читать `.env` в чат.

Мандат: читать можно, если для задачи нужна живая переписка. Писать в чужой чат — только по явной просьбе.

Недоступно даже в tg-self: секретные чаты, удалённые сообщения, личный 1:1 звонок.

### Установка с нуля (на машине Максима, не на компьютере Grok)

```bash
cd "2. БИЗНЕС/08_Системное/_код/tg-self"
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# вписать TELEGRAM_API_ID и TELEGRAM_API_HASH
python3 tg.py login
python3 tg.py login --account work
```

`login` спросит телефон и код из Telegram. Если есть облачный пароль — его тоже. Код и пароль вводит Максим сам.

Если пишет «Сессия не авторизована»: Telegram отозвал сеанс (Настройки → Устройства) или из `.env` пропал `TELEGRAM_PHONE`. Лечится новым `login`, не слепым перезапуском выгрузки.

### Команды, которыми Cursor читает живое

```bash
python3 tg.py whoami
python3 tg.py whoami --account work
python3 tg.py dialogs --limit 30
python3 tg.py history --account work --chat "MSP | Рабочий чат" --limit 20
python3 tg.py search --account work --chat "MSP | Рабочий чат" --query "слово"
```

Папки чатов у Максима: Без ответа, ЭММ, MSP, Группы. Рабочие клиенты чаще в MSP и с аккаунта work. Личные группы вроде «Мачо Дача Хата Хаус» — self.

«MSP | Рабочий чат» — только `--account work`. Живой id супергруппы не повторять в ответах без нужды.

`--silent` в CLI = отправка без уведомления собеседнику. Это не бесшумный режим скилла. Бесшумный режим скилла = черновик, без отправки.

### Выгрузки, из которых собраны профили тона

Лежат в `tg-self/_выгрузки/` и в git не попадают. В Grok их не загружать: там клиенты, жена, деньги, здоровье.

- `сообщения.jsonl` — корпус исходящих
- `метрики_тона.md` — цифры по трём кругам
- `close_circle.json` — состав близкого круга
- `skip_chats.json` — партнёрские группы вне выгрузки
- `voice_cache.jsonl` — расшифровки голосовых

Профили в `_ПРОФИЛЬ/ТОН_ГОЛОСА_*.md` — это и есть сжатый контекст переписки. Не сырой лог.

## Три рабочих способа дать Grok живой Telegram

### 1. Вставка хвоста. Основной. Безопасный

Владелец копирует последние 15–40 сообщений чата и пишет: «бесшумный режим, ответь».

Бот не логинится в Telegram. Не видит секреты. Пишет черновик. Максим сам отправляет с телефона.

Этого достаточно для паритета по тону.

### 2. Локальный диск Максима. Паритет с Cursor

Если у Grok Bot включён запуск на локальном компьютере (Settings → General → Agent → Execution on Local Computer) и есть доступ к vault:

```bash
cd "/Users/max/CURSOR/2. БИЗНЕС/08_Системное/_код/tg-self"
source .venv/bin/activate
python3 tg.py history --account work --chat "ИМЯ ЧАТА" --limit 30
```

Писать через `tg.py send` — только после явного «отправь».
Сессию, `.env`, код из Telegram, облачный пароль — не просить в чат. Вход и 2FA — через Take control, как в доке Grok.

Это единственный путь, где Grok видит тот же аккаунт, что Cursor, без копирования сессии в облако.

### 3. Telegram Web на облачном компьютере Grok. Хуже

У Grok Bot есть свой облачный Linux и браузер. Можно открыть https://web.telegram.org и войти.

Минусы:

- Логин общий на все боты аккаунта. Сессия Telegram окажется у всего ростера.
- Пароль и код вводит Максим сам через Take control. Не в чат.
- Нет паритета с телефоном: секретные чаты всё равно недоступны.
- Файл `*.session` с диска Максима сюда не копировать.

Если всё же заходят: только чтение и черновик. Отправка с web.telegram.org — после явного «отправь».

## Чего не делать

- Не создавать бота через @BotFather «чтобы Grok отвечал в Telegram». Сообщения пойдут от бота.
- Не загружать в скилл `сообщения.jsonl`, `voice_cache.jsonl`, `.env`, `*.session`.
- Не путать официальный @GrokAI с этим скиллом.
- Не писать в чат номера телефонов, `api_hash`, код входа, облачный пароль.

## Если сессия снова умерла

Частая картина 2026-08-21: процесс «умер / CancelledError», на деле Telegram отозвал сеанс или из `.env` пропал телефон. Смотреть полный вывод, не хвост. Затем `python3 tg.py login --account self` или `work`.
