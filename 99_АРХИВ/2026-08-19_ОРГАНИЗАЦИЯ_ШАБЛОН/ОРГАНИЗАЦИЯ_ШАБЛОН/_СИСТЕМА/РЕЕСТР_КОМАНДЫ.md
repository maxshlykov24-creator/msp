# Реестр команды

> **SSOT иерархии.** Любой агент при старте читает этот файл первым (через правило `00-ядро.mdc`).
> Обновляется только Архитектором через двойную верификацию.

## Иерархия

```
ВЛАДЕЛЕЦ (общается только со мной — CEO)
└── CEO  (маршрутизатор)
    │
    ├── СЛУЖБЫ (читают всю систему)
    │   ├── Архивариус — файлы, индексы, классификация
    │   ├── Аудитор — светофоры готовности и баллы
    │   └── Архитектор — структура (спит до запроса)
    │
    └── РУКОВОДИТЕЛИ ОТДЕЛОВ (заполняется Архитектором)
        ├── Руководитель {{ОТДЕЛ_1}}
        ├── Руководитель {{ОТДЕЛ_2}}
        └── ...
```

## Реестр агентов

| Имя | Алиасы (нативно через Cursor `.mdc`) | Файл правила | Роль |
|---|---|---|---|
| **{{ИМЯ_CEO}}** | `@ceo` (+ `@{{имя_ceo_lc}}` если файл переименован) | `.cursor/rules/ceo.mdc` | Маршрутизатор / Исп.Директор |
| **Архивариус** | `@archive` | `.cursor/rules/archive.mdc` | Файлы и индексы |
| **Аудитор** | `@audit` | `.cursor/rules/audit.mdc` | Светофоры + баллы ДЗ |
| **Архитектор** | `@architect` | `.cursor/rules/architect.mdc` | Структура папки |
| **{{ИМЯ_РУК_1}}** | `@dept-{{отдел_1_lc}}`, `@{{имя_рук1_lc}}` | `.cursor/rules/dept-{{отдел_1_lc}}.mdc` (+ `{{имя_рук1_lc}}.mdc` если ученик дал имя) | Руководитель отдела {{ОТДЕЛ_1}} |
| **{{ИМЯ_РУК_2}}** | `@dept-{{отдел_2_lc}}`, `@{{имя_рук2_lc}}` | `.cursor/rules/dept-{{отдел_2_lc}}.mdc` (+ ...) | Руководитель отдела {{ОТДЕЛ_2}} |
| ... | ... | ... | ... |

> **Как работают алиасы (нативно):**
> Каждый агент = `.mdc`-файл в `.cursor/rules/` с настройкой `alwaysApply: false` и пустым `globs`.
> **Cursor сам распознаёт `@имя_файла` в чате** и применяет правило. Никакой кастомной логики не нужно.
>
> Например, файл `ceo.mdc` → активируется через `@ceo`.
> Файл `dept-продажи.mdc` → через `@dept-продажи`.
> Если есть и `маша.mdc` (по имени) — оба алиаса работают.

> **Имя CEO** задаёт владелец при установке М2 (обязательное условие). Архитектор переименовывает файл `ceo.mdc` → копию с именем владельца, либо оставляет `ceo.mdc` как универсальный.
>
> **Имена руководителей** — на выбор. Если дано — Архитектор создаёт **два файла**: `dept-{отдел}.mdc` (всегда) + `{имя}.mdc` (если задано). Если не дано — только `dept-{отдел}.mdc`.

## Реестр скиллов

| Скилл | Кто использует | Триггер | Эффект |
|---|---|---|---|
| `auto-context-pull` | CEO | «загрузим бизнес», новый файл | Складывает в `_ВХОДЯЩЕЕ/новое/` |
| `agent-creator` | CEO | «создай агента», «нужен X» | Новый агент из 4 вопросов |
| `business-discovery` | CEO (fallback) | «у меня нет сайта» | Чек-лист 9 категорий |
| `inbox-classifier` | Архивариус | новый файл в `_ВХОДЯЩЕЕ/новое/` | Карточка верификации |
| `department-builder` | Архитектор | Протокол 3 / `/архитектор добавь` | Создаёт отдел из карты смыслов |

## Зоны влияния

| Агент | Читает | Пишет | Может вызывать |
|---|---|---|---|
| CEO | всё | `_СИСТЕМА/_АГЕНТЫ/CEO/`, `07_КООРДИНАЦИЯ/`, `_ПРОФИЛЬ/` | любого |
| Архивариус | всё | `_ВХОДЯЩЕЕ/_к_проверке/`, INDEX.md любого отдела, `99_АРХИВ/` | inbox-classifier |
| Аудитор | всё (read) | свои ЛОГИ/ | — (отчёты CEO) |
| Архитектор | всё | `_СИСТЕМА/`, корневую структуру отделов | department-builder |
| Руководитель отдела | свой отдел + ОБЩАЯ_БАЗА_СМЫСЛОВ.md | свой отдел | Архивариуса |

## Маршрутизация задач (для CEO)

| Тип задачи владельца | Кому передаю |
|---|---|
| «разложи это» / «куда положить» | Архивариус |
| «сколько процентов карты», «отчёт ДЗ» | Аудитор |
| «добавь / убери / объедини отдел» | Архитектор |
| «найми мне X» (где X — новая роль) | сам через `agent-creator` |
| {{специфика отдельных отделов — заполняется Архитектором}} | соответствующий руководитель |
| Неклассифицируемое | Сам, один точный вопрос |
