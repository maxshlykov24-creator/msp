# Скилл: inbox-classifier

## Кто использует
Архивариус.

## Триггер
Новый файл в `_ВХОДЯЩЕЕ/новое/`.

## Что делаю (4 шага)

```
1. Извлечение текста
   • PDF / DOCX / TXT / MD / CSV / JSON → читаю содержимое
   • PNG со скриншотом → читаю + пометка «нужен текст-комментарий от ученика»

2. Извлечение 3–5 главных смыслов
   • Не пересказ файла
   • Конкретные тезисы: «средний чек 2.5М», «срок 6 нед», «KPI по конверсии»

3. Классификация в отдел
   • Читаю РЕЕСТР_КОМАНДЫ.md — какие отделы есть у этого ученика
   • Сопоставляю смыслы с зонами ответственности отделов
   • Выбираю один основной отдел + опционально 1 связанный

4. Сборка карточки верификации
   Кладу в _ВХОДЯЩЕЕ/_к_проверке/{дата}_{имя_файла}.md
```

## Шаблон карточки

```markdown
# Карточка: {имя файла}

**Дата:** {дата}
**Размер:** {N КБ}

## Главные смыслы
1. {смысл 1}
2. {смысл 2}
3. {смысл 3}

## Куда предлагаю положить
**Основной отдел:** `0X_ИМЯ_ОТДЕЛА/`
**Подпапка:** `тематика/` (если применимо)

## Что обновится в отделе
- БАЗА_СМЫСЛОВ.md → новый раздел «{тема}» с тезисами
- INDEX.md → строка с описанием файла

## Дубликат?
{да/нет — если да, ссылка на существующий}

## Решение

[ ] Положить в основной отдел
[ ] Положить в другой отдел: ____
[ ] Не сохранять
```

## Edge cases

| Ситуация | Что делаю |
|---|---|
| Дубликат | В карточке отмечаю «уже есть в Y». Предлагаю «обновить дату» или «не сохранять» |
| Многосмысловой | Основной отдел + предложение «создать ссылку в смежных» |
| Мусор | Помечаю «выглядит как мусор», предлагаю «не сохранять» |
| Слишком большой (>500 МБ) | «Слишком большой, разбей на части или укажи что важно» |
| Не текстовый | Пометка «нужен текст-комментарий» |

## Батч-режим

После 5 успешных классификаций по одному отделу:
> «Дальше группами по 5 на одно "да"? Это сэкономит время.»

Если ученик согласен — следующие 5 файлов с одинаковой классификацией → одна карточка-группа.

## Подчинение правилам
- `10-источники` — не выдумываю смыслы, только то что в файле.
- `11-верификация` — без «да» от ученика не раскладываю.
