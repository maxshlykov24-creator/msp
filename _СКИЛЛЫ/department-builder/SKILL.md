# Скилл: department-builder

## Кто использует
Архитектор.

## Триггер
- Протокол 3 (М2): первое разворачивание цифровой организации.
- Команда `/архитектор добавь отдел Y` (после М2).

## Главный принцип
**Отделы извлекаются из карты смыслов конкретного ученика**, а не из пресетов типа бизнеса. Каждая структура индивидуальна.

## 6 шагов

### Шаг 1. Чтение карты смыслов

**Адаптация под vault (2026-08-19).** Карт две, не одна:
- бизнес — `2. БИЗНЕС/08_Системное/_ЗНАНИЯ/КАРТА_СМЫСЛОВ.md`
- личное — `1. ЛИЧНОЕ/КАРТА_СМЫСЛОВ.md`

Отделы **не создаются с нуля**: папка отдела = существующая папка vault, в неё добавляются `РУКОВОДИТЕЛЬ.md`, `БАЗА_СМЫСЛОВ.md`, `ВХОДЯЩЕЕ/`. Состав отделов и алиасы — `_СИСТЕМА/РЕЕСТР_КОМАНДЫ.md`.

Читаю в карте:
- **№4 «Продукты»** → определяю что компания производит → может быть отдел `04_ПРОИЗВОДСТВО` или нет
- **№9 «Команда»** → люди и их роли → режимы для руководителей (играю/усиливаю)
- **№11 «Процессы»** → ключевые процессы → это будущие отделы
- **№7 «Воронка»** → какие этапы → может означать `02_ПРОДАЖИ` + `06_МАРКЕТИНГ`
- **№5 «Конкуренты»**, **№13 «Контент»** → нужен ли `06_МАРКЕТИНГ_И_ПУБЛИКА`

### Шаг 2. Извлечение списка отделов
Не «давай 8 универсальных» — а **«вот эти процессы есть в твоём бизнесе»**:

| Процесс из карты | Предлагаемый отдел |
|---|---|
| Продажа квартир / SaaS / услуг | `02_ПРОДАЖИ` |
| Реклама / контент / SEO | `06_МАРКЕТИНГ_И_ПУБЛИКА` |
| Бухгалтерия / отчёты | `03_ФИНАНСЫ` |
| Найм / обучение | `01_ПЕРСОНАЛ_И_СВЯЗЬ` |
| Создание продукта | `04_ПРОИЗВОДСТВО` |
| Контроль качества | `05_КАЧЕСТВО` |
| Стратегия / решения | `00_РУКОВОДСТВО` |
| Координация | `07_КООРДИНАЦИЯ` или сливаю в `00` |

Если процесса в карте нет — **отдел не создаётся** (например, для агентства производства как отдельной функции нет — `04` опускается).

### Шаг 3. Черновик в чат
Показываю ученику в Markdown:
- Список отделов
- Режим каждого (играю/усиливаю/закрываю дельту) на основе №9
- Предложения объединений (если есть основания)
- Имена руководителей (если карта подсказывает)

### Шаг 4. Диалог 3–6 вопросов
По одному вопросу за сообщение:
- «Профиль N отделов окей?»
- «Объединить X и Y? (есть основания: оба про привлечение клиента)»
- «Имя корневой папки?»
- «Имена руководителей или дефолтные?»
- ... обновляю черновик после каждого ответа

### Шаг 5. Финальное «делай»
Показываю финальный черновик. Жду «делай».

### Шаг 6. Создание на диске
По «делай» — за один проход:
1. Папка отдела: беру существующую папку vault, новую создаю только если зоны нет вообще
2. В ней — РУКОВОДИТЕЛЬ.md (рендеринг шаблона с подстановкой из карты), БАЗА_СМЫСЛОВ.md (заголовки тематик), ВХОДЯЩЕЕ/
3. Правило-кнопка `.cursor/rules/dept-{отдел}.mdc`; второй файл-алиас только если у руководителя есть имя
4. Регистрация в `_СИСТЕМА/РЕЕСТР_КОМАНДЫ.md`
5. Запись в `_СИСТЕМА/_ДЕЛЬТЫ/M2_install_{дата}.md`
6. Уведомление CEO

## Выход
- Папки отделов на диске.
- Реестр команды актуален.
- РУКОВОДИТЕЛЬ.md каждого отдела заполнен на 60–70% из карты смыслов.

## Связь со скиллом `role-assumer`
Внутри Шага 6 для каждого руководителя вызываю встроенную логику:
- Если человек на роли **есть** в карте №9 → режим «усиливаю», прописываю имя.
- Если **нет** → режим «играю».
- Если есть **частично** → «закрываю дельту», список взятых функций.

## Подчинение правилам
- `10-источники` — отделы только из карты, не из пресетов.
- `11-верификация` — без «делай» не создаю на диске.
- `15-границы` — каждому отделу прописываю собственную зону ответственности.
