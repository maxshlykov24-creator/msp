# 3. АГЕНТЫ

**Службы** цифровой организации. Правило-кнопка в `.cursor/rules/<имя>.mdc`, полная роль в `<ИМЯ>/СИСТЕМНЫЙ_ПРОМПТ.md`, данные и логи — там же в папке агента.

Агент включается **по смыслу фразы**, а не только по `@имя`. Список триггеров — в `description` его правила.

Здесь лежат только службы. **Руководители 12 отделов живут в папках своих отделов** (`РУКОВОДИТЕЛЬ.md`), а не здесь: агент читает то, чем управляет. Полный состав команды — [`_СИСТЕМА/РЕЕСТР_КОМАНДЫ.md`](../_СИСТЕМА/РЕЕСТР_КОМАНДЫ.md).

## Правила команды

- Один агент — одна роль. Не нагружать тело бизнесом.
- Обратная связь службе пишется в `## Корректировки от владельца` её **системного промпта**, руководителю отдела — в тот же раздел его `РУКОВОДИТЕЛЬ.md`. `.mdc` не трогаем.
- Правило-кнопка агента (`dept-*.mdc`, `ceo.mdc` и т.п.) держим до 20 строк. Разрослось — значит содержимое место в промпте. Исключение: шесть дисциплинарных правил Модуля 2 (`00-ядро`, `10-источники`, `11-верификация`, `13-логи`, `15-границы`, `16-обращение`) и кнопка Ио `ceo.mdc` — они `alwaysApply: true`. Алиасы `сео.mdc` / `ио.mdc` остаются `false`.
- Руководители между собой не общаются, координация через Ио (правило `15-границы`).
- Раз в месяц на ретро — чистка неиспользуемых.
