## Подводные камни — учтённые

1. **Поле «Жесткость» в МойСклад называется без ё** — скрипты используют `"Жесткость"` (не «Жёсткость»).
2. **Артикул не уникален** — МойСклад допускает одинаковые article у разных товаров, конфликтов нет.
3. **GET-запрос требует `Accept: application/json;charset=utf-8`** — иначе 415.
4. **Очистка строкового доп.поля** — передаётся `value: ""` (пустая строка), работает корректно.
5. **customentity поле** — нужно передавать объект с `meta.href`, не просто строку.
6. **Аренда (rent28_*)** — в текущем каталоге отсутствует. Скрипт пропускает без ошибки.
7. **Старые дублирующие товары** — "Устройство медицинское DETENSOR 90 х 800..." без артикула в доп.поле — это старые дубли. Шаги 2-7 их НЕ трогают. Нужно отдельно решить: архивировать или оставить.
8. **HFBCL80_6817** — нестандартный артикул (дубль/вариант HFBCL80). Категория и линейка заполнятся через `startswith('HFBCL')`, Жёсткость и Длина не ставятся — корректно.
9. **Rate-limit** — `_DELAY = 0.25s` = 4 req/s. Лимит МойСклад 45 req/s, запас x11.
10. **D18H00** — уже обновлён в ходе теста (article=D18H00, Жёсткость=Ж0, Длина=200). При повторном запуске шагов 2 и 4-7 будет пропущен / перезаписан (idempotent).
