# AS-IS amoCRM — что реально заполняют (поля)

## Сделка

**Доп. поля в сделке по сути не ведут.**  
Из того, что «заносят» в работу со сделкой:

| Поле / сущность | Как заполняется | Примечание |
|-----------------|-----------------|------------|
| **Ответственный** | По сути **автоматически** | Менеджеры **не распределяют** сделки вручную (как понимает Максим) |

Логика движения сделки = этапы + задачи DP + чек-листы F5, не карточка полей сделки.

---

## Контакт (карточка контакта)

То, что реально заносят / используют:

| Поле | Тип | Комментарий |
|------|-----|-------------|
| **Бюджет** | (заносят) | В чек-листе квалификации есть пункт «Бюджет понятен» |
| **Рабочий телефон** | (заносят) | |
| **Компания** | связь | Привязка к компании |
| **Ссылка на таблицу размещения** | **доп. поле** | Одно из двух явных доп. полей |
| **Адрес** | **доп. поле** | Второе явное доп. поле |

## Вывод для TO-BE / скоупа

1. Данные о размещении живут в **Google-таблице**, в CRM — в лучшем случае **ссылка** (+ адрес).  
2. Нет поля «№ счёта / оплачено / резерв до» в сделке → оплата и контроль не могут опираться на карточку сделки.  
3. Расширять поля сделки имеет смысл **точечно** (доказательства этапа), не «заполнить всё из 56-стр. инструкции».  
4. Чек-лист «обязательные поля заполнены» при почти пустой модели полей = слабый шлюз (нечему соответствовать).
