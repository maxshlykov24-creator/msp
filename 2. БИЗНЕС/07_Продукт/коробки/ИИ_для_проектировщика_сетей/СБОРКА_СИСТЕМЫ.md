# Сборка рабочей системы

> **Этот файл читает не человек, а Cursor.**
>
> **Инженеру:** открой в Cursor папку комплекта, переключи чат в режим **Plan** и напиши `@СБОРКА_СИСТЕМЫ.md сделай`. Cursor задаст вопросы и покажет план. Прочитай план и нажми кнопку **Build** — пока ты её не нажал, ничего не создаётся. Ручной работы не будет.

---

## ИНСТРУКЦИЯ ДЛЯ CURSOR

Ты разворачиваешь персональное рабочее пространство для **инженера-проектировщика наружных инженерных сетей**, который только начал работать с нейросетями.

### Твои правила на время сборки

1. **Ты ведёшь, инженер отвечает.** Это интервью плюс сборка, а не диктант.
2. **Вопросы по одному, максимум два за раз.** Не вываливай список. Дождись ответа, потом следующий.
3. **Ничего не выдумывай.** Специализация, объекты, программы, стадии — только из его ответов. Нет данных — ставь `[уточнить]`.
4. **Сначала план, потом файлы.** Ты в режиме Plan: собери интервью, покажи план целиком и объясни, что для запуска инженеру надо нажать Build.
5. **Каждый созданный файл называй вслух** и объясняй одной строкой, зачем он.
6. **Никакого ИТ-жаргона.** Он инженер, а не программист. Не говори «фронтматтер», «репозиторий», «конфиг». Говори «шапка файла», «рабочая папка», «настройки».
7. **Минимализм.** Не создавай папок про запас. Только то, что он реально будет использовать.
8. **Никаких секретов в файлах.** Пароли и доступы — не записывать.

## ФАЗА 2. Сборка

После согласия создай следующее.

### 2.1 Рабочая папка

```
<рабочая папка инженера>/
├── .cursor/rules/            # правила: паспорт и помощники
│   ├── ПАСПОРТ.mdc           # заполненный его ответами
│   ├── ту.mdc
│   ├── нормоконтроль.mdc
│   └── записка.mdc
├── Объекты/                  # папки по объектам
│   └── _ШАБЛОН_ОБЪЕКТА/      # структура папки нового объекта
├── Мои_шаблоны/              # его формулировки, шаблоны писем и записок
├── Мои_чек-листы/            # чек-листы сдачи, растут после каждой экспертизы
└── МОЙ_ЖУРНАЛ.md             # учёт сэкономленного времени
```

Папки создавай **только те, которые он подтвердил**. Пустых веток быть не должно.

### 2.2 Паспорт

Возьми `ПАСПОРТ.mdc` из комплекта, подставь ответы инженера, сохрани как `.cursor/rules/ПАСПОРТ.mdc` в его рабочей папке. Шапку файла (`description`, `globs`, `alwaysApply: true`) сохрани без изменений.

Все места в квадратных скобках должны быть либо заполнены, либо явно помечены `[уточнить позже]`.

### 2.3 Помощники

Скопируй три файла из папки `АГЕНТЫ/` комплекта в `.cursor/rules/`.

В каждом заполни раздел «КОНТЕКСТ» его данными: специализация, программы, тип объектов, стадия. Пустых квадратных скобок остаться не должно.

Если на вопрос 11 он назвал свою рутину — собери **четвёртого помощника** под неё по образцу существующих. Обязательно включи: механику уточняющих вопросов (2-3 за раз), явные границы «не входит», запрет выдумывать данные и номера пунктов норм.

### 2.4 Шаблон объекта

В `Объекты/_ШАБЛОН_ОБЪЕКТА/` создай структуру папок под один объект, например:

```
_ШАБЛОН_ОБЪЕКТА/
├── 1_Исходные_данные/     # ТУ, задание, топосъёмка, геология
├── 2_Расчёты/
├── 3_Документация/
├── 4_Переписка/
├── 5_Экспертиза/
└── README.md              # что за объект, статус, ключевые даты
```

Структуру согласуй с инженером: у него может быть своя, привычная.

### 2.5 Журнал

Создай `МОЙ_ЖУРНАЛ.md` с таблицей: день, дата, задача, время с ИИ, время руками, заметка. Объясни, что колонка «время руками» через месяц даст ему цифру эффекта.

## ФАЗА 3. Проверка

Пройди чек-лист:

- [ ] В `.cursor/rules/` лежит `ПАСПОРТ.mdc`, заполненный реальными ответами, без пустых скобок
- [ ] Там же лежат три помощника (или четыре), у каждого заполнен раздел «КОНТЕКСТ»
- [ ] Все созданные папки нужны, пустых «про запас» нет
- [ ] В файлах нет выдуманных фактов о его работе
- [ ] Нигде не записаны пароли и доступы
- [ ] Названия папок понятны без объяснений

## ФАЗА 4. Что сказать в конце

Коротко и без терминов:

1. Что создано и где лежит
2. Как звать помощников: `@ту`, `@нормоконтроль`, `@записка`
3. Пять команд для старта, например:

```
@ту разбери @ТУ.pdf

@нормоконтроль проверь @Записка.txt перед сдачей

@записка напиши письмо в водоканал: нужно уточнить фактический напор в точке подключения

/что-спросить какие данные нужны, чтобы начать проектировать этот объект

@Объекты/Мой_объект/ найди расхождения между заданием и техническими условиями
```

4. Предупреди, что `/что-спросить` и подобные команды — не встроенные функции программы, а сокращения, которые описаны в его паспорте. Работают они только в этой рабочей папке
5. Скажи, что Word и Excel читаются ненадёжно: рабочие документы лучше пересохранять в `.txt` и `.csv`
6. Предложи прямо сейчас прогнать первую реальную задачу на обезличенных данных, чтобы проверить, что всё работает
7. Скажи, что любой файл помощника можно открыть и поправить руками — это обычный текст, и это единственное «программирование», которое ему понадобится
