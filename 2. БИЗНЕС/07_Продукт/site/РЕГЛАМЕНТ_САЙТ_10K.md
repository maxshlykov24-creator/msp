# Регламент: сайт уровня $10 000 (Cursor)

> **Версия:** 1.0 | **Дата:** 2026-06-04  
> **Для кого:** Максим / MS Product — когда нужен красивый, «агентский» сайт, а не generic AI-slop.

**Когда пользователь говорит «хочу сделать сайт»** — ассистент открывает этот файл, выдаёт структурированный бриф и **не начинает код без референсов и ответов на наводящие вопросы**.

---

## 1. Планка качества

- Цель — сайт, который **выглядит как работа за ~$10 000** (уровень студии/агентства), а не шаблон за $200.
- Инструмент сборки: **Cursor** (не Claude Code), но **методология** — из гайда ниже.
- Сначала **вид и референсы**, потом код. Без «сделай красиво» в вакууме.

**Cursor Skills вообще:** тот же open standard, что Claude Code — см. [skills.sh](https://skills.sh), [Agent Skills spec](https://agentskills.io). Встроенные skills Cursor: `~/.cursor/skills-cursor/` (не трогать).

## 3. Принцип работы (главное)

```
Референсы (как хочу) → наводящие вопросы → design system / прототип → код → полировка → деплой
```

**Не так:** «сделай лендинг для X» → сразу код → непонятный результат.

**Так:** пользователь приносит **3–5 примеров** (скриншоты, ссылки Dribbble/Behance, живые сайты) + ответы на вопросы → от этого «пляшет» вся система.

На этапе **полировки** — подменять generic-блоки компонентами с [21st.dev](https://21st.dev/) / React Bits, а не дописывать анимации с нуля. Визуал-референсы тоже брать оттуда, не только «полирнуть в конце».

## 6. Протокол ассистента при старте «хочу сайт»

### Шаг 0 — выдать этот регламент (краткая выжимка в чат)

### Шаг 1 — референсы (блокер)

Спросить:

1. Есть ли **3–5 примеров** «как должно выглядеть»? (Dribbble, [21st.dev](https://21st.dev/), живые URL, скрины)
2. Что **точно нравится** в каждом? (hero, шрифт, цвет, анимация, «воздух», тёмная/светлая тема)
3. Что **точно не нужно**? (шаблонность, «AI slop», стоковые иллюстрации, перегруз анимацией)
4. Если референс — живая страница: HTML снят через [view-page-source.com](https://www.view-page-source.com)?

**Без референсов — не переходить к коду.** Максимум: wireframe-описание или moodboard-запрос.

### Шаг 2 — наводящие вопросы (обязательно)

Задавать **последовательно**, 2–3 за раз:

| # | Вопрос |
|---|--------|
| 1 | **Тип сайта:** лендинг, визитка, SaaS, портфолио, e-commerce, другое? |
| 2 | **Аудитория и действие:** кто заходит и что должен сделать (CTA)? |
| 3 | **Бренд:** есть лого, цвета, шрифты, tone of voice? |
| 4 | **Стек:** React/Vite, Next.js, чистый HTML+Tailwind (как `site/index.html`), другое? |
| 5 | **Страницы/секции:** какие блоки обязательны (hero, кейсы, pricing, FAQ, контакты)? |
| 6 | **Контент:** тексты готовы или нужен черновик? |
| 7 | **Анимация:** минимум / умеренно / «вау» (как в референсах)? |
| 8 | **Деплой:** GitHub Pages, Vercel, свой VPS, домен уже есть? |
| 9 | **DoD:** как поймём, что сайт готов? (мобилка, PageSpeed, OG-превью, форма) |

### Шаг 3 — skills и инструменты

- Проверить **frontend-design** + **ui-ux-pro-max** в Cursor.
- При необходимости — MCP 21st.dev (если настроен в проекте).

### Шаг 4 — прототип вида

По `.cursorrules`: **сначала прототип/mockup на моках** → согласование → потом логика и прод.

### Шаг 5 — сборка → полировка → деплой

Этапы из гайда:

1. **Inspiration** — референсы зафиксированы  
2. **Build** — scaffold по референсам + skills  
3. **Refine** — 21st.dev, React Bits, polish pass  
4. **Deploy** — GitHub + Vercel / см. `README.md` в этой папке

## 8. Чеклист «$10K vs generic» (кратко)

- [ ] Есть референсы, а не только текстовый бриф  
- [ ] HTML живого референса снят через view-page-source.com (если референс — страница, не картинка)  
- [ ] Уникальная типографика (не Inter + фиолетовый gradient по умолчанию)  
- [ ] Продуманный hero + чёткий CTA  
- [ ] Микро-анимации осмысленные, не декоративный шум  
- [ ] Мобилка проверена  
- [ ] OG / favicon / meta  
- [ ] Polish pass после первого черновика

## 9. Зафиксированные визуальные предпочтения владельца

> **2026-07-02** — liquid glass. **2026-07-06** — эталон bubbbly для продуктового UI.

| Предпочтение | Суть |
|--------------|------|
| **Liquid glass (жидкое стекло)** | Обязательный визуальный акцент при создании сайта. Должен давать **премиальное** ощущение — не «стеклянная карточка ради моды», а цельная дорогая эстетика. |
| **Эталон bubbbly (Retro Pink Calculator)** | Главный референс **DNA продукта**, не только сайта: [precise-calculator.html](https://www.bubbbly.com/app/precise-calculator.html). При старте визуала — **всегда предлагать** открыть и вычленить приёмы (см. ниже). |
| **Не generic** | Эффекты — часть общей $10K-планки (§1), не единственный приём; сочетать с типографикой, воздухом и осмысленной анимацией. |
| **Traffic Masters (2026-08-20)** | Живой референс **каркаса и CTA**, не палитры: [traffic-masters.ru](https://traffic-masters.ru/). Разбор — [`2026-07-08_РЕФЕРЕНСЫ_сайт.md`](2026-07-08_РЕФЕРЕНСЫ_сайт.md) §5. На правках `ms-p.ru` сверять шапку-пилюлю, hero-сцену, капсулы со стрелкой. Светлую схему и чужой оффер не копировать. |
| **Yoolip AI (2026-09-03)** | Живой референс **лестницы SaaS-лендинга**, не оффера: [yoolip.ai](https://yoolip.ai/#faq). Разбор — [`2026-07-08_РЕФЕРЕНСЫ_сайт.md`](2026-07-08_РЕФЕРЕНСЫ_сайт.md) §6. Брать сравнение «было / стало», скрины продукта, три шага с временем, FAQ. Чужой оффер и сборку не начинать, пока владелец сам не скажет делать сайт. |

**Что имеется в виду (для ассистента при сборке):**

- Полупрозрачные слои с `backdrop-filter: blur()` / `-webkit-backdrop-filter`, мягкие границы, лёгкий блик или градиент по краю.
- Глубина: карточки, навигация, модалки, hero-блоки «плавают» над фоном (mesh-gradient, мягкое видео или статичный rich-background).
- Референсы при старте: Apple Liquid Glass (WWDC 2025), Awwwards/Godly с glassmorphism; при необходимости — компоненты с 21st.dev (§5).
- **DoD по эффекту:** на десктопе и мобилке стекло читается; fallback без blur — читаемый контраст, не «серое мыло».

**Эталон bubbbly — что вычленять (2026-07-06):**

| Слой | Приём в референсе | Перенос в продукт |
|------|-------------------|-------------------|
| Холст | Текстура «устройства» + прозрачные кнопки поверх | Skeuomorphism lite: один hero-объект, не плоская сетка карточек |
| Фон | Пастель + dot-pattern (`radial-gradient` точки) | Мягкий фон с характером, не белый `#fff` |
| Тип | Orbitron на дисплее, контраст цифр | Характерная display-гарнитура для ключевых чисел/заголовков |
| Motion | hover glow, `scale(0.96)` на press, ~100ms | Микро-отклик на каждое действие |
| Layout | Центр экрана, скругление ~40px, один виджет | Фокус + воздух; не перегружать панелями |

При старте «хочу сайт» / «нужен визуал продукта» — **явно предлагать**: (1) liquid glass в moodboard, (2) сверку с [bubbbly calculator](https://www.bubbbly.com/app/precise-calculator.html) и список переносимых приёмов (§4, §6).
