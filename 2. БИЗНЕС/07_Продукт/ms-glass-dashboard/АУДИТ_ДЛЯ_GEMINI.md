## 2. Что уже собрано (архитектура текущего `index.html`)

Один HTML-файл (HTML/CSS/JS инлайн, без сборки/зависимостей), один экран-скролл + модалки/дровер (никаких вкладок):

1. **Hero-лента (sticky)** — стих/якорь дня → Кинжал (главная задача дня) + фокус-таймер → 1–3 задачи фокуса → мини-прогресс целей + ближайший флажок.
2. **Фокус дня** (`#secFocus`) — 1–3 задачи, soft-cap.
3. **Поток задач** (`#secStream`) — хвосты/инбокс/очередь + быстрый захват + фильтр по проекту.
4. **Пульс жизни** (`#secPulse`) — 8 направлений (Дух/Тело/Семья/Разум/Церковь/Порядок/Бизнес) с целью/фактом часов в неделю, скор недели, стрики, дневной чекин.
5. **Дровер «Год 2026»** — долг, доход, флажки, weekly/monthly review.
6. **Модалки** — разбор задачи (DoD, 3-й перенос → развилка удалить/делегировать/упростить, блокпост при форс-мажоре без вины), открывашка/закрывашка, редактор направлений жизни.
7. **cmd+K палитра** — мгновенный захват в инбокс + переход к секции.

Правила, которые должны быть **реально вшиты в механику**, не просто текстом:
- DoD «Готово»: физически завершено · нет хвостов на уточнение · инсайт внедрён/сохранён.
- 3 переноса → на 4-й обязательная развилка (удалить/делегировать/упростить).
- Главное действие первым: очередь мелочей приглушена до старта Кинжала.
- Блокпост: Кинжал не сделан → без вины → фиксация причины → авто-перенос завтра пунктом №1 → если перенос системный, предложить упростить шаг.
- «Дожать»: отдельная линза задач «почти готово / залипли».
- Пятница = стратегический компас, субббота = «Большая зачистка» (инбокс→0, метрика «сколько красных задач закрыто»).
- Долг ≥30% от входящих (лучше 50%) — правило распределения денег.

**Реальные данные, вшитые как seed** (редактируемые, хранятся в `localStorage`):

- Доход: ~200 000 ₽/мес → цель 300–400 000 ₽/мес за 90 дней.
- Хвосты (first-class): MANSBAND касса МойСклад, MANSBAND CRM баг, Detensor (10 МС + 4 amoCRM), Ван Пак перенос МойСклад, MartaChe RetailCRM→МС, DKAcademy бот→amoCRM, денежные хвосты людям.
- Недельные цели: выручка 100 000 ₽/нед, долги 30 000 ₽/нед.
- История жизни (привычки Бог/Лёд/Зал/Изучение/Настя + деньги) — сид из старого Excel-трекера, мигрирован под 8 направлений.

## 4. Что мне важно, чтобы ты проверил особо

- **Логика фокуса**: реально ли ограничен soft-cap 1–3 задачи, не размывается ли Кинжал по нескольким источникам правды (отдельное поле vs задача в очереди).
- **Правило 3 переносов и блокпост**: механика реально считает переносы и триггерит развилку/блокпост, или это просто текст в модалке без действия на данных.
- **Долг/доход как рабочий контур**: есть ли видимый прогресс к целям (611 680 → 0, 200к → 400к), правило ≥30% на долги — влияет ли на что-то в UI или просто зафиксировано в тексте.
- **Флажки**: реально вычисляются от прогресса (честный факт) или это статичный список.
- **8 направлений жизни**: часы факта копятся автоматически (таймер/чекин) или требуют ручного ввода — и не потеряна ли история старых привычек при миграции.
- **DoD-гейт**: закрытие «красной»/важной задачи действительно требует подтверждения по чек-листу, а не просто клика «✓».
- **Целостность данных**: что произойдёт с данными пользователя, если открыть файл в браузере, где уже есть старые ключи `ms_cmd_*_v4` — миграция идемпотентна (повторный запуск не дублирует/не портит), нет потери при частичном сбое (например, `JSON.parse` упал на битом значении).
- **XSS/безопасность инпутов**: пользовательский текст (названия задач, заметки, инбокс) вставляется в DOM через `innerHTML` без экранирования? Это личный файл без сервера, но привычка важна, если он когда-то будет sync/шариться.
- **Производительность**: нет ли полного `renderAll()`/пере-рендера DOM на каждое нажатие клавиши в текстовых полях (лаг при вводе), нет ли утечек `setInterval` у таймеров при повторных открытиях/закрытиях модалок.
- **Мобильность и доступность**: `@media (hover:none)` отключает эффекты; фокус видим на клавиатурной навигации; Escape/Enter работают в модалках; cmd+K не конфликтует с системными шоткатами браузера.
- **Соответствие эстетике**: хром-нить/фон не выглядят дёшево (плоские градиенты, отсутствие слоёв) — но здесь важнее логика, чем вкус; отметь визуальные баги (наслоение z-index, обрезание на малых экранах), не переделывай стиль без запроса.

## 5. Оси аудита (используй как чек-лист)

1. **Соответствие целям** — на каждую боль из раздела 1: реализовано / реализовано частично / не реализовано, с конкретной строкой кода или отсутствием функции.
2. **UX-логика** — сколько кликов до Кинжала/фокуса от открытия файла; не перегружен ли hero; конфликтуют ли открывашка/закрывашка/чекин за внимание.
3. **Целостность данных** — миграция, схема версий, порча/потеря при ошибках парсинга, дублирование источников правды.
4. **Код** — читаемость, дублирование функций рендера, глобальные утечки, обработка ошибок, чистота event-листенеров (нет ли повторной привязки при каждом рендере).
5. **Безопасность** — XSS через `innerHTML`, доверие к `localStorage` без валидации схемы.
6. **Производительность** — лишние ре-рендеры, тяжёлые SVG-фильтры на мобиле, память (таймеры).
7. **Доступность** — aria, контраст текста на градиентном фоне, keyboard-only прохождение.
8. **Мобильность** — брейкпоинты, `hover:none`, размер тач-таргетов.
9. **Соответствие запрещённым элементам** — нет ли следов единичек Гребенюка/старых экранов/канбана из 5 lanes.

## 6. Технические рамки — не нарушать при правках

- Один файл `index.html`, без сборки, без внешних зависимостей (кроме Google Fonts через `<link>`, как сейчас).
- Любые правки схемы `localStorage` — только с миграцией старых данных, без потери истории.
- Не возвращать единички Гребенюка, отдельные экраны Клиенты/Календарь/Газ/Стратегия — это осознанно снесено.
- Правки эстетики (шрифты/хром/фон) — только если явно попрошу или это баг (обрезание, нечитаемость), не «улучшение вкуса» по инициативе.
