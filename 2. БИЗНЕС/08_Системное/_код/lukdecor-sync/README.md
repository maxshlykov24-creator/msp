# lukdecor-sync

Локальный демонстрационный интерфейс WB FBS для ЛУКДЕКОР. Не боевой склад и не интеграция, заменяющая TopSeller. Внешние вызовы ограничены GET: МойСклад и оригинальные PDF с print.topseller.ru. SQLite хранит только состояние демонстрации.

## Запуск

```sh
python3 -m pip install -r requirements.txt
python3 run.py
```

Перед обычным запуском передать MOYSKLAD_TOKEN либо MOYSKLAD_LOGIN и MOYSKLAD_PASSWORD через окружение. Секреты не передавать в аргументах команды и не добавлять в репозиторий.

С разрешения владельца от 26.10.2026 поддерживается `python3 run.py --vault-access`: нужная строка katrina10 из существующего файла доступов читается программно, пароль остаётся в памяти процесса и не выводится. Файл доступов не копируется.

Адрес: http://127.0.0.1:8768 · предварительное КП: http://127.0.0.1:8768/proposal

Слушает только loopback. Вход по имени и станции служит отметкой в демо-журнале, а не проверкой личности. После перезапуска войти снова; задания и журнал сохраняются. Для работы ТСД по Wi-Fi нужна отдельная согласованная установка с настоящей авторизацией, HTTPS и правами. В сеть демо не выставлять.

## Демонстрация

1. Войти под именем сотрудника и станцией. Обновить задания из МойСклад.
2. Выбрать задания одного склада, ввести или отсканировать тележку, создать волну.
3. Отбор: сводный лист группирует товар по волне и UUID товара. Каждую единицу подтвердить её штрихкодом. При дефиците указать ответственного; остальные задания продолжаются.
4. Станция: выбрать волну и сканировать товар. Сервер выбирает самое раннее из отобранных заданий этой волны. Если есть незакрытая этикетка, повторит её. Без дедлайна WB приоритет по сроку не подтверждён.
5. Открыть оригинальный PDF и напечатать вручную. Автоматического агента печати и подтверждения принтера в демо нет. Физическая печать в этой проверке не запускалась.
6. В выбранном задании сканировать QR стикера, затем код DEMO-BOX из волны. Чужой стикер и чужой короб отклоняются.
7. Если состояние МС изменилось, операция блокируется. Отсканировать товар и ячейку возврата; решение по документу принимает склад. Незакрытое задание можно явно передать другой станции.
8. Журнал показывает сотрудника, станцию, время и действие. Время интерфейса в МСК. Отображаемая задержка включает сервер и запросы МС, это не замер на ТСД клиента.

Проверка статуса повторяется перед получением, выдачей PDF и при контрольных сканах. Она видит лишь состояние МС и не гарантирует обнаружение отмены WB до синхронизации TopSeller. Изменения уже закрытых демо-коробов автоматически не отслеживаются. Нужна сверка перед реальной отгрузкой.

## Границы

- Реальная поставка WB, дедлайн и прямой статус отмены не получены. DEMO-BOX не является коробом поставки WB. Без доступа WB правило одной открытой поставки и его ручная сверка должны быть согласованы до пилота.
- Размещение запаса Склад ФБС физически не подтверждено. Ячейки другого склада не подставляются. Есть поддержка проверки подтверждённой ячейки, но снимок не выдаёт неподтверждённые адреса за маршрут.
- Сборка без сети не поддерживается: при отказе МС или этикеток действие остановится. Аварийный PDF, агент печати, переотбор дефицита, сверка коробов и настоящие права входят в проектирование пилота.
- Обмен 1С, запись заказов сайта, MAX, замена TopSeller и Клеверенс не реализованы в этом демонстрационном этапе.
- Модули ff-sync не импортируются. Из net.py адаптированы keep-alive, пауза и ограниченные повторы; пути и методы зафиксированы на чтение. Боевые модули заказов, списаний и поставок Березы не скопированы и не запускались.
