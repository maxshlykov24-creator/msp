# LicenseBridge USA — live-дашборд аналитики

Дашборд продаж на данных Kommo. Прод: **https://lb.mspod24.ru** (сервер
`72.56.123.137` — тот же VPS, что хаб LicenseBridge), вход по логину и паролю.

Прототип, который согласовал клиент, лежит в
`2. БИЗНЕС/04_Производство/Активные/LicenseBridge_USA/дашборд/` — он остаётся
единственным источником вёрстки, здесь она собирается скриптом.

## Из чего состоит

| Файл | Что делает |
|---|---|
| `app/kommo.py` | read-only клиент Kommo API v4 (rate limit 4 rps, retry). Мутаций нет и быть не должно |
| `app/collector.py` | полная перевыгрузка → `snapshot.json`: правила метрик, валидация схемы, атомарная запись |
| `app/config.py` | ID воронок, нормы SLA, карты каналов и уволенных сотрудников |
| `app/scheduler.py` | пересбор по расписанию (внутри процесса API, без отдельного worker-контейнера) |
| `app/main.py` | FastAPI: `/login`, `/`, `/api/data`, `/health` |
| `app/auth.py` | логин + bcrypt + подписанная cookie на 30 дней |
| `build_web.py` | `web/index.html` из прототипа: данные через `/api/data`, баннер несвежести, выход |
| `deploy/up.sh` | выкладка на сервер |

Данных мало (~1.6 тыс. сделок), поэтому **Postgres не нужен**: срез — один JSON
в томе `lb_analytics_data`. Каждый прогон — полная перевыгрузка, дрейфа между
CRM и дашбордом не бывает.

## Почему цифрам можно верить

1. **Валидация схемы перед публикацией.** Не тот `account_id`, пропала воронка
   или переименован этап из норм SLA → `SchemaError`, новый срез не пишется,
   прежний остаётся. Проверка в `validate_schema()`.
2. **Сбой сбора не подменяет данные.** `run_collection()` пишет `snapshot.json`
   только при успехе, и то атомарно (`os.replace`).
3. **Возраст данных видно.** Старше `STALE_AFTER_HOURS` (26 ч) → красный баннер
   «данные не обновлялись N ч» с датой последнего успешного сбора и причиной сбоя.
   Тихой выдачи устаревших цифр не бывает.
4. **Правила метрик сверены с согласованным срезом 22.07.2026:** даты создания
   0 расхождений, даты закрытия 0 из 1237, причины отказа 0, источники — 11 из
   1611 (у них источник реально изменился в CRM за 9 дней).
5. **Никаких выдуманных метрик.** Spend / CPL / CAC / ROI по-прежнему не
   показываются: в Kommo нет рекламных расходов (`ПАСПОРТ_МЕТРИК.md` §1).
6. **Сбой сбора не оставляет дашборд на сутки:** следующий тик через 30 мин
   повторит попытку; старше 2 ч — красный баннер.

## Правила расчёта (кратко)

| Что | Как |
|---|---|
| Даты (создание, закрытие, переход в «Сборку») | **UTC** — так посчитан согласованный срез; смена пояса сдвинет историю на сутки |
| Выиграно | первый переход в Closed-won (status 142) внутри Pipeline; «В производстве» = переход в «Сборку» |
| Ответственный при закрытии | восстанавливается по `entity_responsible_changed` ≤ `closed_at`; текущее поле для истории негодно (82.8% расхождений) |
| Уволенные сотрудники | Kommo отдаёт по ним 404, имена берутся из `FORMER_USERS`, иначе «Бывший сотрудник» |
| Источник | FB-тег → `Channel` → `utm_source` → первый чат «(talk)»; мусор `да/нет` отбрасывается |
| Застряли | возраст на этапе по последнему `lead_status_changed` > нормы SLA |
| Без задачи / просрочка | сопоставление открытых сделок с открытыми задачами (`complete_till` < сейчас) |
| Где теряются | отказы по дате закрытия: этап `before` последнего перехода в status 143 (`lost_from_stage`). Линейную «конверсию этап→этап» не считаем: лиды входят с разных этапов и прыгают |
| «Сделки по этапам» | снимок открытых из созданных за период — очередь, не переходы |

Полный допуск метрик и оговорки —
`…/LicenseBridge_USA/дашборд/ПАСПОРТ_МЕТРИК.md`.

## Эксплуатация

```bash
# статус (без авторизации)
curl -s https://lb.mspod24.ru/health

# логи и принудительный пересбор
ssh licensebridge-hub 'docker logs --tail 50 lb-analytics'
ssh licensebridge-hub "docker exec lb-analytics python -c \
  'from app.collector import run_collection; print(run_collection())'"

# выложить изменения кода/вёрстки
python3 build_web.py && bash deploy/up.sh

# сменить пароль: пересчитать хеш, вписать в /opt/licensebridge-analytics/.env
# ВАЖНО: в .env для docker compose каждый $ → $$ (иначе хеш сломается: $2b/$12 съест compose)
python3 -c "import bcrypt;print(bcrypt.hashpw(b'НОВЫЙ',bcrypt.gensalt()).decode())"
# пример строки: AUTH_PASSWORD_HASH=$$2b$$12$$....
ssh licensebridge-hub 'cd /opt/licensebridge-analytics && docker compose up -d'
```

`/health` отдаёт `degraded`, если среза нет, он просрочен или схема Kommo не
сошлась — это и есть сигнал мониторинга.

## Ограничения

- Дашборд читает Kommo, но **не** отвечает за качество заполнения: пустой
  `price` у выигранных и `Channel` у 6.7% сделок остаются как есть.
- Разрез по менеджерам осмыслен только после стабилизации команды: до этого
  сделки вели уволенные сотрудники.
- Атрибуция отказов строже, чем в аудите 22.07: если сделка закрыта до первой
  смены ответственного, берётся тот, с кого потом сменили, а не текущий
  владелец карточки. Поэтому «Илона» в исторических отказах здесь меньше.
