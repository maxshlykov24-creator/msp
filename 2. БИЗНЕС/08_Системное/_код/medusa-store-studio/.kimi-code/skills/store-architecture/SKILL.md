Спроектируй структуру магазина «**$brief**» **до того, как наводить красоту**.

> ⚠️ **Зачем этот шаг.** Стартер Medusa даёт только коммерческий костяк: каталог, товар, корзина, чекаут, аккаунт. В нём **нет** страниц «о нас», «контакты», «доставка и оплата», «возврат», «оферта», «политика», «избранное» — и нет нормальной главной (там заглушка). Если сразу звать дизайн, агент отполирует то, что есть, и не достроит то, чего нет. Результат — красиво, но торговать нельзя.

## 1. Инвентарь страниц (gate — проверить, что всё существует)

**Коммерция** (обычно уже есть в стартере — проверить):
- [ ] Главная `/`
- [ ] Каталог `/store` · Категории `/categories/[slug]` (вложенные) · Коллекции `/collections/[handle]`
- [ ] Карточка товара `/products/[handle]`
- [ ] Корзина (страница и/или drawer) · Чекаут (свой layout, **гость разрешён**) · Подтверждение заказа
- [ ] Поиск и результаты `/search` + **пустое состояние**

**Аккаунт:**
- [ ] Вход / регистрация · Личный кабинет · История заказов · Детали заказа · Адреса · Профиль
- [ ] **Избранное / вишлист** ← в стартере нет, обычно забывают
- [ ] Восстановление пароля

**Контент и юридическое** ← **этого в стартере нет вообще, создавать с нуля:**
- [ ] О нас · Контакты · FAQ
- [ ] **Доставка и оплата** · **Возврат и обмен**
- [ ] Блок из раздела 5 (обязательный для РФ)

**Служебное:**
- [ ] 404 · пустые состояния (корзина, избранное, поиск, категория) · `sitemap.xml`

**Действие:** пройди список, отметь, чего нет, покажи пользователю план создания — и создай недостающие маршруты с осмысленными заглушками контента (не «lorem ipsum», а реальный текст под этот магазин).

## 2. Каркас главной (e-commerce, НЕ SaaS-лендинг)

Типичная ошибка ИИ — собрать главную как лендинг стартапа: hero с градиентом, три колонки «иконка+текст», «Get Started». **Для магазина канон другой:**

1. **Шапка (sticky):** лого · навигация по категориям · **открытое поле поиска** (не иконка — для каталога это конверсионно важно) · избранное · корзина со счётчиком
2. **Hero:** одна статичная промо-картинка, одно сообщение, одна CTA. **Карусели работают хуже** — не делать по умолчанию
3. **Входы в категории** — плитки с фото, главный навигационный блок
4. **Хиты продаж / новинки** — реальные товары с ценами, а не «фичи»
5. **Блок доверия (USP-бар):** доставка, срок возврата, безопасная оплата, гарантия
6. **Социальное доказательство:** отзывы, фото покупателей
7. **Редакционный блок** (опционально): подборка, лукбук, гид
8. **Подписка** на рассылку
9. **Футер:** юр-документы · сервис (FAQ, доставка, возврат, контакты) · о компании · **реквизиты продавца** · иконки оплаты · соцсети

## 3. Навигация и таксономия

- **Мега-меню** — если категорий много (10+, как в одежде/электронике). **Простое меню** — для узкого DTC-ассортимента. Не усложнять без нужды.
- Глубина: `Главная > Категория > Подкатегория > Товар`. Глубже 3 уровней — обязательны **хлебные крошки**.
- 🔴 **Промежуточные страницы — главный провал большинства магазинов.** Страница категории не должна вываливать плоский список всех товаров: сначала **плитки подкатегорий**, потом товары. По исследованиям это одна из самых частых ошибок, и почти никто не показывает, где пользователь сейчас находится (активное состояние в меню + крошки).
- Фасетные фильтры (цена, размер, цвет, бренд, наличие) + сортировка, состояние **в URL** — для SEO и чтобы ссылкой можно было поделиться.

## 4. Мерчандайзинг (где что стоит)
- **Карточка товара:** похожие товары, «с этим часто покупают», «собрать образ»
- **Корзина:** кросс-сейл + подсказка «до бесплатной доставки осталось N ₽»
- **Сквозное:** недавно просмотренные
- **Пустые состояния:** вместо «ничего не найдено» — хиты продаж

## 5. 🇷🇺 Обязательное для российского магазина

Без этого магазин юридически не готов торговать. Создать страницы и **сослаться на них из футера**, а на чекауте — чекбокс согласия:

- [ ] **Публичная оферта** — предмет, цена, доставка, оплата, условия возврата, переход права собственности
- [ ] **Политика обработки персональных данных** (152-ФЗ)
- [ ] **Пользовательское соглашение**
- [ ] **Реквизиты продавца** — наименование, ОГРН/ОГРНИП, ИНН, адрес, контакты (в футере + отдельной страницей)
- [ ] **Условия возврата** — с учётом права на возврат в течение 7 дней (ЗоЗПП)

⚖️ **Важно:** генерируй **черновики** документов под конкретный магазин и прямо скажи пользователю: «это заготовки, перед запуском продаж их должен проверить юрист». Не выдавай сгенерированный текст за готовый юридический документ.

## 6. Путь покупателя (проверить сквозняком)
`Главная → категория → подкатегория → товар → корзина → чекаут → подтверждение`

- **Гостевой заказ обязателен** — принудительная регистрация выбивает покупателей.
- Чекаут: корзина → гость/аккаунт → адрес → доставка → оплата → проверка → подтверждение.
- Подтверждение заказа: номер, состав, сумма, срок доставки, что дальше.
- Данные не запрашиваются повторно между шагами.

> Отраслевой контекст (для понимания планки): брошенных корзин в среднем ~70%, и подавляющее большинство магазинов имеют посредственный чекаут. Аккуратно сделанный путь — реальное конкурентное преимущество, а не перфекционизм.

## 7. Результат шага
1. Показать пользователю **карту сайта**: что было, что добавили.
2. Все маршруты созданы и открываются (нет 404 на своих же ссылках).
3. Футер связывает все служебные и юридические страницы.
4. Главная собрана по каркасу из раздела 2.
5. Только теперь → `скилл store-design` наводить красоту.
