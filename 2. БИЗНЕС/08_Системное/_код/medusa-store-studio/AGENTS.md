# AGENTS.md — Medusa Store Studio

Агентная среда для сборки **интернет-магазинов под российский рынок**: Medusa v2 (бэкенд + админка) + Next.js-витрина + российские платёжки с чеками 54-ФЗ. Магазином можно управлять прямо из агента.

## Что мы строим
Полноценный магазин: каталог, корзина, чекаут, оплата картами/СБП, фискальные чеки, доставка, админка на русском. Хостится на своём сервере — движок бесплатный, платишь только за VPS.

## Ключевой принцип
**Коробка даёт коммерцию, агент даёт дизайн и наполнение.** Medusa из коробки — рабочий, но визуально шаблонный магазин. Ценность агента: (1) довести дизайн до уровня «делал дизайнер», (2) подключить российские платёжки/доставку, (3) наполнить и вести каталог.

## Стек
- **Бэкенд:** Medusa v2 (Node 20–24, PostgreSQL 15+; Redis — только прод)
- **Витрина:** Next.js 15 + Turbopack + Tailwind (официальный стартер Medusa)
- **Оплата:** ЮKassa (карты, СБП, SberPay, MirPay) + чеки 54-ФЗ через плагины Gorgo
- **Хостинг:** любой RU VPS (~650–950 ₽/мес)

## Пайплайн (skills) — порядок важен
1. `скилл store-setup <название>` — развернуть магазин, БД, админку, витрину, рублёвый регион.
2. **`скилл store-architecture <бриф>` — спроектировать СТРУКТУРУ: недостающие страницы, каркас главной, навигация, юр-статика для РФ. ← без этого шага дизайн полирует дырявый каркас.**
3. **Open Design (MCP) — дизайн-система.** Выбрать бренд-контракт `DESIGN.md` из библиотеки (151 система) и прогнать **refresh по существующему коду**: агент рефакторит реальные компоненты витрины под спеку. Подключение: `od mcp install kimi`.
4. `скилл store-design <бриф>` — ecom-детали поверх бренда: карточка, каталог, PDP, корзина, состояния.
5. `скилл payments-ru` — подключить оплату и фискальные чеки.
6. `скилл shipping-ru` — доставка (СДЭК/Почта/Boxberry).
7. `скилл store-manage <задача>` — наполнение и ведение каталога через Admin API.
8. `скилл deploy-store` — деплой на VPS.

⚠️ **Почему такой порядок.** Open Design рефакторит то, **что уже есть** — на голом стартере ему нечего причёсывать. Поэтому сначала шаг 2 достраивает страницы, и только потом бренд накрывает готовый каркас.

⚠️ **Ключевой факт:** стартер Medusa даёт только коммерческий костяк (каталог, товар, корзина, чекаут, аккаунт). Страниц «о нас», «доставка», «возврат», «оферта», «политика», «избранное» и нормальной главной в нём **нет** — их создаёт шаг 2.
Ревью перед сдачей: сабагенты `design-critic` (внешний вид) и `store-qa` (коммерция).

## Конвенции
- **Цены в major-единицах:** 1990 = 1990 ₽ (в Medusa v1 было иначе — частая ошибка).
- Рублёвые цены работают только при наличии **региона с валютой RUB**.
- Плагины Medusa **v1 несовместимы** с v2.
- Витрина ходит в Store API с **publishable key**; агент управляет через **Admin API** с JWT.
- Тексты магазина — на русском, человеческим языком, без канцелярита.

## Гардрейлы
- 🔒 **Секреты** (ключи ЮKassa, пароли админа, токены) — только в `.env`/окружении. Никогда в код, в git и в чат.
- 💳 **Деньги — это ответственность.** Любую платёжную интеграцию проверять на тестовом магазине до боевого. Не обещать «работает» без проведённого тестового платежа.
- 📜 **54-ФЗ:** приём платежей от юрлица/ИП требует фискальных чеков. Не запускать продажи без настроенных чеков и не утверждать, что «и так сойдёт».
- ⚠️ Перед массовым изменением/удалением каталога — подтверждение пользователя.
- 🎯 Честная экономика: движок бесплатный, но эквайринг берёт свой процент, а сервер стоит денег. Не обещать «бесплатный магазин».
- 🚫 **Не «нейрослоп»:** дизайн только через `store-design` (токены → самокритика → вёрстка), иначе выйдет шаблон.

## Команды проекта
```bash
npm run dev                 # turbo: бэкенд + витрина
cd apps/backend && npx medusa develop     # :9000, админка :9000/app
cd apps/storefront && npm run dev         # :8000
npx medusa db:migrate                     # миграции
npx medusa user -e <email> -p <pass>      # создать админа
```
