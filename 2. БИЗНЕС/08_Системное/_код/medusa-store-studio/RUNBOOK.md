# 🎬 RUNBOOK — прогон магазина от начала до конца

Пошаговый сценарий: идёшь сверху вниз, копируешь промпты, на выходе — работающий магазин. Рассчитан на **репетицию до записи**, чтобы на камере не спотыкаться.

**Реальное время полного прогона: ~2.5 часа** (из них ~15 мин ждёшь установку). На записи это ужмётся в 8 минут за счёт перемоток.

---

## 0. ДО СТАРТА (5 мин, сделать один раз)

**Проверь окружение:**
```bash
node -v          # нужно 20–24
psql --version   # нужен PostgreSQL 15+
pg_isready       # должно быть "accepting connections"
lsof -ti:9000,8000 | xargs kill -9 2>/dev/null   # освободить порты
```
Если постгрес не отвечает на macOS — фикс в `store-setup`, раздел 0 (кривые симлинки Homebrew).

**Реши, что продаём.** От этого зависит дизайн и каталог. Хорошие варианты для съёмки: кофе, парфюм, керамика, кроссовки, украшения — визуально богатые, легко найти фото. Дальше в промптах вместо `<ТОВАР>` подставляй своё.

**Открой эту папку в агенте** (Codex, Kimi Code или Claude Code) и проверь, что скиллы видны — попроси перечислить доступные скиллы. Должны быть `store-setup`, **`store-architecture`**, `store-design`, `payments-ru`, `shipping-ru`, `store-manage`, `deploy-store`.

## ШАГ 1 · Развернуть магазин (~20 мин, из них 15 — ожидание)

```
скилл store-setup магазин <ТОВАР>
```

**Что произойдёт:** агент создаст проект (`npx create-medusa-app`), подключит базу, прогонит миграции, создаст админа, поднимет бэкенд и витрину.

**Контрольные точки — не идти дальше, пока не выполнено:**
- [ ] `curl localhost:9000/health` → `OK`
- [ ] Админка `localhost:9000/app` открывается, логин работает
- [ ] Витрина `localhost:8000` показывает демо-товары
- [ ] Создан регион **Россия** с валютой **RUB**

**Где спотыкается (проверено):**
- Установка идёт **~15 минут** — это норма, не зависание.
- `.env` может быть без перевода строки → `DATABASE_URL` приклеится к предыдущей строке → миграции упадут простынёй «No database clientUrl provided». Проверить: `grep -n '^DATABASE_URL' apps/backend/.env`.
- Витрина не найдёт регион, если `NEXT_PUBLIC_DEFAULT_REGION` не совпадает со страной региона.

📸 **Снять для ролика:** дефолтную витрину — это твоё «ДО» для сплита с дизайном.

## ШАГ 2 · Структура магазина (~20 мин) — ⚠️ НЕ ПРОПУСКАТЬ

```
скилл store-architecture магазин <ТОВАР>, рынок Россия
```

**Зачем:** в стартере Medusa есть только коммерческий костяк. **Нет** страниц «о нас», «контакты», «доставка и оплата», «возврат», «оферта», «политика данных», «избранное» — и главная это заглушка. Если сразу звать дизайн, агент отполирует то, что есть, и не достроит то, чего нет. Это ровно та ошибка, из-за которой первый прогон вышел провальным по UX.

**Контрольные точки:**
- [ ] Агент показал **карту сайта**: что было, что добавил
- [ ] Созданы контентные страницы: о нас, контакты, FAQ, доставка и оплата, возврат
- [ ] Созданы юридические: оферта, политика персональных данных, пользовательское соглашение, реквизиты
- [ ] Есть избранное, страница поиска с пустым состоянием, 404
- [ ] **Главная собрана как магазин:** шапка с открытым полем поиска → hero → плитки категорий → хиты → блок доверия → отзывы → подписка → футер со всеми ссылками
- [ ] Футер связывает все служебные страницы, нет 404 на свои же ссылки
- [ ] Страница категории показывает подкатегории, а не плоский список

**Если главная опять как SaaS-лендинг** (градиент, три колонки «иконка+текст», «Начать») — дожать:
```
Главная собрана как лендинг стартапа, а нужен магазин. Переделай по каркасу: шапка с открытым поиском, hero с одним промо, плитки входа в категории, блок хитов с реальными товарами и ценами, полоса доверия (доставка/возврат/оплата), отзывы, подписка, футер со всеми служебными ссылками.
```

⚖️ Юр-документы агент генерирует **черновиками** — перед реальными продажами их должен посмотреть юрист. В ролике так и сказать.

📸 **Снять:** карту сайта / список созданных страниц — наглядно, что агент достроил магазин, а не только покрасил.

## ШАГ 3 · Дизайн-система через Open Design (~25 мин) — 🎨 источник насмотренности

MCP Open Design уже подключён к Kimi (`od mcp install kimi`). Это тот самый недостающий кусок: агент перестаёт **выдумывать** дизайн и начинает работать по **бренд-контракту**.

**3.1 Выбрать дизайн-систему.** В репозитории Open Design лежит **151 готовая система** (каждая — `DESIGN.md` с токенами, у новых ещё `tokens.css`, компоненты, ассеты). Открой библиотеку и выбери близкую по характеру товара — премиальный минимализм, техно, лайфстайл. Свою папку с `DESIGN.md` тоже подхватит.

**3.2 Прогнать refresh по существующему коду.** Ключевая фича: агенту отдаётся **репозиторий + `DESIGN.md`**, и он рефакторит реальные компоненты под спеку.

```
Возьми активную дизайн-систему Open Design и прогони refresh по витрине: apps/storefront. Приведи компоненты к бренд-контракту — палитра, типографическая шкала, отступы, радиусы, моушен. Не ломай логику данных Medusa (загрузка товаров, корзина, чекаут) — меняй только представление.
```

**Контрольные точки:**
- [ ] Токены системы реально применились (цвета/шрифты/отступы поменялись, а не остались дефолтные)
- [ ] Витрина по-прежнему рабочая: товары грузятся, корзина считает, чекаут открывается
- [ ] Единая типографическая шкала и один акцентный цвет по всему магазину
- [ ] На мобильном не разъехалось

⚠️ **Почему именно здесь, а не раньше.** Refresh рефакторит то, **что уже есть**. Запустишь на голом стартере — причешет две страницы (главную-заглушку и каталог), и всё. Поэтому сначала шаг 2 достраивает страницы, и только потом бренд накрывает готовый каркас.

⚖️ Если берёшь за эталон известный бренд — извлекай **язык** (ритм, пропорции, палитру), но не логотип, не название и не продуктовые рендеры. Лучше готовая система из библиотеки под своим брендом.

📸 **Снять:** момент подключения/выбора системы и «до/после» рефреша — это сильный кадр.

## ШАГ 4 · Ecom-детали поверх бренда (~20 мин)

```
скилл store-design <ТОВАР>. Настроение: <например: тёмный минимализм, товар — герой, много воздуха>. Возьми за ориентир характер бренда из references/brand-tokens.
```

**Что произойдёт:** бренд уже задан шагом 3 — здесь добиваем то, чего Open Design не знает: коммерческие паттерны. Пропорции карточек, галерея на PDP, sticky-кнопка покупки, drawer корзины, состояния (нет в наличии, пусто, загрузка).

**Контрольные точки:**
- [ ] Карточки товара в **единых пропорциях** (не рваная сетка)
- [ ] На hover карточка меняет фото или мягко увеличивается
- [ ] Название и цена **по левому краю**, не по центру
- [ ] Не больше одного бейджа на карточку
- [ ] Нет фиолетово-синих градиентов и Inter как основного шрифта
- [ ] На мобильном не разъезжается

**Если вышло похоже на шаблон** — не мириться, дожать:
```
Это всё ещё читается как шаблон. Возьми одну эстетику из references/brand-tokens, выведи из неё палитру и пару шрифтов, и переделай карточку товара и каталог по ней. Один акцентный цвет, крупная типографика, больше воздуха.
```

Затем ревью:
```
Прогони сабагента design-critic по витрине и почини всё, что blocker и high.
```

📸 **Снять:** «ПОСЛЕ» + сплит с «ДО». Это ключевой кадр ролика — не пожалей времени.

## ШАГ 5 · Оплата и чеки (~15 мин)

```
скилл payments-ru подключи ЮKassa и Т-Кассу
```

**Что произойдёт:** установка плагинов, регистрация в `medusa-config.ts`, переменные окружения, привязка провайдеров к региону «Россия».

**Ключи:** для репетиции хватит заглушек (`test_shop_id` / `test_secret_key`) — провайдеры всё равно зарегистрируются и появятся в админке. Живой платёж не проводим.

**Контрольные точки:**
- [ ] Сервер стартует **без ошибок** после правки конфига
- [ ] В админке **Settings → Regions → Россия** видно `Tkassa (TKASSA), Yookassa (YOOKASSA)`
- [ ] В конфиге стоит `useReceipt: true` (чеки 54-ФЗ)

**Известная ловушка:** ответ API на привязку провайдера возвращает пустой массив **даже при успехе**. Не привязывать повторно — проверять в админке или через `fields=+payment_providers.*`.

📸 **Снять:** экран админки с двумя платёжками и регионом Россия.

## ШАГ 6 · Каталог из агента (~20 мин) — 🤖 второй вау

Сначала подготовь «прайс» — просто список в свободной форме (10–20 позиций: название, описание, цена, размер/цвет).

```
скилл store-manage заведи товары из этого списка: <вставить прайс>. Категории создай сама. Цены в рублях.
```

**Контрольные точки:**
- [ ] Агент **показал план перед заливкой** (сколько товаров, категории) и дождался подтверждения
- [ ] Товары появились в админке
- [ ] Товары видны **на витрине** с ценами **в рублях**
- [ ] Категории работают

**Частая ошибка:** цены в Medusa v2 — в major-единицах (1990 = 1990 ₽). Если цена выглядит как 19.90 ₽ или 199000 ₽ — масштаб перепутан, сказать агенту переделать.

📸 **Снять:** как ты пишешь «заведи 20 товаров» → агент работает → товары появляются на витрине. **Это то, чего конструктор не умеет — снимать не жалея.**

## ШАГ 7 · Доставка (~10 мин, опционально)

```
скилл shipping-ru подключи ApiShip
```
Настройка после установки — **в админке** (`Settings → ApiShip`), env-переменных нет.
Для репетиции можно ограничиться установкой и показом раздела настроек.

## ШАГ 8 · Финальная проверка (~10 мин)

```
Прогони сабагента store-qa по магазину и покажи все находки по severity.
```

**Контрольные точки перед «сдачей»:**
- [ ] Нет blocker'ов
- [ ] Цены в рублях в правильном масштабе
- [ ] Нет ключей и паролей в коде/гите
- [ ] Путь покупателя проходится целиком: каталог → товар → корзина → чекаут
- [ ] На мобильном всё работает

📸 **Снять:** полный проход покупателя на десктопе и мобиле — финальное доказательство.

## ШАГ 9 · Деплой (опционально, ~30 мин)

```
скилл deploy-store
```
Для ролика можно **не деплоить** — достаточно показать, что скилл есть и что путь понятен. Если деплоишь: нужен VPS, домен, Redis. Ключи и токены на экране — **блюрить**.

## 🎥 Чек-лист съёмочных кадров
- [ ] Дефолтная витрина (**ДО**)
- [ ] Витрина после дизайна (**ПОСЛЕ**) + сплит
- [ ] Админка: регион Россия + две платёжки
- [ ] Админка на русском (и видимые английские пункты — для честности)
- [ ] Агент заводит товары → они появляются на витрине
- [ ] Проход покупателя: каталог → карточка → корзина → чекаут
- [ ] Мобильная версия
