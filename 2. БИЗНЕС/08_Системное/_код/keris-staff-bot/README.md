# keris-staff-bot — фото до/после для администратора

Telegram-бот **@kerisclubphotobot** («Keris Club Photo»). Один сценарий: администратор
выбирает запись за сегодня или за вчера, присылает фото «до» и «после», отправляет
отчёт клиенту.

В списке только незакрытые визиты — те, где не хватает фото «до» или «после».
Всё загружено — бот отвечает «все супер» вместо пустого списка.

Бот Карины (`keris-admin-bot`) не затрагивается: у неё управление и уведомления,
здесь — только фото. Разные токены, разные whitelist.

## Где живут фото

Фото не остаются в Telegram: сервер скачивает файл себе (`getFile` даёт `file_path`
на ~час) и хранит в `PHOTOS_DIR` (`/var/lib/keris/photos/<booking_id>/`), раздаёт
nginx через `/media/`. Постоянное место отчёта — кабинет «Мой Keris»: клиент
открывает любой прошлый визит и видит фото. Сообщение в боте клиента — дубль.

Клиент ещё не в боте — фото всё равно сохранены. Отчёт помечается ожидающим и
уходит автоматически, когда клиент поделится номером в Telegram или MAX.

## Маршрут

```
администратор → @kerisclubphotobot → POST /admin/bookings/{id}/photos → файл на диске
                                   → POST /admin/bookings/{id}/report/send → клиент
```

## Запуск

```bash
KERIS_DEPLOY_PASSWORD=... STAFF_BOT_TOKEN=... STAFF_TELEGRAM_IDS=... ADMIN_API_KEY=... \
  python3 deploy.py
```

`STAFF_TELEGRAM_IDS` — Telegram ID администраторов через запятую. Свой ID видно в
ответе бота на `/start`, пока whitelist пуст. `ADMIN_API_KEY` — тот же, что у
`keris-server`, иначе admin-API вернёт 401.

`STAFF_AUTO_ENROLL_LIMIT` (по умолчанию 3) — сколько новых людей получают доступ
сами, без правки `.env`: первые три написавших боту (Карина, администратор салона,
запас) занимают места и попадают в `state.json`. Дальше доступ только через
whitelist. Сбросить места — удалить ключ `_enrolled` в `state.json` и рестартнуть.

Логи: `journalctl -u keris-staff-bot -f`.
