## Что работает

- новый клиент: питомец → услуга → мастер → дата и слот → контакты → мгновенное подтверждение;
- повторный клиент: демонстрационный Keris Memory → повтор прошлой услуги → новый слот;
- собака и кошка (оба блока есть в прайсе собственника), автоматическая ценовая категория;
- конкретный мастер и «Любой свободный»;
- допуслуги, итоговая цена и длительность;
- состояния «нет мест» и «слот только что занят» (слот `20:15`);
- добавление записи в календарь, перенос, отмена и переход в `@kerisclubbot`;
- phone-first интерфейс для сайта и Telegram WebView.

## Мой Keris (кабинет клиента)

Вход по номеру телефона: SMS-код из 4 цифр (`POST /api/auth/request-code` →
`POST /api/auth/verify`, шлёт P1SMS). Профиль, питомцы, абонемент и история визитов
приходят с сервера: `GET /api/client?phone=…` — своих данных браузер не хранит,
кроме самого номера в `localStorage`. Что даёт кабинет:

- ближайшая запись, история визитов и карточка визита;
- Keris Memory — паспорт питомца из истории (последний визит, любимый мастер, повтор ухода);
- автоподстановка имени и телефона в форму записи (поля остаются редактируемыми);
- выбор питомца из профиля или «Другой питомец» на первом шаге;
- отзыв о мастере: форма открыта только клиенту с завершённым визитом у него
  (`POST /api/reviews`, то же правило проверяет сервер), отзывы отдаются в `GET /api/masters`.

Демо-профиля в файле нет: без записей кабинет пустой. Для тестов история подставляется
подменой `fetch` (`prototype.html?stub=1`, см. `test_prototype.py`).

## Живой API (Этап 2, с 2026-07-28)

`prototype.html` теперь подгружает актуальные цены/длительности/мастеров с `keris-server`
(`GET /api/services|addons|masters|subscriptions`, функция `loadLiveCatalog()`) и после
подтверждения записи фоново отправляет её на сервер (`POST /api/bookings`,
`syncBookingToServer()`) — источник истины: `2. БИЗНЕС/08_Системное/_код/keris-server/`.
Если сервер недоступен (в т.ч. локальный автономный файл `file://`) — тихий откат на
встроенные `DATA` и мок-логику слотов, как раньше; демо и `test_prototype.py`
не зависят от сети. Полная миграция генерации слотов на сервер (вместо клиентской
эвристики) — следующий шаг.

### Перенос и отмена (с 2026-08-07)

Кнопки в кабинете, на экране визита и на экране подтверждения работают через API,
а не через «напишите в Telegram»:

| Действие | Запрос | Поведение |
|---|---|---|
| Перенести | `POST /api/bookings/{id}/reschedule` (`submitReschedule`) | Переезжает **та же** запись: мастер, услуга и питомец сохраняются, поэтому на шаге «Мастер и время» показывается только текущий мастер. Новой записи не создаётся, прежний слот освобождается сервером |
| Отменить | `POST /api/bookings/{id}/cancel` (`cancelBooking`) | Слот освобождается, визит абонемента возвращается на баланс |

Телефон владельца записи уходит в оба запроса как право на действие (`state.movePhone`
для переноса, `bookingActionTarget()` для обоих). Ближе чем за 24 ч
(`DATA.rules.freeRescheduleHours`) клиент видит отсылку к мастеру и запрос не уходит —
то же правило проверяет сервер. Смена мастера или услуги — это не перенос, а новая запись.

Статус `no_show` из `/api/client` (администратор поставил «Не пришел» в журнале YCLIENTS)
показывается как «Не пришёл» с пометкой, что слот освобождён, и кнопкой «Записаться заново».

Сервер сам пушит запись в YCLIENTS (зеркало календаря) и amoCRM (сделка), шлёт
уведомление в личный бот Карины — см. `ТЗ_ЭТАП2_ГРУМИНГ.md`.

Старый контракт payload (для справки, актуальные поля — `app/main.py:BookingIn`):

```json
{
  "booking_id": "KERIS-1234",
  "owner": {"name": "Анна", "phone": "+79990000000"},
  "pet": {"name": "Тедди", "type": "dog", "breed": "мальтипу", "weight_kg": 4.2, "size": "XS"},
  "service_id": "dog_complex_cut",
  "addon_ids": ["dog_mask_hydra"],
  "price": 9100,
  "master_id": "anna",
  "starts_at": "2026-07-22T13:00:00+03:00",
  "ends_at": "2026-07-22T15:30:00+03:00",
  "source": "website",
  "utm": {},
  "comment": "",
  "personal_data_consent": true,
  "previous_visit_id": null
}
```

События аналитики уже обозначены вызовами `track()`: открытие, экраны, выбор питомца, услуги, мастера, даты и слота, ошибка занятого слота, подтверждение, перенос, отмена, календарь и повтор прошлой услуги.

## Ограничения

Слоты в UI считаются клиентской эвристикой (мок), реальная проверка доступности и
анти-гонка — на сервере в момент `POST /api/bookings`. YCLIENTS-синхронизация и
amoCRM-сделка активируются после появления `YCLIENTS_USER_TOKEN`/`AMOCRM_LONG_LIVED_TOKEN`
(см. `keris-server/README.md`). Фотосессия, бронь щенка и привилегии покупателей щенка
не продаются.

## Проверка

При установленном Playwright:

```bash
python3 test_prototype.py
```

Smoke-тест проверяет ширины 360, 390, 430 и 1440 px, отсутствие горизонтального скролла, новый и повторный сценарии, занятый слот, отсутствие мест, перенос через `/reschedule` (из кабинета и с экрана визита), отмену через `/cancel`, запрет изменений в окне 24 ч и статус «Не пришёл». API кабинета и записи подменяется стабом (`?stub=1`), отправленные запросы видны в `window.__apiPosts`.
