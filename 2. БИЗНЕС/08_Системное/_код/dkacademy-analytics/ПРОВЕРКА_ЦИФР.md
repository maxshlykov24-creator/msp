# DKAcademy Analytics — проверочный регламент

**Дашборд:** https://dkacademy-analytics.ru
**Версия формул:** 2026-07-20
**Полный паспорт:** [`МЕТРИКИ.md`](МЕТРИКИ.md)
**Обновление:** каждые 10 минут, 07:00–22:00 МСК.

## Критерий приёмки

- Счётные показатели: разница дашборд ↔ независимый расчёт = **0**.
- Деньги: разница = **0 ₽**.
- Проценты: только округление интерфейса, не более **0,01 п.п.**
- `avg_check = revenue / paid`.
- Когортные успехи являются подмножеством лидов когорты; конверсия ≤100%.
- Сумма разрезов менеджеров и дневных значений равна отделу для одной оси даты.
- Нет дублей `lead_id`, note id и event id.
- Любое иное расхождение раскладывается до конкретных сущностей и получает документированную причину.

Задержка автоматического цикла не считается допустимым постоянным расхождением: приёмка выполняется после завершённого сбора.

**Граница строгой приёмки:** лиды, когортный Успех и конверсия, оплаты,
приход, средний чек, количество счетов и звонки. Сумма счетов остаётся
операционной: событие перехода не хранит исторический бюджет сделки.
Сообщения, диалоги, пропущенные, `rt_avg` и `first_rt_avg` также операционные:
их полная история требует длительного чтения событий amoCRM.

## Три обязательных периода

1. Полный закрытый календарный месяц.
2. Последние семь полных календарных дней, без текущего незавершённого дня.
3. Произвольный диапазон внутри доступной истории событий.

Границы включительны, календарные сутки считаются в `Europe/Moscow`.

## Машинная сверка

На сервере из каталога проекта:

```bash
python scripts/audit_amo.py \
  --period 2026-06-01:2026-06-30 \
  --period 2026-07-13:2026-07-19 \
  --period 2026-04-10:2026-04-20 \
  --compare-db \
  --skip-communications \
  --output reports/audit_latest.json
python scripts/render_audit_report.py reports/audit_latest.json
```

`--compare-db` читает только итоговые агрегаты production-дашборда; формулы
независимого расчёта по-прежнему получают исходные сущности напрямую из amoCRM.
Для проверки именно HTTP API вместо этого передаются `DKA_DASH_LOGIN` и
`DKA_DASH_PASSWORD`. Значения в отчёт и git не записываются.

Выход:

- `reports/audit_latest.json` — агрегаты, разницы, инварианты и исходные id.
- `reports/Протокол_сверки_DKAcademy.html` — клиентский протокол без персональных данных.

## Ручная контрольная сверка

1. **Новые обращения:** воронка «Продажи» + дата создания.
2. **Когортный Успех:** сохранить список `lead_id` из п.1 и проверить текущий статус этих же сделок.
3. **Оплачено / приход:** «Успех» + дата закрытия; количество и сумма бюджета.
4. **Счета:** события перехода на «Отправлен счёт»; первый переход на `lead_id`.
5. **Звонки:** `call_in/call_out`, дата создания заметки, длительность в секундах.
6. **Сообщения / SLA:** события чатов и пары входящее → следующее исходящее по одному `lead_id`.
7. Повторить для одного менеджера и одного источника.

## Backfill без удаления планов

1. Сделать `deploy/backup.sh`.
2. Не удалять snapshot `plans`.
3. Сбросить только вычисляемые `metric_daily`, `invoice_facts` и курсор `backfill_done_from`.
4. Запустить `python -m app.collector backfill`.
5. Дождаться завершения и выполнить машинную сверку.
6. Проверить следующий штатный 10-минутный цикл: свежесть изменилась, цифры и инварианты не разошлись.

## Качество исходных данных

`GET /api/data_quality` отдельно показывает успешные сделки:

- с `price=0`;
- без контакта;
- без источника;
- без ответственного;
- с отсутствующим или некорректным `closed_at`.

Нулевая сумма не является ошибкой формулы: сделка входит в количество оплат, добавляет 0 ₽ к приходу и снижает средний чек.

## Снимки, не зависящие от периода

Воронки, открытые сделки, сделки без задач, просроченные, застрявшие и качество CRM — «на сейчас». Постоянные клиенты — за всё доступное время. Причины провала — фиксированные последние 60 дней. Эти показатели нельзя принимать как данные выбранного периода.
