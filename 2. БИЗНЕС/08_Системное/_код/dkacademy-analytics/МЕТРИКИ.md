# Паспорт метрик DKAcademy Analytics

**Версия формул:** 2026-07-20  
**Часовой пояс:** `Europe/Moscow`  
**Границы периода:** обе даты включительно, календарные сутки 00:00:00–23:59:59 МСК.  
**Основной контур:** только воронка «Продажи» (`PIPELINE_SALES`). Воронка «Повторные продажи» учитывается только в метриках `repeat_*`. «Магазин» не входит.

## Типы данных

- `created_at` — когорта сделок, созданных в выбранном периоде.
- `closed_at` — сделки, успешно закрытые в выбранном периоде.
- `event` — событие amoCRM, произошедшее в выбранном периоде.
- `snapshot` — состояние CRM на момент последнего сбора; фильтр периода не применяется.
- Все счётные сущности дедуплицируются по `lead_id` или `event id` в пределах правила метрики.

## Реестр

| Метрика / API | Бизнес-смысл | Тип и дата | Формула и дедупликация | Контур | Ручная сверка |
|---|---|---|---|---|---|
| `new_leads` | Новые обращения | `created_at` | уникальные `lead_id`, созданные в периоде | Продажи | Сделки → дата создания + воронка |
| `cohort_won`, UI «Сконвертировано в Успех» | Лиды когорты, когда-либо дошедшие до Успеха | когорта `created_at` | уникальные `lead_id` когорты с текущим `status_id=Успех`; дозревает после периода | Продажи | выгрузить когорту по дате создания, проверить текущий статус |
| `conv_lead_deal` | Когортная конверсия | когорта `created_at` | `cohort_won / new_leads × 100%` | Продажи | предыдущие две выборки |
| `paid` | Количество оплаченных сделок | `closed_at` | уникальные успешные `lead_id`, закрытые в периоде | Продажи | Успех + дата закрытия |
| `revenue` | Приход | `closed_at` | сумма текущего `price` тех же успешных сделок | Продажи | сумма бюджета выборки `paid` |
| `avg_check` | Средний чек | `closed_at` | `revenue / paid` | Продажи | предыдущие две выборки |
| `invoice_count` | Сделки, впервые вошедшие в «Отправлен счёт» | `event.created_at` | один первый переход на этап на `lead_id`; повторный вход не дублируется | Продажи | события смены этапа → «Отправлен счёт» |
| `invoice_sum` | Сумма выставленных счетов | `event.created_at` | сумма бюджета сделок из `invoice_count` на момент доступного снимка amoCRM | Продажи | открыть `lead_id` из аудита и сверить бюджет |
| `repeat_created` | Созданные повторные обращения | `created_at` | уникальные `lead_id` | Повторные | дата создания + воронка |
| `repeat_cohort_won` | Успешные сделки повторной когорты | когорта `created_at` | уникальные `lead_id` когорты с текущим Успехом | Повторные | когорта + текущий статус |
| `conv_repeat` | Когортная конверсия повторных | когорта `created_at` | `repeat_cohort_won / repeat_created × 100%` | Повторные | предыдущие две выборки |
| `repeat_deals`, `repeat_revenue` | Закрытые повторные сделки и сумма | `closed_at` | количество и сумма `price` успешных сделок | Повторные | Успех + дата закрытия |
| `calls_out` | Исходящие звонки | `note.created_at` | уникальные заметки типа `call_out` | все лиды | отчёт телефонии / заметки |
| `call_minutes` | Длительность звонков | `note.created_at` | сумма `params.duration / 60` для `call_in` и `call_out` | все лиды | отчёт телефонии |
| `msg_in`, `msg_out` | Сообщения | `event.created_at` | уникальные event id соответствующего типа | все лиды | события чатов |
| `dialogs` | Начатые диалоги | `event.created_at` | уникальные `talk_created`; fallback — пара `lead_id + день` с входящим | все лиды | события бесед |
| `missed` | Пропущенные диалоги | `event.created_at` | уникальные `talk_missed_event` | все лиды | события бесед |
| `rt_*`, `first_rt_*` | Ответы и первая доступная пара | `event.created_at` входящего | входящее → следующее исходящее по тому же `lead_id`; среднее ограничивает интервал 480 мин; операционный показатель вне строгой финансовой сверки | все лиды | раскрытие пар event id в независимом аудите |
| `cycle_*` | Цикл сделки | `closed_at` | среднее `(closed_at-created_at)` успешных сделок | Продажи | даты карточек выборки `paid` |
| Источники: лиды / конверсия | Привлечение и качество когорты | `created_at` | `new_leads`, `cohort_won/new_leads` по источнику сделки | Продажи | когорта + поле «Источник» |
| Источники: оплачено / приход / средний чек | Денежный результат периода | `closed_at` | `paid`, `revenue`, `revenue/paid` по источнику сделки | Продажи | Успех + дата закрытия + источник |
| Воронки | Распределение активных сделок по этапам | `snapshot` | текущий статус активных сделок | Продажи / Повторные | открыть воронку сейчас |
| В работе / без задач / просрочено | Операционный контроль | `snapshot` | текущие открытые сделки и незавершённые задачи | обе воронки | списки сделок и задач сейчас |
| Застрявшие | Текущие сделки на контрольных этапах | `snapshot` | этапы «Без ответа» + «Лист ожидания» | обе воронки | фильтр этапов сейчас |
| Причины провала | Провалы за последние 60 дней | фиксированное окно `closed_at` | количество закрытых в провал по причине | обе воронки | провал + дата закрытия последние 60 дней |
| Постоянные клиенты | Контакты с успешными сделками | `snapshot`, всё доступное время | уникальные `contact_id` успешных сделок | Продажи / Повторные | успешные сделки → уникальные контакты |
| Качество CRM | Дефекты исходных карточек | `snapshot`, успешные сделки | `price=0`, нет контакта, источника, ответственного, корректного `closed_at` | Продажи / Повторные | список `lead_id` из контрольного отчёта |

## Единообразие API и UI

- `/overview`, `/table`, `/managers` используют одинаковые производные: `avg_check`, `cohort_won/new_leads`, `repeat_cohort_won/repeat_created`.
- `/sources` не смешивает деньги по `closed_at` с лидами по `created_at` в одной формуле: отдельно показывает когортную конверсию и средний чек закрытых оплат.
- `/funnels`, `/stuck`, менеджерские `open/no_task/overdue`, постоянные клиенты и качество CRM всегда помечаются «на сейчас» или «за всё время».
- План числовой метрики за неполный месяц пропорционален числу календарных дней; планы процентов и среднего чека не суммируются.
- `invoice_sum`, сообщения, диалоги, пропущенные и SLA — операционный контур. Событие счёта не хранит исторический бюджет, а коммуникации требуют дорогого полного чтения истории amoCRM.

## Ограничения источника

- `invoice_sum` использует бюджет карточки, доступный при проверке; amoCRM не хранит историческое значение бюджета непосредственно в событии смены этапа.
- У `notes` amoCRM серверный фильтр основан на `updated_at`; после получения применяется строгая граница по `created_at`. Изменённая задним числом старая заметка не попадает в период.
- Нулевая сумма успешной сделки не является ошибкой формулы: она входит в `paid`, добавляет 0 ₽ в `revenue` и снижает `avg_check`.
