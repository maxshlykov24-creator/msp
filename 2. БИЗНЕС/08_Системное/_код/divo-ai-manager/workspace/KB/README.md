# KB — база знаний DIVO Motors / Никита

База для будущего AI-менеджера 1-й линии (голосом Никиты). Собрана из живых данных, не придумана.

## Источники

- **477 звонков** (входящие, `call_in`), 05.06.2026–29.08.2026, диаризация Nexara (`telephonic`, 2 спикера) + разметка ролей по ключевым словам. Файлы: `_ЭТАЛОН/звонки/транскрипты_спикеры/*.md`.
- **11 переписок** Avito / Auto.ru, январь–июль 2026. Файл: `_ЭТАЛОН/ВСТАВЬ_СЮДА.md`.

## Качество данных — прочитать перед использованием

- Из 477 звонков около **14 (≈3%) ведёт не Никита, а коллега Эльзар** — тот же общий скрипт приёма звонков DIVO Motors («Автосалон Дива Моторс, добрый день, меня зовут Эльзар»). Разметка спикеров помечает его как «Никита», это ошибка эвристики: скрипт засчитывает роль по первому говорящему на входящем звонке.
- `ГОЛОС_НИКИТЫ.md` собран только по репликам, где продавец сам называет себя «Никита» — это чистая выборка.
- Общие для салона куски (структура звонка, адрес, часы, обработка возражений) валидны независимо от того, кто отвечал: это скрипт компании.
- Почти вся выборка — **входящие** звонки (476 из 477). Сценарий исходящего звонка живыми данными не подтверждён, уточнять у владельца отдельно.
- Телефоны в звонках маскированы (`+7***XXXX`). Фамилии клиентов из переписок в файлах ниже не воспроизводятся.

## Как считались частоты

Регистронезависимый grep по всем 477 файлам, единица счёта — файл (звонок), где тема встречается хотя бы раз. Это ориентир по теме, а не по факту возражения. Счётчики слов-связок — по репликам Никиты (6707 строк), единица счёта — вхождение.

## Что дальше (не сделано)

1. **Заполнить `workspace/IDENTITY.md`, `AGENTS.md`, `BOOTSTRAP.md`, `MODE_*.md`** под DIVO Motors. Материал в KB есть, сама сборка агента не выполнена.
2. **Дособрать голос по остальным звонкам** — база построена на грепах по всей выборке плюс ручное чтение ~15 звонков вразброс по датам и темам, не на построчном прочтении всех 477.
3. **Проверить реакцию на «дайте человека» и жалобы** — в выборке 2 звонка с явной претензией, для правила эскалации мало.
4. **Уточнить у владельца исходящий сценарий** (перезвон, догрев, невзятая трубка) — данных почти нет.
5. Когда база устоится — подключить через `KB_PATH` в `.env`, проверить на живом диалоге.
