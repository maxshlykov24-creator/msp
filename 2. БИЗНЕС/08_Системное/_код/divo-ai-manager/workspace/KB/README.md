# KB — база знаний DIVO Motors / Никита

База для будущего AI-менеджера 1-й линии (голосом Никиты). Собрана из живых данных, не придумана.

## Источники

- **477 звонков** (входящие, `call_in`), 05.06.2026–29.08.2026, диаризация Nexara (`telephonic`, 2 спикера) + разметка ролей по ключевым словам. Файлы: `_ЭТАЛОН/звонки/транскрипты_спикеры/*.md`.
- **11 переписок** Avito / Auto.ru, январь–июль 2026. Файл: `_ЭТАЛОН/ВСТАВЬ_СЮДА.md`.

## ⚠️ Качество данных — важно перед использованием

- Из 477 звонков в выборке **~14 (≈3%) ведёт не Никита, а коллега Эльзар** (тот же общий скрипт приёма звонков DIVO Motors: "Автосалон Дива Моторс, добрый день, меня зовут Эльзар"). Разметка спикеров в этих файлах помечает его как «Никита» — это ошибка эвристики (скрипт при заголовке-приветствии засчитывает роль по первому говорящему на входящем звонке), не путать с личным голосом Никиты.
- `ГОЛОС_НИКИТЫ.md` собран только по репликам, где продавец сам называет себя «Никита» — это чистая выборка.
- Общие для салона куски (структура звонка, адрес, часы, обработка возражений) валидны независимо от того, кто именно отвечал — это скрипт компании, не только Никиты.
- Почти вся выборка — **входящие** звонки (476 из 477). Исходящих (перезвон, дозвон, холодных) в данных почти нет — сценарий исходящего звонка в KB не подтверждён живыми данными, при необходимости уточнить у владельца отдельно.
- Телефоны в звонках уже маскированы (`+7***XXXX`). Фамилии клиентов из переписок в файлах ниже не воспроизводятся.

## Что дальше (не сделано, нужно для сборки агента)

1. **Заполнить `workspace/IDENTITY.md`, `AGENTS.md`, `BOOTSTRAP.md`, `MODE_LEAD_QUAL.md`** — сейчас там шаблонные `🟡`-плейсхолдеры под курс, не заполненные под DIVO Motors. Материал для этого есть в KB выше, но сама сборка не выполнена.
2. **Дособрать голос Никиты по остальным ~300 звонкам** — этот KB построен на репрезентативной выборке (грепы по всей базе + ручное чтение ~15 звонков вразброс по датам и темам), не на построчном прочтении всех 477. Для тонкой шлифовки тона можно прогнать оставшиеся файлы отдельным проходом.
3. **Проверить реакцию на «дайте человека» / жалобы на живых новых примерах** — в выборке всего 2 звонка с явной жалобой (штраф), маловато для уверенного правила эскалации.
4. **Уточнить у Никиты/владельца исходящий сценарий** (перезвон, догрев, невзятая трубка) — данных почти нет, в KB это отмечено как пробел, не выдумано.
5. Когда KB устоится — подключить через `KB_PATH` в `.env` и `tools/kb_search.sh` (grep-поиск по этим файлам), проверить на живом диалоге.
