## Исправление передачи клиента 2026-10-07

Ответ модели с обещанием звонка продолжал отправляться. Прежний прогон подменял `crm.capture` и не проверял сохранённый входящий номер с настоящей логикой передачи.

Исправление: текущий входящий номер запускает передачу независимо от истории; повтор отсекается по состоянию передачи. Намерение сохраняется в `crm.handoff_pending` до обращения в amoCRM и повторяется после сбоя или перезапуска. Привязка сделки использует ранее проверенный `note_lead_id`. Telegram-пинг записывается доставленным только после ответа API; недоставленные карточки и передачи обслуживаются раньше старых примечаний. При одном телефоне в нескольких чатах общая карточка сохраняет ссылки на все объявления.

Подтверждение номера формируется без LLM. Успешная передача объявляется только после подтверждения Telegram и завершённой записи CRM. ### Воспроизведение

```bash

PYTHONDONTWRITEBYTECODE=1 .venv/bin/python tools/rehearse.py --live-source --compare
```

Первый режим читает реальные четыре диалога и сток по SSH, обезличивает контакты, использует временную локальную историю и блокирует HTTP/CRM/отправку клиентам. Получено 32 успешные проверки, включая положительную отправку существующего отчёта, ответ сотрудника во время «печатает», безопасную обработку утечки инструкций и сохранение первого отправленного сообщения при сбое следующего. Это проверка на живых исходных данных с подменёнными внешними действиями, а не проверка доставки алерта или сообщения в бою.

`--compare` дополнительно делает платные тестовые вызовы через существующий OpenRouter на VPS. На сервер не записывает код или историю. Полученный текст прогоняется через локальный обработчик. `--only 'Вы же написали вот'` выбирает отдельный случай. Старые синтетические сценарии доступны по номерам; они не заменяют реальные кейсы.

### Сравнение моделей: диагностический прогон

По шесть одинаковых ситуаций на модель: тест-драйв, приезд в течение часа, приветствие по Monjaro без подтверждённой карточки, причина продажи, салонная продажа, запрос человека. Фактический `usage.cost`, с холодным и прогретым кэшем, без экстраполяции на месяц:

- Sonnet 5: $0.1329245; средняя задержка API 3.39 с.
- Haiku 4.5: $0.07305275; 5.94 с. Около −45% стоимости относительно Sonnet в этой выборке.
- Gemini 2.5 Flash: $0.024881; 2.58 с. Около −81% в этой выборке.

Качество: Gemini повторно спросил, по какой машине обращаются, хотя объявление задано, и обещал лишний звонок; Haiku обещал выяснить мотивы прошлого владельца и просил номер. Sonnet на вопрос о причине продажи тоже добавил номер. Поэтому вопросы о продавце после этого прогона вынесены в прямой ответ из KB, проверенный отдельной регрессией. Сравнение намеренно вызывало модели даже для этих случаев; в итоговом обработчике такие вызовы уже не нужны. В более раннем прогоне Haiku также промолчал на сообщение о приезде.

Решение: основной Sonnet и резервная цепочка не переключаются. Этих примеров недостаточно для допуска более дешёвой модели на весь поток. Экономия первого этапа достигается сокращением повторных инструкций и исключением LLM из однозначных действий. Перед заменой модели требуется проверка широкой выборки. После выката наблюдать за передачами человеку; боевую экономию считать по новому периоду работы.

Дополнительная проверка спора по скриншоту: Sonnet и Haiku вернули передачу человеку; Gemini начал отрицать договорённость, хотя изображение недоступно. Этот прогон стоил $0.1265301. Все три серии тестовых вызовов вместе стоили около $0.57.

## Исходный шаблон курса

# AI-Менеджер 1-й линии · OpenClaw workspace

> Карточка первого AI-сотрудника курса. Реализовано на **OpenClaw 2026.5+** — тот же фреймворк, что у Дениса в production (`@denis_pleada_bot`). Шаблон, на котором собираются все следующие сотрудники из М4–М8.

## Кто это

OpenClaw-агент, который через Telegram квалифицирует входящие лиды и передаёт квалифицированный лид живому менеджеру с резюме диалога. Работает 24/7 на VPS под одним gateway-процессом. Говорит голосом твоей компании из КОНТЕКСТ.md (М2). Опционально читает базу знаний компании и пишет резюме в выходную папку для систематизации.

## Что меняется vs «классический» бот на коде

| Раньше | OpenClaw |
|---|---|
| Писал Python-код бота | Пишешь markdown-конфиг, агент Cursor его собирает за тебя |
| Один процесс = один бот | Один gateway → много агентов под разные роли |
| Каждый бот свой systemd-юнит | Один systemd-юнит, в нём все агенты |
| Multi-канал = свой адаптер на канал | TG / Discord / iMessage / Slack из коробки |
| Tools захардкожены в коде | Tool registry — bash/CLI скрипты, агент сам решает что вызвать |
| Cron — отдельный systemd timer | Встроен в OpenClaw |
| Память диалога — in-memory | Persistent через memory module |

**Главное:** ты не пишешь код. Cursor пишет markdown-конфиг под твою роль из артефактов М2.

## Запуск · через два промпта Cursor

Ты не вводишь команды руками. Ты пишешь два промпта в чате Cursor.

```
1. ПРОМПТ_СБОРКИ.md → Cursor (локально)
   ↓ Cursor читает КОНТЕКСТ.md, ВОРОНКА.md, МАТРИЦА_РОЛЕЙ.md из М2
   ↓ заполняет 5 markdown-файлов workspace под твой бизнес
   = workspace готов

2. ПРОМПТ_ДЕПЛОЯ.md → Cursor (на VPS через Remote-SSH)
   ↓ ставит Node.js 20+
   ↓ npm install -g openclaw
   ↓ openclaw configure
   ↓ openclaw agents create lead-qualifier
   ↓ openclaw channels add telegram
   ↓ openclaw gateway install --systemd
   = бот работает 24/7 на твоём VPS
```

Между ними — `rsync` workspace на VPS и `nano .env` (одна правка переменных). Подробно — `_ПОДДЕРЖКА/ДЕПЛОЙ_VPS.md`.

- **% квалифицированных от входящих** — целевой 30–60% (зависит от качества трафика).
- **Время до квалификации** — 5–10 сообщений / 3–7 минут.
- **Доля «передан без ответа»** — должна снижаться (ловится в М6 ОКК).

## Сделка в amoCRM и алерты менеджерам

Когда клиент оставил номер или нужен человек (просит звонок, жалоба, тупик, маркер эскалации):

- берётся сделка, которую виджет Авито / Авто.ру уже создал в воронке «Техническое», и переводится в «Продажи», этап «Новая заявка», ответственный Никита. Новую сделку бот не создаёт;
- в примечание пишется полная переписка, машина, VIN, канал;
- клиенту при эскалации бот **молчит**;
- менеджерам в `@divoalertbot` уходит алерт сразу, затем на 5 / 10 / 15 / 30 минуте и через час, только с 10:00 до 20:00 МСК;
- цепочка гаснет, если сделку сдвинули с этапа или менеджер ответил в чате Авито.

Токен amo и токен `@divoalertbot` лежат в `.env`. Чат алертов бот запоминает сам: добавь его в группу менеджеров и напиши любое слово.
