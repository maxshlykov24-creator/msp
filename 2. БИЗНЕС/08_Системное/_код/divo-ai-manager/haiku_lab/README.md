# DIVO Haiku Lab

Отдельный тестовый Telegram-бот. Рабочий `bot/`, его правила, Telegram polling,
Avito, Auto.ru, CRM и состояние не используются этим приложением.

## Как работает

- Haiku 5.5 (`reasoning=low`) возвращает только намерения в JSON.
- Проверяемый Python-слой собирает ответ из разрешённых полей выбранной машины.
- Факты из старых ответов бота не переносятся в карточку.
- Пустое поле означает, что нужны уточнения. Отсутствие поля Long не означает короткую базу.
- Телефон, спор, запрос человека переводят тестовый диалог в паузу.
- Передача менеджеру, звонки, отправка фото/видео и CRM здесь только обозначаются.
- Это эксперимент с управляемыми ответами, а не свободная генерация текста прежним промптом.
  Тон будет более шаблонным; полноту распознавания вопросов нужно проверять.

## Использование

В личке отдельного бота: `/start`, `/cars`, `/car НОМЕР`, затем вопросы клиента.
Для старых объявлений: `/cases`, `/case НОМЕР`. Некоторые из них не имеют точного
совпадения в текущем снимке, поэтому наличие и технические данные не подтверждаются.

`/reset` начинает новый диалог по той же машине. `/resume` позволяет продолжить
после имитации передачи менеджеру. `/debug` показывает намерения, источники фактов,
неизвестные поля и стоимость. `/feedback ТЕКСТ` сохраняет замечание. `/export`
выгружает JSON с вопросами, ответами, решениями модели и замечаниями.

Бот доступен только владельцу по числовому Telegram ID. Группы и посторонние
пользователи игнорируются до запроса к модели. Телефоны маскируются при хранении.
Имена и произвольный текст тестера могут остаться в журнале: используй вымышленные данные.

## Изоляция

- Код: `haiku_lab/`; сервер: `/opt/divo-haiku-lab`.
- Процесс: отдельный `divo-haiku-lab.service`, пользователь `divo-haiku-lab`.
- Секреты: `haiku_lab/.env`, исключён из Git. Рабочий токен запрещён проверкой ID.
- История, offset, бюджет и журнал: `haiku_lab/runtime/lab.sqlite3`.
- Каталог: копия данных `catalog.json`, дата видна через `/status`.
  Автообновления из production нет. Снимок обновляется отдельно, только чтением источника.
- Никаких импортов `bot.*`, клиентских ключей Avito/Auto.ru, CRM, обработчиков вебхуков.
- Один poller на лабораторию: файловая блокировка и отдельный Telegram-токен.
- У сервиса нет доступа к `/root`, системные каталоги доступны только для чтения.
- CPU 15%, RAM до 192 MiB. Ограничения относятся только к лаборатории.
- OpenRouter пока общий по аккаунту с рабочим агентом. Локальный лимит лаборатории:
  $0.50 за UTC-день, учитывает Telegram и CLI-прогоны вместе. Каждая попытка заранее
  резервирует $0.02, неуспешная попытка оставляет резерв. Более сильная денежная изоляция
  потребует отдельного ограниченного API-ключа или аккаунта.
- Общими остаются VPS, сеть и SOCKS-прокси. Рабочий процесс не перезапускается.

## Проверки и запуск

```sh
python -m unittest haiku_lab.test_engine -v
python -m haiku_lab.rehearse --only 1 5 10 14
python -m haiku_lab.main
```

Репетиция вызывает настоящую Haiku, но не содержит Telegram-транспорта. Результаты
сохраняются в `runtime/rehearsal.jsonl`. Старые диалоги берутся из обезличенного
`fixtures.json`; он и каталог исключены из Git.

Сервис запускать только после проверки `getMe`: ID нового бота должен отличаться
от обоих рабочих ботов и совпадать с `LAB_EXPECTED_BOT_ID`. Существующий webhook
лаборатория сама не удаляет. Второй процесс с рабочим токеном запрещён.

Если отправка Telegram оборвалась после обработки входящего сообщения, оно не
повторяется автоматически (чтобы не дублировать ответы). В журнале останется
`pending` без события `delivery`, а update получит `failed`. Для повтора напиши вопрос
ещё раз. При перезапуске уже начатый update не пересчитывается.

Источники API: [Telegram Bot API](https://core.telegram.org/bots/api),
[OpenRouter Structured Outputs](https://openrouter.ai/docs/guides/features/structured-outputs).
