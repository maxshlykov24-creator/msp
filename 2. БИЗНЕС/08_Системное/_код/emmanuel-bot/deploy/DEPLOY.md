# Деплой Emmanuel Report Bot (Ubuntu + Docker)

## Важно

- Токен бота только в файле `.env` на сервере. **Канон: `@emmrov_bot` (id `8679755747`)**. Не путать с `@mshlykov_bot` — им этот контейнер уже поллился по ошибке, из‑за этого группа отвечала `chat not found`.
- Проверка после деплоя: в логах `bot @emmrov_bot id=8679755747`. Если другой username — сразу стоп.
- **MUTE (`OUTBOUND_MUTE=true`):** обычная отправка отчёта в группу выключена, мастер отчёта в личке доступен участникам группы. Сводки используют отдельный вызов `send_message_live`; расписание зависит от `JOBS_ENABLED`. Снимать MUTE только отдельным «можно в чат».
- **Сводка 00:00 в группу:** `#рвыотчёт` плюс жирные N из M. В Телеге по хэштегу виден ряд недель.
- **Администратор бота**: владелец `ADMIN_TG_USER_ID`; флаг `is_bot_admin` в таблице `users` тоже есть.
- **Зачёт отчёта:** в сообщении группы есть хэштег. Без `#` не считаем.
- **Имя в отчёте бота:** берём последний хэштег, которым человек уже подписывался в группе. Если не писал — имя из `seed/assigned_hashtags.json`. Спрашиваем «как подписывать» только если нет ни того ни другого. Леша пастор (`291663131`) вне круга отчёта, имя не спрашиваем.
- Состав группы сидируется из `seed/group_roster.json`, дальше ловим `chat_member`.

## 1. Подготовка на сервере

```bash
sudo apt update && sudo apt install -y docker.io docker-compose-plugin git
sudo mkdir -p /opt/emmanuel-bot && sudo chown "$USER:$USER" /opt/emmanuel-bot
cd /opt/emmanuel-bot
```

Скопируй каталог проекта `emmanuel-bot/` на сервер (git clone/rsync/scp).

## 2. Конфиг

```bash
cd emmanuel-bot
cp .env.example .env
mkdir -p data
nano .env
```

Заполнить:

| Переменная | Пример |
|------------|--------|
| `BOT_TOKEN` | токен `@emmrov_bot` из @BotFather |
| `GROUP_CHAT_ID` | `-1002125032114` (Копают рвы) |
| `OUTBOUND_MUTE` | `true` пока нельзя писать в чат |
| `JOBS_ENABLED` | `false` пока нельзя слать сводки по расписанию |
| `ADMIN_TG_USER_ID` | личный Telegram id владельца |

Бот должен быть **админом группы**, иначе не увидит все сообщения и вход/выход.

## 3. Запуск

```bash
docker compose build --no-cache
docker compose up -d
docker compose logs -f
```

SQLite лежит в **Docker volume** `emmanuel_report_bot_data` (см. `docker-compose.yml`). Бэкап:  
`docker run --rm -v emmanuel-report-bot_emmanuel_report_bot_data:/from -v $(pwd):/to alpine tar czf /to/emmanuel-db-backup.tgz -C /from .`

URL в `.env`: `sqlite+aiosqlite:////data/emmanuel.sqlite3` — четыре слэша, иначе путь трактуется как относительный и БД не откроется.

Личные команды владельца в личке с ботом: `/start`, `/coverage`, `/sunday`. В группу бот при MUTE не отвечает.

## Часовой пояс

Все задачи расписания: **Europe/Moscow** (`app/scheduler.py`).

Сейчас при MUTE/JOBS_ENABLED=false наружу не уходят:

- вс 17:00 — напоминание в группу;
- вс 22:00 — личка;
- пн 10:00 — dropout;
- 00:00 / 20:00 — сводка покрытия (код есть, расписание выкл).

Дедлайн «вовремя» для счётчика серии — **понедельник 00:00 МСК** после отчётного воскресенья (см. `app/time_utils.py`).


## Исправление обратной связи 02.11.2026

- Подтверждено по журналу прода: в `msg_q4` был Telegram timeout при отправке следующего вопроса. Старый `MemoryStorage` терял диалог при перезапуске.
- Шаг и черновик теперь хранятся в `dialog_states` в основном SQLite volume. `/resume`, `/start` и кнопка отчёта продолжают текущий шаг; устаревшая кнопка получает пояснение. Обработка обновлений одного пользователя последовательная.
- Неделя отчёта фиксируется при старте. Новые заметки из самого отчёта привязаны к ней; отдельный блокнот использует календарную неделю. Старые строки без привязки фильтруются по дате создания; неотправленные старые заметки доступны через архив. Исторические данные автоматически не исправляются.
- Предпросмотр, правка и сохранение используют один текст откровений. Открытие правки и её отмена больше не заменяют отдельные заметки. Правка сохраняет исходные дату подачи и признак своевременности.
- Длинные отчёты разбиваются на сообщения; HTML-символы в нуждах и откровениях безопасны. При неподтверждённой отправке в группу бот просит проверить чат, автоматического повтора нет.
- Проверка: `python scripts/test_hashtag.py`. Для прогона на копии рабочей БД: `EMMANUEL_AUDIT_DB_COPY=/secure/copy.sqlite3 python scripts/test_hashtag.py`. Все изменения выполняются на временной копии, Telegram transport заменён тестовым, реальные сообщения не отправляются.
- Обновление БД добавляет `dialog_states` и nullable `revelations.report_week_start`, существующие отчёты и заметки не переписывает. Перед установкой обязателен SQLite backup и резервная копия текущего кода. `.env` с локальной машины не переносить поверх рабочего.
- Важное ограничение перехода: незавершённый диалог, который ещё жил только в памяти старой версии, восстановить из SQLite нельзя. После первого обновления такой отчёт потребуется начать заново. Последующие черновики переживают перезапуск.


### Проверка установки 02.11.2026

- На серверном образе с копией рабочей БД пройдены 84 проверки, включая искусственный таймаут, восстановление из нового экземпляра SQLite storage, все семь правок, отмену, сохранение и длинные сообщения. Тестовый transport не отправлял сообщения людям.

В compose добавлен `extra_hosts` только для этого контейнера. Адрес переопределяется через `TELEGRAM_API_IPV4`; при новых сетевых сбоях перепроверить оба адреса.
- Рабочие настройки сохранены: `OUTBOUND_MUTE=true`, `JOBS_ENABLED=true`. Автоматическая отправка отчётов в группу не включалась.

- Резервные копии на VPS: `/opt/emmanuel-report-bot/backups/2026-11-02-audit/` (БД, код, build и checks logs); прежний образ: `emmanuel-report-bot:pre-audit-20261102`. Обновление построено поверх прежнего образа с сохранением его библиотек. Откат кода возможен без удаления добавленных таблицы и столбца.

- Финальная проверка запуска: канонический бот запущен, `Start polling` и `Run polling` подтверждены в 14:42 МСК; `restart_count=0`, SQLite integrity `ok`. Реальную публикацию отчёта в группу при проверке не выполняли.
