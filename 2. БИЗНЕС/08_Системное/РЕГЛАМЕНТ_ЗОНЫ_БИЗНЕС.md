# Регламент зоны `2. БИЗНЕС/`

> Единые правила для людей и ИИ: что создавать, куда складывать, когда нужен README. Глобальные договорённости по работе в Cursor — в [`.cursorrules`](../../.cursorrules) и [`_ПРОФИЛЬ/СТИЛЬ_РАБОТЫ.md`](../../_ПРОФИЛЬ/СТИЛЬ_РАБОТЫ.md).

---

## Модель «офисного здания»

Одна карта: метафора **не заменяет** нумерацию операционных зон (`01_`…`08_`), а объясняет, зачем нужны уровни и README. Вторая параллельная оргструктура в vault не вводится.

| Метафора | Где в `2. БИЗНЕС/` |
|----------|-----------------|
| Главный вход, распределение потока | [`_ВХОДЯЩЕЕ`](../../_ВХОДЯЩЕЕ/README.md) (корень vault) → раскладка по этажам |
| Этаж (функция компании), 8 зон | `01_` … `08_` — операционные «отделы»; [`08_Системное`](README.md) — системный слой (профиль, регламенты, скрипты, обучение) |
| Типовые отделы (соответствие) | Стратегия → `01_`; Финансы → `02_`; Продажи → `03_`; Производство → `04_`; Поддержка → `05_`; Маркетинг → `06_`; Продукт → `07_`; Системное → `08_` |
| Кабинет (подразделение, клиент, тип работ) | Подпапка на этаже **с `README.md`** (например `04_/Активные/КЛИЕНТ/`, `04_/Шаблоны_ТЗ/`) |
| Шкаф (класс документов) | Ещё один уровень **только** если в одном кабинете реально смешиваются разные классы (например отчётность: ДДС / ОПиУ) и их путают; иначе — файлы в кабинете или префиксы имён |
| Документы | Файлы в кабинете / шкафу |
| Вывески, индексация для людей и ИИ | `README` на этаже (корень зоны) и в каждом новом кабинете; периодически — ICQ (§6) |

**Правило глубины:** не создавать вложенность «на вырост». Новый уровень — если без него нельзя за несколько секунд ответить: «куда кладу этот файл?» и «кто за эту зону отвечает?».

---

## 1. Входящий поток

- Файл по работе или клиенту **без явного адреса** — сначала в [`_ВХОДЯЩЕЕ`](../../_ВХОДЯЩЕЕ/README.md) (корень vault).
- После наполнения — раскладка: список → целевая зона → перенос (вручную или с помощью ИИ по контексту).

---

## 2. Новая логическая папка (внутри `2. БИЗНЕС/`)

Под **логической** имеется в виду отдельная категория работ (новый клиент, новый тип артефактов), а не одиночный `.md` рядом с остальными в уже описанной зоне.

**Обязательно:**

1. Создать **`README.md`** в этой папке со структурой:
   - краткий тезис в первой строке после заголовка (зачем папка);
   - **О папке** — назначение;
   - **Содержимое** — что хранить (список или таблица);
   - **Как использовать** — правила пополнения и обновления;
   - **Связи** — ссылки на соседние зоны, [`ПРОФИЛЬ_ПРОЕКТА.md`](ПРОФИЛЬ_ПРОЕКТА.md), при необходимости [`_ЗНАНИЯ/КАРТА_СМЫСЛОВ.md`](_ЗНАНИЯ/КАРТА_СМЫСЛОВ.md).

2. Добавить папку в таблицу «Содержимое» в [`../README.md`](../README.md), если это **новая верхнеуровневая** зона (`01_`…`08_`, при необходимости `3. АГЕНТЫ/`); для вложенных — достаточно README и ссылки из родительского README.

Расширенный шаблон описания папки для ИИ: [`Обучение_MAC/СКРИПТ_README.md`](Обучение_MAC/СКРИПТ_README.md).

## 3. Проекты внедрения (клиенты)

- Действовать по [`../04_Производство/Активные/README.md`](../04_Производство/Активные/README.md): отдельная подпапка, **`README.md`** с сутью, статусом и следующим шагом, при необходимости — ТЗ, схемы, заметки.

---

## 4. Исключения (README не обязателен отдельно)

- Одноразовый черновик или один файл внутри уже описанной папки — без новой подпапки и без отдельного README на каждый файл.
- Технические каталоги без смысловой нагрузки (например кэш скриптов) — по усмотрению; если ИИ должен их понимать, один README на каталог всё же лучше.

---

## 5. Контекст для ИИ

- Типовой набор: `@2. БИЗНЕС` или конкретная папка + [`ПРОФИЛЬ_ПРОЕКТА.md`](ПРОФИЛЬ_ПРОЕКТА.md) (контекст **компании**).
- Личные договорённости с ассистентом, стиль диалога и границы объёма — в [`_ПРОФИЛЬ/СТИЛЬ_РАБОТЫ.md`](../../_ПРОФИЛЬ/СТИЛЬ_РАБОТЫ.md); не смешивать с корпоративными README.
- При смене ниши, стека или модели монетизации **компании** — обновить профиль и при необходимости соседние README.

## 6. Контроль качества (ICQ)

Раз в 4–8 недель или после крупного пополнения зоны — прогон по [`Обучение_MAC/ПРОМПТ_ПРОВЕРКИ_ДЗ.md`](Обучение_MAC/ПРОМПТ_ПРОВЕРКИ_ДЗ.md) с контекстом `2. БИЗНЕС/` (цель ≥ 80%). Подробнее в [`README.md`](README.md) раздел «Контроль качества контекста».

---

## 7. Артефакты ИИ и папки `_ai/`

- В операционных зонах (`01_`–`07_`) используются подпапки **`_ai/`** — черновики, отчёты и сводки, сгенерированные ИИ по задачам этой зоны. Имена файлов: `YYYY-MM-DD_Тип_описание.md`.
- Единая схема конфигов корпоративных ИИ-агентов, межагентный обмен и продуктовые шаблоны — **по материалам курса**; самодельную параллельную структуру не вводить без явного решения владельца.
- Передача контекста между зонами — через `_ВХОДЯЩЕЕ/`, README зон и согласованные регламенты; отдельной «шины» до появления согласованной схемы нет.
- ИИ-команда живёт в [`3. АГЕНТЫ/`](../../3. АГЕНТЫ/README.md) в корне vault; данные бизнес-агентов — в `2. БИЗНЕС/агенты/`.

---

## 8. Запрещённые legacy-пути (после миграции 2026-07)

Канон зоны — только `2. БИЗНЕС/` с зонами `01_`…`08_`. **Не создавать** и не ссылаться в новых файлах на:

| Устаревшее | Канон |
|------------|-------|
| `Бизнес/` (без префикса `2.`) | `2. БИЗНЕС/` |
| `04_Производство_внедрений/` | `04_Производство/` |
| `99_Системное/` | `08_Системное/` |
| `агенты/` (корень vault) | `3. АГЕНТЫ/` |

Если папки снова появились на диске — это артефакт незавершённой миграции или устаревшего launchd; `vault-sync-auto.sh` удаляет их при синхронизации. После смены путей vault — переустановить launchd: `bash 2. БИЗНЕС/08_Системное/Скрипты_vault/git/install-launchagents.sh`.
