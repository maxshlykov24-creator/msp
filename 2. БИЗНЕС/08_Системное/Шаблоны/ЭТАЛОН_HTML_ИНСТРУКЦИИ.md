## Пол, не потолок

```
Это не «идеал, который нельзя трогать».
Это минимальный уровень качества, с которого мы СТАРТУЕМ каждую новую инструкцию.

Каждый следующий проект:
  → копируем подход и структуру эталона;
  → улучшаем, если контекст требует (другая система, другая роль, видео, интерактив);
  → после удачного апгрейда — дописываем сюда «что изменилось» (раздел «Эволюция» внизу).

Запрещённый паттерн: «у нас уже есть эталон, просто заменим названия» без сверки с реальным процессом клиента.
```

**Когда поднимать планку:** новый тип UI (мобильное приложение), другой стек визуала, запрос клиента на видео/GIF, многоязычность — не обязательно в первой версии, но фиксируем в проекте как следующий шаг.

## Принцип содержания

```
Не протокол встречи → сценарии «что нажать и в каком порядке».
Не ТЗ для разработчика → язык роли, без API и webhook.
Не «на созвоне договорились» → только актуальные названия таблиц, столбцов, статусов.
Не скриншоты прод-системы → CSS-макеты интерфейса (без ПДн и без устаревания при смене темы МС).
```

**Голос:** на «ты» к исполнителю (склад/линия), если так принято у клиента; иначе «вы». MS Product в шапке — автор («мы сделали систему»), не лектор.  
**Тон клиента:** палитра и название компании в nav; структура и плотность — MS Product.

**Источники текста (порядок):**
1. Транскрипт обучающего созвона + TO-BE / карта процесса  
2. ТЗ (только поля, статусы, названия сущностей)  
3. Регламент роли — сокращённый чеклист со ссылкой на HTML

## Структура HTML (эталон Rusbrend — 9 блоков)

| № | Раздел | Задача |
|---|--------|--------|
| 0 | **Как устроена система** | Карта «таблица ↔ МойСклад ↔ роли»; без технических деталей |
| 1 | **Настройка один раз** | Стартовый экран, склад, закладки фильтров |
| 2–N | **Сценарии по одному на экран** | Каждый = повторяемая операция (отгрузка, массовое назначение, приёмка…) |
| … | **Контроль статусов** | Что значит каждый статус, что делать при залипании |
| … | **Типовые проблемы** | errors-лист, расхождения, к кому идти |
| финал | **Контакты** | MS Product + контакт у клиента |

**На каждый сценарий:**
1. Один абзац «зачем»  
2. Блок `.steps` — нумерованные шаги  
3. Один или два `.ui-panel` — CSS-макет (таблица / форма МС / список отгрузок)  
4. `.callout` — tip / warn только там, где ошибка дорого стоит

## Визуал (CSS-паттерны)

Смотреть реализацию в эталон-файле. Кратко:

| Элемент | Назначение |
|---------|------------|
| `:root` CSS-переменные | Палитра клиента + семантика статусов (`--c-shipped`, `--bg-pick`…) |
| `nav` sticky | Оглавление по якорям `#s0`…`#sN` |
| `.nav-brand` | **Обязательный формат шапки** — см. § «Шапка nav-brand» ниже; в финале — data URI |
| `.ui-panel` + `.ui-titlebar` | «Окно» системы без скриншота |
| `.steps` / `.step-num` | Пошаговый сценарий — **основной** носитель акцентов |
| `.callout-tip` / `.callout-warn` | Редко; не дублировать текст шагов |
| `.status-pill` | Статусы документов в цветах процесса |
| `@media print` | Печать в PDF: nav скрыт, разрывы страниц у секций |

### Чего избегать

- Скриншоты реального МойСклад / Google Sheets с ПДн  
- Оранжевые «подсказки поверх UI» (`::after`, overlapping hints) — ломают вёрстку  
- Жаргон: webhook, meta, href, idempotency  
- Фразы «как на созвоне», «потом доработаем»  
- Чёрный квадрат под логотипом MS — **запрещено**; только [`logo-ms-transparent.png`](../БРЕНД/logo-ms-transparent.png)  
- Лого клиента на тёмном/цветном фоне без прозрачности — обработать под светлый nav (PNG с alpha)

## Шапка `.nav-brand` (обязательный формат)

**Единый стандарт для всех HTML-инструкций.** Шаблон: [`ШАБЛОН_NAV_BRAND.html`](ШАБЛОН_NAV_BRAND.html).  
Образцы: [`LicenseBridge …/Подключение_WhatsApp_Kommo.html`](../../04_Производство/Активные/LicenseBridge_USA/инструкция/Подключение_WhatsApp_Kommo.html), [`Береза …/Серёжа_МойСклад.html`](../../04_Производство/Активные/Береза_Групп/05_Материалы/инструкция/Серёжа_МойСклад.html).

**Порядок:** MS (transparent) → «MS Product» → divider → лого клиента → заголовок инструкции.

**Сборка:** `logo-ms-transparent.png` из `08_Системное/БРЕНД/` + лого клиента в `assets/` → `embed_instruction_logos.py` → проверка без чёрных квадратов.

### Логотипы: только inline (обязательно)

**Проблема:** `src="assets/logo.png"` ломается при открытии из другой папки, в превью IDE, если клиенту отправили только `.html`.

**Правило:** в **финальном** HTML все логотипы — **`data:image/png;base64,…`** (или `image/jpeg` по факту файла). Папка `assets/` — исходники для правок.

**Передача через Telegram (один файл):**
- Клиент скачивает `.html` и открывает в браузере телефона — **без интернета**, без папки `assets/`.
- **Запрещено** в финале: `@import url(https://…)`, любые `src="assets/…"`, внешние CSS/JS.
- Шрифты — **системный стек** (`-apple-system`, `Segoe UI`), не Google Fonts.
- Лого MS в финале: **`logo-ms-transparent.png`** — единственный допустимый вариант.
- Перед отправкой: прогнать скрипт → открыть файл на телефоне (или «Поделиться → Safari/Chrome») → лого и вёрстка на месте.

**Перед передачей клиенту:**
```bash
python3 08_Системное/Шаблоны/embed_instruction_logos.py путь/к/инструкция/*.html
```
Скрипт: [`embed_instruction_logos.py`](embed_instruction_logos.py).

Workflow: PNG в `assets/` → HTML с `src="assets/…"` → **прогнать скрипт** → открыть HTML и убедиться, что лого видны без папки `assets`.
