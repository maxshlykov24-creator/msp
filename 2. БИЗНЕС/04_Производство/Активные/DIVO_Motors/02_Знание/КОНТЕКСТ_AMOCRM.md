## Срез данных (прототип, без ПДн клиентов)
Реальные агрегаты по дням: `../02_Знание/агрегаты_по_дням.json` → зашиты в `дашборд/DIVO_дашборд_прототип_.html` (объект `DAILY`). Фильтр периода считает клиентски. Воронка «Продажи», только Евгений + Никита.

**Метрики по этапам:** `stage` — текущий статус **всех** сделок периода (включая «Успех» и «Провал»), % от входящего трафика. Не только «в работе».

**Трейд-ин:**
- `tradein` — обращения с «Авто в обмен = Есть» (интерес)
- `tradein_won` — «Успех» + «Авто в обмен = Есть» (успешный приём трейд-ин)

Последнее обновление среза: **2026-07-16**. Для прода — бэкенд по аналогии с `dkacademy-analytics` (collector → БД → API → фронт), токен не в браузере.

## Инсайты, найденные при анализе (реальные, не выдуманные)
- ~90% активных (незакрытых) сделок «зависают» на этапе **«Контакт установлен»** — узкое горлышко воронки.
- 70–80% провалов зафиксированы с причиной **«Другое»** — реальная причина не указывается. Нужен регламент для менеджеров по обязательному заполнению причины провала.
- Поле «Визит состоялся» практически не заполняется — метрику «встречи в салоне» из скриншота-таблицы напрямую из CRM сейчас получить нельзя, только через сам статус воронки.
- Поле цены (`price`) заполнено у 2 из ~70 сделок в статусе «Успех» за квартал — средний чек/выручку показывать нельзя, пока менеджеры не начнут заполнять цену на этапе закрытия.
