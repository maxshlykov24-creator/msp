# Проверка цифр DIVO Motors — дашборд vs amoCRM

## Метод

Скрипт напрямую запрашивал amoCRM API (`/api/v4/leads`, `/api/v4/events`) внутри
серверного `api`-контейнера (тот же токен, что использует collector) и сравнивал
результат с тем, что реально отдаёт `divo-analytics` из `Snapshot.payload["days"]`
(то, что видит `/api/daily`). Это не сверка «сам с собой»: агрегаты в
`Snapshot` строятся из `LeadSnapshot`/`StageReached` в БД, а прямые запросы идут
в amoCRM, минуя нашу БД.

Фиксированный период: **1–30 июня 2026 (МСК)**, воронка «Продажи»
(`pipeline_id=10372290`), только 3 менеджера отдела (`eugene`, `nikita`, `elzar`).

## Определения (как считаем)

| Метрика | Дата-фильтр | Источник |
|---|---|---|
| `traffic`, `src{}`, `tradein_yes`, `mgr.traffic` | `created_at` в периоде | текущее состояние сделки |
| `cohort_won` / `cohort_lost` / `active` / `agreed` | `created_at` в периоде | текущий `status_id` / checkbox `2027799` |
| `won` / `lost` / `cash` / `invoice` / `tradein_won` / `loss{}` / `mgr.won` / `mgr.lost` | `closed_at` в периоде | закрытые сделки (статус 142/143) |
| `cycle_sum` / `cycle_n` | `closed_at` в периоде | `closed_at − created_at`, дни |
| `stage{}` | `created_at` в периоде (cohort) | `StageReached` (историческое достижение статуса) ∪ текущий статус |

Важно: `won/lost` по `closed_at` **не делится** на `traffic` по `created_at` —
это разные выборки (сделка может закрыться не в месяц создания). Конверсия
считается только как `cohort_won / traffic` внутри одной когорты.

## Историческая воронка (stage{}) — точечная сверка

Полная пересборка `stage{}` использует таблицу `StageReached`, которую наполняет
collector из `lead_status_changed` событий. Чтобы проверить её независимо от
собственной БД, для 9 сделок из когорты (3 «Успех», 3 «Провал», 3 активные)
события `lead_status_changed` были запрошены заново напрямую из amoCRM и
сравнены с тем, что хранится в `StageReached`:

| lead_id | Путь по amoCRM (события) | Путь в БД (`StageReached`) | Совпадение |
|---|---|---|:---:|
| 42531411 | Контакт установлен → Визит запланирован → Визит состоялся → Покупка согласована → Успех | тот же | ✅ |
| 42122173 | тот же полный путь | тот же | ✅ |
| 42326297 | тот же полный путь | тот же | ✅ |
| 41838339 | Провал, Спам | тот же | ✅ |
| 41924951 | Провал, Спам | тот же | ✅ |
| 42000099 | Провал, Спам | тот же | ✅ |
| 42902401 | Контакт установлен (текущий, активная) | тот же | ✅ |
| 42741573 | Контакт установлен (текущий, активная) | тот же | ✅ |
| 42922137 | Контакт установлен (текущий, активная) | тот же | ✅ |

9/9 совпадений — расхождений не найдено. Восстановление истории **не**
опирается на допущение «дошёл дальше — значит прошёл все промежуточные этапы»:
каждый статус в `StageReached` подтверждён отдельным событием
`lead_status_changed` из amoCRM (см. `КОНТЕКСТ.md` предзапускового чек-листа в
плане интеграции).

## Инфраструктура — что уже проверено

- `https://divomotors-analytics.ru` — HTTPS (Let's Encrypt, автопродление через `certbot.timer`), HTTP редиректит на HTTPS.
- Firewall (`ufw`): открыты только `22/80/443`, порт API `19100` снаружи недоступен (проверено таймаутом).
- Rate limit на `/login` (5 запросов/мин + burst) — подтверждён (10 быстрых запросов → `503` после исчерпания лимита).
- Логин/кука/`/api/daily`/`/api/meta` без куки → `401`, с куки → `200`.
- Ежедневный `pg_dump` поставлен в cron (`03:00`, хранение 14 копий) и **проверен восстановлением** (`deploy/restore.sh`) — БД пересоздана из бэкапа, api/worker подняты, `/health` снова `ok` без потери данных.
- SSH: вход только по ключу, `PasswordAuthentication no`, пароль root ротирован (новый не публикуется, доступ — только по ключу).

## После приёмки (осталось сделать вручную)

Опубликованный в переписке **токен amoCRM** нужно ротировать через интерфейс
amoCRM (Настройки → Интеграции → приватная интеграция → выпустить новый
долгосрочный токен) — программной ротации через API нет, и делать это без
подтверждения владельца рискованно (может порвать текущий сбор данных).
После выпуска нового токена — заменить `AMO_ACCESS_TOKEN` в серверном `../06_Доступы/.env`
(`/root/divo-analytics/.env`, `chmod 600`) и перезапустить `api`+`worker`
(`docker compose up -d --force-recreate api worker`).

Пароль дашборда для владельца сгенерирован отдельно и передан в чате (не
хранится в git, только bcrypt-хэш в серверном `../06_Доступы/.env`).
