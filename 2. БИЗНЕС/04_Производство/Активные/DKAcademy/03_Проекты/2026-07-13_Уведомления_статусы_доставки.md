# DKAcademy: уведомления по статусам доставки (2026-07-13)

## Поведение

После webhook LiveInform бот шлёт шаблон в Telegram/MAX **только** по смысловым статусам ниже. По остальным сменам (в т.ч. «вручен», «возврат», неизвестный текст) — тишина.

Дедуп: один раз на пару «трек + смысловой статус». Нативная связка LI→amoCRM поле статуса обновляет, в мессенджер не пишет.

**«Заказ собран»** в эту версию не входит (не статус LiveInform).

## Whitelist → шаблон

| Смысл | semantic_id |
|-------|-------------|
| Принят в городе отправителя / в отделении | `accepted_origin` |
| Сортировка | `sorting` |
| Отправлен в город получателя | `to_dest_city` |
| Готов к выдаче / прибыло в место вручения | `ready_pickup` |
| У курьера | `with_courier` |
| Вручен | `delivered` |
| Не вручен / неудачная попытка | `delivery_failed` |
| Истекает срок хранения | `storage_expiring` |

Код LiveInform `1` (в месте вручения) → всегда `ready_pickup` (текст про вскрытие под камерами).  
Код LiveInform `2` (вручен) → `delivered`.

Формулировки СДЭК/Почты мапятся через алиасы в коде (`delivery_semantics.py`), клиент видит только наши шаблоны.
