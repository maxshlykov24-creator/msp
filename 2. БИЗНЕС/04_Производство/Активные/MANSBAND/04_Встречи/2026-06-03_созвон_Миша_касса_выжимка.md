## 2. Методология разработки (главное решение)

Миша **переопределил** план «сначала всё сделать → потом правки»:

```
НЕ:  сделать 16 видов → одна сверка → внедрение
ДА:  пачка 1–3 вида → сверка по ТЗ на созвоне → пачка 2–3 → … → когда 3 пачки чистые → остальное сразу
```

**Почему:** без боевого прогона на 1–2 видах накопятся ошибки во всех 16; переделывать дороже.

**Порядок работы на созвонах:**

1. Открыть ТЗ + прототип конкретного вида
2. Прогнать сценарий «как консультант в зале» — поля сверху вниз, без прыжков
3. Сверить техничку (оплаты, связки, этапы)
4. Следующая пачка

**Меню слева** — **не трогать** до прохождения всего функционала. Сначала ядро форм, потом навигация.

**Миша перед каждым созвоном** — перечитать своё ТЗ (20–30 мин). **Макс** — знать конструктор ТЗ от А до Я до кодинга.

## 3. Техническая платформа

| Тема | Решение |
|------|---------|
| Где живёт | **Сайт на российском сервере**, не Telegram-бот |
| Доступ | Логин/пароль у каждого; **неограниченное число пользователей** |
| Подписки | **Нет** ежемесячной платы за кассу — только хостинг сервера |
| Мобильное | Сначала **веб + PWA** («на экран Домой» в Safari). App Store — позже |
| Интернет | Работа с интернетом; офлайн — не обсуждали |
| Магазин | При открытии смены консультант выбирает шоурум |
| amoCRM | Остаётся «мозгом»; касса — UI. Сделка = заявка |
| Успех | При проведении: заказ в amoCRM + МойСклад, остатки, входящие платежи (по способам) |
| Без полной оплаты | **Успех запрещён** — неоплаченное = отложка, не продажа |

## 4. Эдвин — требования (в scope 160k)

**Роль:** контроль **денежных и товарных потоков**, не маркетинговая аналитика.

**Видит (упрощённый список заявок):**

- Каждую **продажу** (не только агрегаты) — как в старом WhatsApp: что купили, за сколько, способ оплаты, сдача
- Максимум: имя + телефон (опционально, «чтобы спокойнее»)
- **Не видит:** источник, цель покупки, сливы «люди пришли», бесплатные отложки
- **Видит:** продажи, оплаченные отложки, сертификаты проданные, аренды

**Действия:** очередь переводов (сдача/возврат) → «Отправил» → статус выдано. Утром авто-выдача (как в прототипе).

**Формат:** укороченная версия экрана заявок, не отдельная логика. Возможен вход только в раздел «Очередь Эдвина».

## 7. Детали по «Продаже» (прогон на созвоне)

### Поля и порядок

| Элемент | Решение |
|---------|---------|
| № заявки | Виден с начала; документ создаётся при открытии формы; при вводе телефона — **схлопывание** с существующей |
| Дата создания | Показывать в форме |
| Тип + Вид | Оба: тип = оффлайн/онлайн/дефект/возврат; вид = продажа/аренда/… — в карточке заявки и для статистики |
| Консультант | Авто из сессии |
| Направивший консультант | Поле для сплита; при сливе→продажа подтягивается имя/телефон; **имя закрывающего важнее** |
| Телефон → Имя | **Телефон левее**, имя правее (подстановка по номеру) |
| Товары | Сканер + **поиск по артикулу** без пистолета (партии не уникальны до Честного ЗНАКа) |
| Сумма к оплате | Итог крупно — продиктовать клиенту |
| Скидка | На **весь чек** (₽ или %) — **добавить в прототип**; на товар отдельно + подарок 100% |
| Доставка | **Оставить** в оффлайн-продаже (бабочки, Яндекс-курьер, 0 если клиент сам) |
| Оплата | Мульти: нал, карты, сертификат; кнопка **«остаток»**; сертификат — баланс в реестре, не дублировать в форме |
| Сертификат = 0 | Авто «использован» / успех по правилам сертификата |
| Чаевые | Поле в блоке оплаты: из сдачи указать сумму чаевых → **в очередь Эдвина** |
| Частично не оплатил | В продаже **нельзя** → только отложка |
| Сдача | Статус: Эдвин отправил / нет; очередь Эдвина — основное место (дубль в заявке — под вопросом) |
| Канал, цель, комментарий | **Внизу, после оплаты** (реальный порядок работы консультанта) |
| Комментарий | **Обязательное поле** — добавить |

### Слив ↔ Продажа

- Слив **не превращается** в другую форму — в продаже **сворачиваемый блок** «был слив» (+, дата, кто слил)
- Слив с телефоном + встреча → этап «Встреча назначена»; при продаже в другом магазине — **схлопывание**, учёт конверсии
- Телефон в сливе **не обязателен**
- Дата встречи в сливе — **нужна** (аналитика «через сколько возвращаются»)

### Пачка 1 — статус видов

| Вид | Статус по созвону |
|-----|-------------------|
| **Продажа** | Разобрана детально (см. выше) — это эталон |
| **Сертификат пластик** | Прототип почти готов; добавить комментарий, сценарий «возврат остатка деньгами» реализуется в Продаже |
| **Продажа компании** | **На созвоне детально НЕ разбиралась.** В пачку 1 идёт как **минимальная форма по оригинальному ТЗ** — поля «черновик к согласованию», финально утверждаем на субботнем созвоне. Не выдавать за договорённость |
