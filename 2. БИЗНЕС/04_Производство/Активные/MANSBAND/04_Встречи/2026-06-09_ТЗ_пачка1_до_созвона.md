Три формы полностью по ТЗ + общие правки конструктора, чтобы на созвоне прогнать «как консультант в зале» (поля сверху вниз, без прыжков):

## Сценарий показа на созвоне (3 формы, ~10 мин)

1. **Продажа**: открыть → видно №+дата → ввести телефон (подстановка) → товары → скидка на чек → оплата с кнопкой «остаток» → попытка Успеха без оплаты (блок) → доплата → чаевые → раскрыть «был слив» → комментарий → Провести.
2. **Сертификат пластик**: гость → номинал → № → оплата → комментарий → сохранить (этап «продан»).
3. **Продажа компании**: показать черновик-форму (компания, счёт, «оплачен/выдано») → проговорить, какие поля финалим.

## Зафиксировано на будущее

> Ниже — всё, что обсуждалось и зафиксировано как следующие шаги после пачки 1. Не входит в текущую реализацию — реализуется по согласованию на созвоне.

| # | Пункт | Детали |
|---|-------|--------|
| Б1 | **Тот же консультант заносит продажу по своей сделке** | Если в amoCRM уже есть сделка с этим клиентом, ведённая консультантом — он же должен быть автором новой записи. Логика матчинга: по номеру телефона → приоритет проверенного консультанта. |
| Б2 | **Приоритет имени при объединении сделок** | Если консультант скорректировал имя клиента вручную — именно это имя имеет приоритет при слиянии с дублирующей сделкой из amoCRM. |
| Б3 | **Память формы при переходах между разделами** | При переходе «новая заявка → список заявок → обратно» — сохранять черновик формы в `localStorage`. Не вводить всё заново. |
| Б4 | **Расширенная панель информации по сливу** | Кнопка «Обновить» уже есть (базовая). На будущее: показывать полную лид-историю слива/обещания — все сделки по этому телефону, список этапов, комментарии. |
| Б5 | **Редактируемая дата оплаты по каждому платежу** | Поле «дата оплаты» у каждого платёжного блока — сейчас авто-заполняется. На будущее: ручная правка (например, оплата была вчера, а заносят сегодня). |
| Б6 | **Триггер «Успех» сертификата при фактическом использовании** | Сейчас сертификат уходит в «Успех» при продаже. По бизнес-логике «Успех» должен срабатывать, когда остаток = 0 (сертификатом воспользовались). Требует связи с формой «Продажа» — при оплате сертификатом автоматически снижать баланс и переводить в «Успех». |
| Б7 | **ё/е нормализация имён при объединении** | При поиске клиента и слиянии дублей — нормализовать «ё» → «е» в именах и фамилиях клиентов. |
| Б8 | **Кнопка «Обновить» в сливе — расширенный режим** | Текущая реализация: ищет одну заявку sliv/promise по телефону. Расширение: показывать весь список совпадений, выбирать нужный, видеть дату встречи и имя консультанта. |
| Б9 | **Роли пользователей и авторизация** | Каждый консультант входит под своим логином/паролем. Активный консультант подставляется автоматически. Смена консультанта — только Миша или РОП. |
| Б10 | **Маркировка (DataMatrix)** | В будущем — сканирование DataMatrix для маркированного товара. Архитектурно зарезервировать кнопку «Сканировать» (уже есть в ProductPicker — заглушка). |
| Б11 | **Формат телефона для передачи в API** | В UI — маска `+7 (XXX) XXX-XX-XX`. В amoCRM/бэкенд передавать без скобок и дефисов: `+7XXXXXXXXXX`. Функция `phoneToApi()` в `format.ts` уже готова. |
| Б12 | **Авто-подстановка всех данных при вводе телефона** | При вводе 10 цифр — авто-запрос в amoCRM: подставить имя клиента + консультанта, который ведёт сделку + направившего (если есть открытый слив/обещание) + дату встречи. Сейчас: имя подставляется из мок при вводе; направивший — кнопкой «Обновить» в блоке слива. В проде: один вызов API по телефону → всё заполняется автоматически. |
