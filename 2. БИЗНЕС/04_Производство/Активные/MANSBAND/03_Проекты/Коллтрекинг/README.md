# Коллтрекинг вместо Roistat

Свой коллтрекинг для MANSBAND на телефонии Телфин и сервере моста чата. Цель: отказаться от Roistat, сохранив подмену номера на сайте и метки в сделках amoCRM.

**Статус:** по сообщению владельца 21.10 Roistat не оплачен и не работает несколько дней. Куплены и подключены 10 номеров, звонки доходят до менеджера. Основной номер принадлежит клиенту и работает, повторная проверка владельцем отменена. Наш боевой режим пока выключен; контроль меток звонка, чата и квиза не завершён.
**Презентация:** [`presentation/Предложение_MANSBAND_коллтрекинг.html`](presentation/Предложение_MANSBAND_коллтрекинг.html), один файл, в Telegram уходит как есть.
**Скрипт на сайт:** [`ИНСТРУКЦИЯ_СКРИПТ.md`](ИНСТРУКЦИЯ_СКРИПТ.md).

## ТЗ: каждый звонок с сайта и рекламных каналов попадает в сделку amoCRM с источником и метками без Roistat

**Кому:** Максим, код рядом с `talkme-amojo-bridge/` на VPS `mansband-bridge`.
**Контекст:** Roistat перевёл аккаунт на Базовый 250 из-за трафика. Из тарифа используется подмена номера и запись меток. Мост чата уже находит сделку по телефону и пишет поля `tracking_data` по хуку `add_lead`.
**Факты владельца 2026-10-12:** сделку по звонку создаёт интеграция Телфин, не Roistat. Источник в Метрику передаёт amoCRM. Таблицу статистики в проект не включаем.
**Номера:** номера Roistat стоят только в подмене на сайте. 2ГИС, Авито и другие каналы уже на номерах Телфин, их не меняем.
**Скрытая зависимость:** мост чата и квиз берут первым приоритетом `roistatVisitId` (94% бесед против 44% у `utm_source`, `03_Проекты/ТЗ_UTM_из_чата_в_amoCRM.md`). После снятия скрипта Roistat этот идентификатор пропадёт. Наш скрипт выдаёт свой идентификатор визита, его получают Talk-me и квиз, мост по нему достаёт метки.
**Вход:** кабинет и API Телфин, поля amoCRM `tracking_data` (id в `03_Проекты/ТЗ_UTM_из_чата_в_amoCRM.md`), Метрика для нагрузки, сайт через Сергея.
**Выход:** 15 номеров Телфин для сайта, скрипт подмены на сайте, сервис сопоставления звонка с визитом, метки в сделке для звонка, чата и квиза, ежедневная сверка с сигналом в Telegram, инструкция.

**Definition of Done:**

1. Звонок на номер Телфин канала (2ГИС, Авито и другие) получает источник этого канала в сделке.
2. Посетитель с UTM видит номер из пула, номер держится весь визит, включая переходы по страницам.
3. Контрольный звонок с каждого источника: utm_source, medium, campaign, content, term, yclid и страница входа в сделке совпадают со ссылкой.
4. Чат и квиз после снятия Roistat пишут метки в сделку через наш идентификатор визита.
5. Отладка на живых звонках: каждый звонок с сайта без источника разобран, причина закрыта или объяснена. Расхождения приходят в Telegram.
6. Номера Roistat сняты с сайта.

**Правила на краях, решить в неделю 1:** повторный звонок клиента с открытой сделкой, номер по умолчанию при исчерпании пула и без JS, подмена для органики и прямых заходов.

**Ограничения:** Телфин и рабочее место менеджеров не меняем. Поля, которые сейчас пишет Roistat, заполняем теми же кодами. Кабинет расходов и ROI не делаем.
**Срок:** 3 недели со следующего дня после стартовой оплаты. Весь проект за одну неделю: доплата 30 000 ₽ по факту сдачи.

## Контроль нагрузки и ошибок: согласовано 21.10.2026

Владелец подтвердил применение в этом чате. Начальный пул 10 номеров; докупка по фактической нагрузке. Основной номер сайта используется как резерв вне пула. Реальный список пула хранится только в настройках сервера, его ещё нужно получить.

- Занятый номер не отбираем. При исчерпании показываем основной. Звонок на общий основной и резервный номер не получает выдуманный источник «органика»; существующие поля CRM не меняем.
- Контроль раз в минуту: загрузка пула, недавние отказы выдачи, ошибки API, неразобранные события Телфин, ошибки CRM, звонки без сделки и источника.
- Стартовый порог предупреждения: 80% занятых номеров. Нехватка фиксируется при выдаче, сообщение приходит ближайшим циклом контроля. Это выбранный рабочий порог, достаточность пула ещё не доказана.
- Повтор записи в CRM сохраняется в БД до запроса. До 6 попыток, фоновый повтор каждые 5 минут; после исчерпания попыток нужна проверка ошибки. Повторно читаем сделку и дописываем только пустые поля.
- Telegram: первый сигнал, повтор не чаще раза в 30 минут, восстановление. Неудачная отправка не помечается доставленной, повторяется следующим циклом. Ошибки не исчезают из контроля только из-за смены суток.
- Сводка в первый день ежечасно до 22:00, далее в 09:00 за предыдущий день: визиты, увиденные скриптом, источники, пик занятого пула и активных рекламных визитов, число ответов с резервом, звонки и незакрытые случаи. Пульс также считается ответом с резервом, это не число уникальных посетителей.
- Общая посещаемость остаётся в Метрике: наш скрипт видит только обратившиеся к нему визиты. В тестовом режиме его визиты также входят в счётчики.
- `GET https://ai-msp.ru/ct/health`: БД и свежесть фоновой сверки. Для обнаружения падения всего сервера этот адрес должен проверять независимый наблюдатель. Сам наблюдатель пока не подключён.

Проверка локально: 32 теста прошли, включая пул из 10 номеров с резервом на 11-м визите, параллельную выдачу, повтор CRM после нового подключения к БД, повтор Telegram, счётчик ошибок API и протухшую фоновую сверку. Это не заменяет реальные контрольные звонки.

Осталось до приёмки: список 10 номеров в env; бот и адресат Telegram; реальное событие Телфин и его разбор; скрипт через Сергея; контрольные сделки звонка, чата и квиза; независимый монитор доступности. Неполученное событие Телфин нельзя обнаружить только из нашей БД: сверка с журналом провайдера пока не реализована.
