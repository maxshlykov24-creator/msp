# Формула задач кассы MANSBAND

> Дата: 2026-08-06 · после созвона 05.08 (п.7–9) · обновлено 27.08 (правки созвона 20.08)
> Источник правды в коде: `kassa/packages/shared/src/taskFlow.ts` (реестр) + `kassa/apps/api/src/services/taskFlow.ts` (движок).

Одна задача = четыре ответа: **откуда появилась → кому прилетела → что делает человек внутри → куда переходит заявка после выполнения.**

Этап заявки после выполнения задачи меняется **автоматически**: консультант нажимает одну кнопку, этап уезжает в amoCRM сам, в истории заявки видно «Этап изменён: … · Причина: задача «…» выполнена».

---

## Таблица

| Задача | Откуда появляется | Кому прилетает | Что внутри | Куда переходит после выполнения |
|---|---|---|---|---|
| **Сделать перемещение** | Заявка (отложка / обещание / продажа / компания / аренда / пластик) встала на этап «Ждет товар» | Консультанту магазина заявки — оформить; после выбора источника: **логисту**, если источник «Центральный склад», иначе консультанту магазина-источника | Позиции заявки, откуда (справочник расположений), куда (Новокузнецкая / Бауманская). Кнопка «Отправлено» ставит товар «В пути» | Рождается задача **«Принять товар»** у магазина-получателя |
| **Принять товар** | Отправитель нажал «Отправлено» | Консультанту магазина-получателя | Подтверждение получения — создаёт документ перемещения в МойСклад | Этап **«Товар в магазине»** + задача «Отложить» |
| **Отложить** | Заявка встала на «Товар в магазине» (любой вид) | Консультанту магазина | Отложить комплект на клиента, указать срок отложки | Этап **«Товар отложен»** |
| **Связаться по отложке** | Срок отложки («Резерв до») вышел — сканер раз в 15 мин | Колл-менеджеру | Позвонить: продлеваем или снимаем. Продлил срок в заявке → цепочка гаснет | Задача **«Убрать отложку»**, если срок не продлили |
| **Убрать отложку** | Колл-менеджер отзвонился, клиент не продлил | Консультанту магазина | Разобрать отложку, вернуть комплект в зал; расположение позиций возвращается в магазин | Этап не меняем — решение по сделке за колл-менеджером |
| **Собрать для СДЭК** | Доставка встала на «Передан на сборку» | Консультанту магазина | Собрать и упаковать заказ | Этап **«Собран»** |
| **Отнести в СДЭК** | Доставка встала на «Собран» | Консультанту магазина | Сдать посылку в пункт СДЭК | Этап **«Отправлен»** |
| **Забрать со СДЭК** | Доставка встала на «Не выкуплен» | Логисту | Забрать возврат из пункта; позиции получают расположение «СДЭК» (с 20.08 значение единое, без «у нас / у клиента») | Этап не меняем — дальше приёмка на склад |
| **Проштрихкодировать** | В заявке есть позиции без штрихкода | Консультанту магазина | Наклеить штрихкод, сверить позицию с МойСклад | Этап не меняем |
| **Проверить позицию вручную** | Возврат / обмен, где позицию не нашли по штрихкоду | Консультанту магазина | Найти позицию в МойСклад и подтвердить возврат | Этап не меняем |

## Как это выглядит цепочкой

```
Отложка создана на «Ждет товар»
   └─ задача «Сделать перемещение» → консультант оформляет: откуда / куда / позиции
        └─ задача уезжает логисту (центральный склад) или консультанту магазина-источника
             └─ «Отправлено» → товар «В пути»
                  └─ задача «Принять товар» магазину-получателю
                       └─ «Принял» → перемещение в МойСклад + этап «Товар в магазине»
                            └─ задача «Отложить» консультанту
                                 └─ «Отложил» → этап «Товар отложен»
                                      └─ срок вышел → задача колл-менеджеру «Связаться по отложке»
                                           ├─ продлил срок → цепочка гаснет
                                           └─ не продлил → задача консультанту «Убрать отложку»
```

Доставка:

```
«Передан на сборку» → «Собрать для СДЭК» → этап «Собран»
                                  → «Отнести в СДЭК» → этап «Отправлен»
«Не выкуплен» → «Забрать со СДЭК» (логист) → расположение «СДЭК у нас»
```

## Правила, общие для всех задач

1. **Адресуется роль по магазину, а не человек.** Кто из консультантов точки зашёл — тот видит задачу и берёт. График смен не подключаем.
2. **Без дублей.** У каждой задачи ключ идемпотентности вида `reserve:{заявка}`, повторный триггер задачу не удваивает. У просрочки в ключ входит дата отложки — после продления и нового просроченного срока задача появится заново.
3. **Ответственность на источнике.** Перемещение ведёт тот, кто отдаёт товар: центральный склад — логист, магазин — консультант этого магазина.
4. **Закрытые сделки автоматика не двигает.** Если заявка в «Успех» или «Провал», этап меняет только РОП, с указанием причины.
5. **Этап «Провал» по просрочке не ставим** — решение по неактуальной отложке остаётся за колл-менеджером.
6. **Расположение позиций двигают задачи** (с 20.08): «Отложить» → расположение магазина + статус «отложен», «Убрать отложку» → магазин, «Отнести в СДЭК» / «Забрать со СДЭК» → «СДЭК», отправка перемещения → «В пути». Значение единого справочника `ITEM_LOCATIONS`, видно в карточке заявки.
7. **Любое авто-действие пишется в историю изменений** (с 20.08): создание задачи движком, автосмена этапа, синк из amoCRM — с пометкой «авто», отделимой фильтром от ручных действий.
8. **Авторство отложки** (с 20.08): отложка колл-менеджера живёт без консультанта (`callManager` заполнен), продавец проставляется при продаже. Отложка консультанта остаётся его продажей, кто бы её ни выдал.

## Что нужно от Миши

1. Проверить формулировки задач в очередях — они видны консультанту дословно из этой таблицы.
2. Подтвердить, что срок отложки берём из поля «Резерв до» заявки (для компаний — «Отложка до»).
3. Решить по архитектуре воронки (документ `2026-08-06_ВОРОНКА_AMO_ВАРИАНТЫ.md`) — от этого зависит, останется ли «Товар в магазине» этапом или станет полем.
