## 2. Роли листов

| Лист | Роль |
|------|------|
| **Поставка …** (сырьё) | Как заносят приёмщики: блоки модель + сетка размеров; вид часто на уровне комплекта (двойка/тройка) |
| **Поставка … flat** | Нормализованный плоский вид: 1 строка = модель + размер + шт |
| **Справочник** | Эталоны и сокращения: крой, цвет, узор, производитель↔сокр., модель↔сокр., UUID родительских товаров (вид) |
| **Расчеты** | Историческая ручная матрица (пиджак / брюки / жилет…) |
| **Номенкларутра** | Снимок номенклатуры МС для первичного анализа. Перед записью источник правды — **live API МС** |
| **Прогон … / Блокеры …** | Служебные листы пайплайна (статусы match/create/blocked) |
| **Новые модификации / Выгрузка / Дубли** | Старый Excel-контур; новый путь — API |

## 3. Модель данных в МойСклад

| Уровень МС | Смысл у MANSBAND |
|------------|------------------|
| **Товар** | = **Вид** позиции: «Пиджак однобортный», «Брюки», «Жилет»… |
| **Модификация** | Конкретная складская позиция с характеристиками |

Характеристики модификации:

- Размер (в выгрузке иногда опечатка `Рзамер`)
- Ростовка
- Вариация
- Цвет
- Узорность
- Крой

Описание = состав ткани, **каждый компонент с новой строки**:
```
70% шерсть,
20% вискоза,
10% полиэстер
```

Документ складского прихода для этого контура: **Оприходование** (`entity/enter`).

| Поле | Значение |
|------|----------|
| Организация | `MANSBAND` |
| Склад | `Центральный` |
| Дата (`moment`) | дата поставки (для 15.07 → `2026-07-15 12:00:00.000`) |
| Поставщик | не требуется |
| Цена позиции | если нет в источнике — 0 (влияет на себестоимость) |
| Идемпотентность | `externalCode` прогона, напр. `postavka-2026-07-15` |

## 4. Разворот комплекта (двойка / тройка)

Вход может быть комплектом. Перед записью в МС разворачиваем:

| Вид в поставке | Позиции МС |
|---|---|
| Однобортный тройка | Пиджак однобортный + Брюки + Жилет |
| Смокинг тройка | Пиджак от смокинга + Брюки от смокинга + Жилет от смокинга |
| Двубортный двойка | Пиджак двубортный + Брюки |
| Двубортный тройка | Пиджак двубортный + Брюки + Жилет |
| Двубортный на застежке двойка | Пиджак двубортный на застежке + Брюки |
| Двубортный с 1 пуговицей двойка | Пиджак двубортный с 1 пуговицей + Брюки |
| Двубортный с 4 пуговицами двойка | Пиджак двубортный с 4 пуговицами + Брюки |
| Спорт кэжуал двойка | Пиджак кэжуал + Брюки |
| Однобортный оверсайз двойка | Пиджак оверсайз с накладными карманами + Брюки |
| Брюки | Брюки (без разворота, отдельные штуки) |

Кол-во на каждую часть = шт из строки поставки (одинаково на все части комплекта).  
Контроль: `expanded_qty == expected_qty` (двойка ×2, тройка ×3).  
**Факт = сумма размеров**, не ячейка «Всего» в сырье (пример: модель №7 Saco 1180 — размеры дают 45, «Всего» ошибочно 40 → берём **45**).

## 5. Ключ антидубля

**Канон:**

```
Вид + Вариация + Размер + Ростовка
```

- **Вариация** заменяет производитель + модель + артикул.
- **Цвет** и **узор** заложены в артикуле → в ключе не участвуют.
- У комплекта пиджак/брюки/жилет часто имеют одну вариацию+размер+ростовку — поэтому **Вид обязателен**.
- Если антиключ совпал, а **цвет и/или узор** отличаются (или пусты в МС) — **не создаём** новую модификацию: обновляем характеристики найденной позиции в МС значениями из поставки и кладём её в оприходование.

---

## 6. Формула вариации

```
Вариация = сокр.производителя + артикул + сокр.модели
```

Пример: `S` + `04/549` + `BC-5000` → `S04/549BC-5000`.  
Если **сокр. модели — только цифры**, отделяем дефисом: `AR` + `70/710` + `1186` → `AR70/710-1186` (не `AR70/7101186`).

Сокращения — только из **Справочник**. Без однозначного abbr строка идёт в **Блокеры**, в МС не пишем.  
Новые модели/бренды сразу дописываем в справочник (**одна модель = одно сокр.**).  
Если в справочнике у одного имени несколько разных сокр. — **блок** (`ambiguous_*_abbr`), в МС не пишем.  
Известный техдолг справочника (в поставке 15.07 не используются): `337`, `117`, `2001`.

Безопасные нормализации до lookup: `saco`→`Saco`, `milan10`→`Milan 10`, trim/регистр.

Если **производитель пуст** — вариация без префикса бренда: `артикул + сокр.модели` (пример: `05/051APP`).

## 7. Код модификации

- **Целевой код = Вариация** (может повторяться у разных видов/размеров).
- На **CREATE** API требует уникальный code → временный `CristalNNNN`, затем batch-UPDATE `code = вариация`.
- На **UPDATE** неуникальный code допустим (проверено: 18 позиций с одним `S70/843M10`).
- Ускорение: `POST /entity/variant` массивом (chunk 50), timeout 180с + verify после таймаута.
- Массовый прогон всего каталога: `scripts/supply_pipeline/batch_code_eq_variation.py` (`--scan` → `--apply` / `--resume`), state в `_private/batch_code_eq_variation/`.
- Повторный запуск: сначала live-поиск по антиключу; найденное не создаём заново.

## 8. Целевой контур

```
Сырьё / flat
  → разворот двойка/тройка
  → вариация по справочнику
  → агрегирование одинаковых антиключей (sum qty)
  → поиск в Номенкларутра (черновик) + live API МС
      ├─ 1 match, цвет/узор ок → UUID в оприходование
      ├─ 1 match, цвет/узор отличаются → UPDATE хар-к в МС → UUID в оприходование
      ├─ 0 match → создать модификацию (API) → UUID
      └─ >1 / нет abbr → Блокеры
  → одно оприходование (organization=MANSBAND, store=Центральный)
    с stable externalCode прогона (напр. postavka-2026-07-15)
```

Код пайплайна: `2. БИЗНЕС/04_Производство/Активные/MANSBAND/scripts/supply_pipeline/`.
