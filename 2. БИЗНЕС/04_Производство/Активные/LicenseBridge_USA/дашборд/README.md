## Определение WON

**Выиграно** = первый переход сделки в Closed-won (`status 142`) внутри Pipeline. «В производстве» по-прежнему считается по переходу того же `lead_id` в воронку «Сборка». Согласовано с Павлом 26.08.2026.

## Источник данных

Read-only срез Kommo API v4 (`licensebridgeusa.kommo.com`, account_id `34679511`) от **2026-07-22**: 1634 сделки, 3431 событие смены ответственного, 408 открытых задач, 10 причин отказа. Числа в прототипе — реальные обезличенные агрегаты этого срез, не выдумка и не рыночные ориентиры.

## Что показано

- **Вкладка РОП:** воронка сейчас (KPI за всё время / за 30 дней), сделки по этапам, очередь и просрочки (с фильтром по менеджеру), эффективность менеджеров — **только за последние 14 дней** (см. пояснение в самом прототипе — раньше состав команды был другим, атрибуция ненадёжна).
- **Вкладка Маркетинг:** причины отказов (с индикатором полноты 41.6%), то немногое, что есть по источникам (Channel заполнен на 6.7%), блок «что не считаем и почему» по всем финансовым метрикам клиента.

## Главное, что нашёл аудит (см. паспорт метрик для деталей)

1. Команда в Kommo сменилась полностью с прошлого созвона (18.06.2026) — 4 из 6 менеджеров уже не в системе.
2. 82.8% отказов за всё время показывают текущего ответственного неверно (переназначения) — менеджерский разрез сделан только на восстановленном по событиям и стабильном окне (14 дней).
3. `Channel`/`utm_source` заполнены у 6.7%/1.6% сделок — источник трафика практически не прослеживается в текущих данных.
4. Экономика (Spend/CPL/CAC/выручка/ROI) — исключена: в Kommo нет расходов на рекламу, а `price` заполнен у 20–30% сделок.
5. Очередь/просрочки — самый надёжный блок: 3 из 320 открытых сделок без задачи, 199 (62%) с просроченной задачей.
