# Телефония, IVR и Pleep — простой разбор и цена

**Дата:** 2026-07-25 (обновлено — прочитана официальная документация docs.pleep.app)

## Контекст

Павел прислал схему (Meta → Kommo → WhatsApp → голосовой AI → SMS → задача), затем формальный документ **`LicenseBridge USA — AI Sales Automation Architecture v2`** с комментарием: «отправляю на оценку, так как все функции практически настраиваются на стороне сервера через API».

Первый разбор был по маркетинговому сайту pleep.app. Сейчас прочитал **официальную документацию** (docs.pleep.app) — разделы «Интеграции», «Голосовой агент», «Публичный API», «Рассылки», «Улучшение агента». Часть выводов подтвердилась, но нашлась одна важная техническая деталь, которая, похоже, объясняет, почему тест робота 24.07 не прошёл.

## Что умеет Pleep сам, без разработки (подтверждено по докам)

- **Каналы** — WhatsApp (несколько вариантов, включая совместный режим с живым оператором), Instagram, Telegram, веб-виджет — подключаются в панели в один клик. [Источник](https://docs.pleep.app/ru/integrations)
- **CRM (amoCRM/Kommo)** — родная интеграция: подтягивает воронки, этапы и кастомные поля автоматически. В интерфейсе настраиваются: (а) автозаполнение любых полей CRM по условию на естественном языке («для поля X — когда клиент скажет Y»), (б) правила автоматического перемещения сделки по этапам воронки. Без кода. [Источник](https://pleep.app/ru/changelog/better-amo-crm-integration)
- **Обучение поведения агента** («Улучшение») — отдельный чат-интерфейс: описываешь проблему словами («отвечай короче», «не называй цену без уточнения штата») — система сама переписывает инструкции агента. Есть готовые шаблоны. Без кода. [Источник](https://docs.pleep.app/ru/improvement)
- **Рассылки / follow-up** — 4 типа (WhatsApp, WABA-шаблоны, гибрид с оператором, голосовая рассылка): фильтр аудитории, подстановка переменных, отложенная отправка, повтор при неудаче. Это и есть механизм «повторного касания, если клиент не ответил». [Источник](https://docs.pleep.app/ru/broadcasts)
- **Саммари разговора, извлечение LLM** — встроено в основной AI-агент, отдельно интегрировать LLM не нужно.

Вывод не изменился: 8-этапный AI-пайплайн из PDF — это **настройка Pleep**, а не наша разработка.

## Новое и важное: голосовой агент — своя логика, не «SIP-трубка в нашу АТС»

В доках чётко написано: голосовому агенту Pleep **присваивается собственный уникальный виртуальный номер** при подключении — не «регистрация в существующий SIP-транк клиента». [Источник](https://docs.pleep.app/ru/voice-agent)

Это, по всей видимости, и есть причина, почему **тест на номер 646 24.07 не прошёл** — Павлу передавали SIP-данные аккаунта 103 на нашем Asterisk (`159.65.97.156`), чтобы «подключить робота к нашей схеме», но штатный способ работы Pleep — не «зайти в чужой транк», а «выдать свой номер и вести звонок целиком у себя».

**Хорошая новость: это не усложняет, а упрощает нашу часть.** Правильная архитектура:

- Pleep выдаёт Павлу отдельный номер для голосового агента.
- На нашем Asterisk в нерабочее время (или после N секунд без ответа живых менеджеров) мы просто **переадресуем звонок на этот номер** (`Dial()` на внешний SIP-URI/номер Pleep) — это одна строка в диалплане, а не отдельный SIP-аккаунт с конфликтами регистрации.
- Также подтверждает связность: после звонка тот же AI продолжает диалог в WhatsApp с полным контекстом — это тоже нативно, без нашего кода.

Дополнительно уточнил: голосовой агент помечен **Beta** и требует тариф **PRO**. [Источник](https://docs.pleep.app/ru/voice-agent)

## Важное уточнение по API — сузили ожидания

Публичный API Pleep v1 — **не универсальный API интеграций**, а узкая функция: отправка одобренных WhatsApp-шаблонов (broadcast) из внешних систем, лимит 30 запросов/мин. [Источник](https://docs.pleep.app/ru/api)

То есть тезис Павла «всё настраивается через API» — верен в смысле «не нужно ничего кодить», но не в смысле «мы будем дёргать API Pleep из своего хаба». Все интеграции (CRM, каналы, поведение) настраиваются **в панели Pleep**, а не через API-запросы с нашей стороны. Наш `/pleep/sync` в этой схеме, скорее всего, не понадобится вовсе — обмен с Kommo Pleep делает сам.

## WhatsApp — как подключать, чтобы не потерять номер

Отдельно разобрал риск блокировки номера — он реален, но управляемый.

- Сейчас WhatsApp подключён через **Wazzup**, скорее всего в режиме **личный номер / QR** (официальную Cloud API интеграцию готовили как отдельный контур на будущее — она не активирована).
- **Официальная интеграция WhatsApp Business API (Coexistence)** технически несложная (мастер + QR-код с телефона, 30–60 минут + до суток на подгрузку истории), но это **отдельная регистрация номера у Meta** — она не гарантированно совместима с уже работающей QR-сессией Wazzup. Есть риск, что при активации Coexistence слетит текущая сессия Wazzup и её придётся пересканировать / временно возникнут дубли чатов.
- Причина блокировки номера в Wazzup — **не сам факт подключения стороннего сервиса** (WhatsApp технически не отличает Wazzup от обычного «связанного устройства»), а **массовая автоматическая рассылка без согласия получателей**. Собственная база знаний Wazzup прямо пишет: обработка входящих диалогов — безопасно, рассылки с личного номера — риск бана. [Источник](https://wazzup24.ru/help/how-to-use/bans-in-whatsapp-ru/)

**Рекомендация — самый безопасный путь:**

- Подключить Pleep **не отдельной Coexistence-регистрацией**, а через уже работающий канал **Wazzup** (у Pleep есть нативная интеграция с Wazzup). Номер не трогаем, ничего не переключаем.
- Пока Pleep только **отвечает на входящие** от лидов (как сейчас делают Илона/Елена/Полина) — риск бана не выше сегодняшнего.
- Функцию **follow-up (повторное касание неответившим)** — если делать её массово по большой пачке лидов одновременно, это уже похоже на автоматическую рассылку и повышает риск бана личного номера. Для такого объёма рассылок правильнее завести отдельный официальный WABA-канал именно под рассылки, не смешивая с диалоговым номером. Для повторного сообщения в рамках одного диалога с одним клиентом — это безопасно и не требует WABA.

## Что реально требует разработки от нас

**1. Телефония — единственный настоящий кусок кода.**
Голосовое меню (IVR) и карусель распределения звонков между **живыми** менеджерами (Илона, Елена, Полина) в рабочее время + переадресация на номер голосового робота Pleep в нерабочее время / при отсутствии ответа. Делается на нашем Asterisk-сервере (`159.65.97.156`), через уже готовый резолвер ответственного (`/internal/responsible/resolve`). Стало проще, чем думали изначально — не нужен отдельный конфликтующий SIP-аккаунт, только переадресация вызова.

**2. Настройка Pleep + Kommo — конфигурация, не код.**
- Создать в Kommo недостающие поля (штат, тип лицензии, опыт — сейчас их нет).
- Подключить Pleep к каналам (WhatsApp, Telegram) и к Kommo.
- Указать в панели Pleep, какие поля заполнять и в какую воронку/этап двигать сделку.
- Настроить follow-up-рассылку (повторное касание, если клиент не ответил).
- Обучить поведение агента через «Улучшение» под сценарий LicenseBridge.
- Протестировать на живых лидах.

**3. Голосовой агент Pleep — только конфигурация в его панели** (голос, скрипт, первое сообщение), плюс со стороны нашего Asterisk — переадресация вызова на выданный Pleep номер (см. выше, входит в п.1).

## Что нужно уточнить у Павла / у поддержки Pleep

- Тариф аккаунта — голосовой агент требует **PRO** ($226/мес по прежним данным сайта). Без него функция может быть недоступна вообще, а не «работать вручную через API» — публичный API её не подменяет.
- Совместимость: интеграция в доках названа «amoCRM» — Kommo это тот же продукт (международная версия), API идентичен, но стоит явно проверить при первом подключении, что Pleep корректно видит домен `kommo.com`, а не только `amocrm.ru`.
- Попросить у поддержки Pleep номер, который они выдадут под голосового агента, **до** того как мы напишем переадресацию в Asterisk — чтобы не тестировать вслепую второй раз.
- Подтвердить, что Pleep подключается к WhatsApp именно через существующий Wazzup (не через отдельную Coexistence-регистрацию) — чтобы не трогать номер.

## Цена — вилка по WABA

Follow-up (повторное касание неответившим лидам) массово безопасен только на официальном WABA-канале (см. раздел выше про блокировку номера). Отсюда два варианта:

### Вариант A — без WABA (только Wazzup, как сейчас)

Follow-up-рассылку **не встраиваем в автоматическую логику** агента — риск бана личного номера со временем слишком высок. Агент отвечает на входящие, ведёт диалог, заполняет CRM — но сам не рассылает повторные сообщения неответившим пачками.

| | Часы | Цена |
|---|---|---|
| Мало (демпинг) | — | до 30 000 ₽ |
| **Справедливо** | 14–17 ч × 4 000 ₽/ч | **56 000–68 000 ₽** |
| Много (необоснованно) | — | от 95 000 ₽ |

**Называть: 60 000–65 000 ₽.**

### Вариант B — с официальным WABA-каналом

Дополнительно подключаем официальный WABA (отдельно от личного номера, под рассылки) — тогда follow-up-автоматику можно безопасно включить в логику агента.

| | Часы | Цена |
|---|---|---|
| Мало (демпинг) | — | до 45 000 ₽ |
| **Справедливо** | 19–24 ч × 4 000 ₽/ч | **76 000–96 000 ₽** |
| Много (необоснованно) | — | от 130 000 ₽ |

**Называть: 85 000–90 000 ₽.**

⚠️ Верификация бизнеса в Meta для WABA — **1–7 рабочих дней**, это не наше время и не зависит от нас. Follow-up-автоматика в варианте B физически заработает только после того, как Meta одобрит номер — то есть к среде (30.07) может не успеть, даже если мы всё настроим.

### Разбивка часов

- Телефония (IVR, карусель, переадресация на номер робота Pleep) — одинаково в обоих вариантах: 8–12 ч.
- Настройка Pleep (каналы, CRM-интеграция, автозаполнение полей, обучение поведения) + Kommo-поля + тест: 6–7 ч.
- Только в варианте B: подключение официального WABA (шаблоны, верификация, тест) + настройка follow-up-автоматики: +5–7 ч.

Ставка 4 000 ₽/час — публичная ставка MS Product на допработы вне проекта (используется в Billboardoff).
