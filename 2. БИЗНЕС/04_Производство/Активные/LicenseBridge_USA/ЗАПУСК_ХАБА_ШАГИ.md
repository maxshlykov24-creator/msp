### Что проверено вживую, а не «по таймеру»

Вместо суток ожидания прогнали через хаб всю реальную базу и по одному тестовому
объекту на каждый этап. Это вскрыло **пять** дефектов, которые сутки наблюдения не
показали бы:

| Дефект | Чем грозил | Статус |
|---|---|---|
| Поиск контакта по телефону не видел половину дублей (в CRM номера записаны в трёх форматах) | хаб сам плодил бы дубли при приёме заявок | исправлено |
| Карточки «Autocontact +1» считались одним человеком | склейка чужих контактов | исправлено |
| Дубль на втором номере карточки не находился | пропуск дублей | исправлено |
| Комментарии менеджеров с карточки дубля не переносились | терялись после уборки | исправлено |
| Сделка не переезжала на основную карточку (Kommo ждёт другое поле в API) | удаление дубля вместе с его сделкой | исправлено, добавлен предохранитель: не переехала сделка — склейка отменяется |

## Главный ответ: новая интеграция в Kommo НЕ нужна

Подписка на вебхуки (`add_lead`, `status_lead`, `add_contact`, `update_contact`)
создаётся через `POST /api/v4/webhooks` **тем же долгосрочным токеном** уже
существующей частной интеграции (та, что используется для анализа CRM; scope `crm`).
Проверено 2026-07-24: токен читает `/account` и `/webhooks` (видны Teletype, Wazzup24,
отключённый Make).

**Redirect URI нужен только для OAuth** (как у Make.com). Наш сервис ходит по
Bearer-токену и принимает вебхуки на свой URL — редирект в схеме не участвует.

## Про «этапы включения флагов» — решать не нужно

Раньше требовалось вручную решать, когда включать каждый флаг. Теперь это делает
сервер (`AUTO_ROLLOUT=true`): он идёт по лестнице сам и останавливается при первой
же ошибке.

| Этап | Что делает | Состояние |
|---|---|---|
| 0 `shadow` | только считает решения | пройден |
| 1 `assignment` | ставит ответственного на новые лиды (Илона / наследование), воронку «Сборка» не трогает | **включён, проверен вживую** |
| 2 `deals` | убирает дубль-сделки (примечания переносит), сворачивает Pipeline→Сборка | **включён, проверен вживую** |
| 3 `contacts_no_chat` | склеивает контакты без переписки | **включён, проверен вживую** |
| 4 `contacts_light` | склеивает контакты с коротким читаемым чатом | включится сам через сутки; в этом аккаунте бездействует — сообщений мессенджеров в карточках нет |

Любая ошибка обработки, затор очереди или расхождение конфигурации — продвижение
замирает на текущем этапе (назад само не откатывается, поведение не «мигает»).

Контроль в браузере: страница статуса из `ДОСТУПЫ.md` — видно этап, что уже включено,
очередь, ошибки, решения за сутки, очередь ручной склейки.

Если нужно вмешаться: «пауза», «назад в shadow» — одна команда, без передеплоя
(раздел 3 и 8 в `RUNBOOK.md`).

## Ограничение Kommo: удалять карточки из API нельзя

Проверено на боевом аккаунте 2026-07-24: `DELETE` сделки/контакта возвращает `405` —
платформа не даёт удалять через API (только вручную в интерфейсе). Поэтому дубль
сервер **обезвреживает**: переносит примечания, звонки и сделки на основную карточку,
а сам дубль помечает тегом **`дубль_удалить`**. Работы на нём не остаётся, статус не
меняется — конверсия в отчётах не искажается.

Физическая уборка — раз в неделю, 30 секунд: фильтр по тегу `дубль_удалить` →
выделить всё → удалить.

**Опция «Архив дублей».** Если не хочется видеть помеченные дубль-сделки в рабочих
воронках до уборки, можно завести отдельную воронку «Архив дублей» — сервер будет
сразу переносить их туда (`ARCHIVE_PIPELINE_ID` в `.env`). Это добавляет одну воронку
в интерфейс Kommo; без неё дубль остаётся на месте, но с тегом и без работы.
