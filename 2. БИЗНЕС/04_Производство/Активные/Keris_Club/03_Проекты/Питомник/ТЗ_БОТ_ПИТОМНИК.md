# ТЗ — Telegram-бот Keris Club: Модуль «Питомник»

**Версия:** 1.1 · **Дата:** 2026-06-25 (обновлено после встречи с Леной 24.06)  
**Связано:** [ТЗ_ЭТАП0_ПИТОМНИК.md](ТЗ_ЭТАП0_ПИТОМНИК.md) · [ДОСТУПЫ.md](../../06_Доступы/ДОСТУПЫ.md) · [2026-06-24_РЕШЕНИЯ_ВСТРЕЧИ_С_ЛЕНОЙ.md](../../04_Встречи/2026-06-24_РЕШЕНИЯ_ВСТРЕЧИ_С_ЛЕНОЙ.md)

> Клиентский бот для приёма заявок и показа витрины щенков. Фокус — питомник (Модуль 1). Груминг и передержка добавляются позже отдельными сценариями.

> **Уточнение модели (24.06.2026).** Бот — это **витрина щенков + квалификация + передача в номерной канал**, а не live-chat менеджера через amoCRM Chat API. Карину в CRM не заводим: живое общение остаётся в её Telegram (рабочий номер подключён к amoCRM номерным каналом), а распределение по воронкам/этапам и автосообщения делает **ИИ**. Бот квалифицирует лида (холодный / тёплый / горячий): горячего сразу переводит в номерной Telegram с контекстом «хочу вот этого малыша», холодного — на канал + в базу под прогрев. Везде, где ниже сказано «задача менеджеру», читать как «лид попадает в воронку → ИИ-распределение / перевод в номерной к Карине».

---

## 1. Назначение и роль в системе

```
Пользователь → Telegram-бот → FastAPI-сервер → amoCRM
                                              ↳ Сделка «Продажи» (Новая заявка)
                                              ↳ Контакт владельца
                                              ↳ Источник = «Телеграм-канал»
                          ↳ Горячий лид → перевод в номерной Telegram Карины
                                          (с контекстом «хочу вот этого малыша»)
amoCRM ← номерной канал (рабочий Telegram Карины) ← живая переписка
       ↳ ИИ распределяет по воронкам/этапам + автосообщения
```

Бот **не хранит данные** — всё передаётся на сервер. Данные о щенках берёт из amoCRM (воронка «Щенки», этап «Свободен»). Живое общение ведётся **не в боте**, а в номерном Telegram Карины (подключён к amoCRM); распределение и автосообщения — на стороне ИИ.

## 3. Сценарии (flows)

### 3.1 /start — первый запуск

**Триггер:** команда `/start` или первое обращение.

**Логика:**
1. Записать `telegram_id` → проверить на сервере, был ли контакт с этим ID раньше.
2. Если новый — показать полное приветствие.
3. Если возвращается — короткое приветствие + главное меню.

---

### 3.2 Витрина щенков

**Триггер:** кнопка «🐾 Смотреть щенков».

**Логика:**
1. Сервер запрашивает amoCRM: сделки в воронке «Щенки» (ID `11036834`), этап «Свободен» (ID `86718366`).
2. Если щенков нет → сообщение «Сейчас все щенки нашли хозяев».
3. Если есть → карточки по одной (пагинация кнопками «← / →») или списком.

**Карточка щенка:**
- Фото (если есть URL в поле «Фото/видео»)
- Основные данные
- Кнопка «Узнать подробнее / Забронировать»

---

### 3.3 Сценарий «Оставить заявку»

Линейный диалог. Каждый шаг — одно сообщение. Пропуск только для необязательных полей.

**Шаги:**

| # | Бот спрашивает | Валидация | Сохраняем |
|---|----------------|-----------|-----------|
| 1 | Имя | текст, не пустой | `name` |
| 2 | Телефон | формат +7/8 + кнопка «Поделиться номером» | `phone` |
| 3 | Предпочтения (пол, окрас) | необязательно, кнопка «Пропустить» | `preferences` |
| 4 | Согласие ПДн | обязательно, кнопки «✅ Согласен / ❌ Не согласен» | `consent` |

После шага 4:
- Если согласен → отправить на сервер → создать сделку + контакт в amoCRM → подтверждение.
- Если не согласен → объяснить и предложить вернуться позже.

---

### 3.4 Подбор конкретного щенка через витрину

**Триггер:** кнопка «Узнать подробнее / Забронировать» на карточке щенка.

**Логика:**
1. Показать полную карточку щенка.
2. Кнопка «📋 Хочу этого щенка» → запуск сценария заявки (3.3), но с предзаполненным предпочтением = кличка щенка.
3. В amoCRM сделка «Продажи» создаётся с заполненным полем «Запрос/предпочтения» = `«{кличка}»`.

## 6. Поведение при ошибках

| Ситуация | Бот |
|----------|-----|
| amoCRM недоступен | «Временно не можем показать щенков. Оставьте заявку — перезвоним вручную.» |
| Щенок уже не свободен (забронирован пока смотрел) | «Этот щенок только что нашёл хозяина 🥲 Смотреть других?» |
| Неверный формат телефона | «Кажется, номер введён неправильно. Попробуйте ещё раз в формате +7XXXXXXXXXX» |
| Пользователь ввёл текст вне сценария | Сообщение 4.12 + главное меню |

## 7. Передача данных в amoCRM

При создании заявки сервер:

1. Ищет контакт по телефону (дедупликация).
2. Если не найден — создаёт контакт с полями: `Имя`, `Телефон`, `Согласие ПДн` = да, `Дата согласия ПДн` = сейчас.
3. Создаёт сделку в воронке «Продажи» (ID `11036674`), этап «Новая заявка» (ID `86717266`).
4. Заполняет:
   - `Источник сделки` = `Телеграм-канал`
   - `Запрос/предпочтения` = текст из шага 3 (если заполнено)
   - `Температура лида` = холодный / тёплый / горячий (по квалификации в боте)
5. Дальнейшая маршрутизация (модель 24.06.2026):
   - **горячий** → перевод в номерной Telegram Карины с контекстом заявки (без задачи в CRM — Карина в CRM не работает);
   - **тёплый/холодный** → остаётся в воронке «Продажи»; **ИИ** распределяет по этапам и шлёт согласованные автосообщения; предложить подписку на канал.

## 9. Открытые вопросы

1. **MAX-бот** — логика идентичная, только канал другой. Делаем в той же кодовой базе через `source` = `MAX`. Реализуем после Telegram (на старте — резерв, см. решения встречи).
2. **Перевод горячего лида** — в номерной Telegram Карины (рабочий номер, подключённый к amoCRM номерным каналом). Уточнить юзернейм/ссылку для перевода и текст контекст-сообщения.
3. **ИИ-распределение** — нейросеть анализирует переписку из номерного канала, раскладывает по воронкам/этапам и шлёт автосообщения от имени Keris Club. Шаблоны автосообщений согласовать с Кариной.
4. **Фото щенков** — хранятся как URL в amoCRM. Нужно убедиться, что ссылки публичные (не Drive с ограниченным доступом).
