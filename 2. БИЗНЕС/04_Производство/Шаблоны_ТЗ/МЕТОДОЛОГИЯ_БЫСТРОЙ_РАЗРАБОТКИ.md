# Методология быстрой разработки под ИИ-агента (Docker/Caddy/FastAPI/React)

> Источник: разбор транскрипта [«Проект за 100к на вайбкодинге»](../../06_Маркетинг/_ai/2026-07-02_YouTube_вайбкодинг_100k_транскрипт.md) (Е. Пантела). Применимо к проектам, где нужен кастомный веб-сервис / Telegram Mini App / клубная система «заявка → одобрение → оплата → доступ», а не типовая интеграция amoCRM/МойСклад. Дополняет [`МЕТОДОЛОГИЯ_ДОСТАВКИ.md`](МЕТОДОЛОГИЯ_ДОСТАВКИ.md) (та — про процесс работы с клиентом, эта — про инженерный контур и работу с ИИ-агентом).

## 1. Дефолтный стек (не изобретать заново на каждом проекте)

| Слой | Технология | Почему |
|------|-----------|--------|
| Инфраструктура | Docker (весь проект в контейнерах) | Ноль ручных зависимостей на сервере, воспроизводимо, чисто |
| Reverse-proxy / HTTPS | Caddy | Автоматический сертификат, не требует ручной настройки nginx |
| Backend | FastAPI (Python) | Самый популярный фреймворк — агент пишет на нём стабильнее всего |
| Frontend | React | Дефолт, в т.ч. для Telegram Mini App (это просто сайт, завёрнутый в Telegram) |
| БД | PostgreSQL, в своём docker volume | Чёткая структура (таблицы/колонки), выдерживает рост |
| VCS | Git + приватный репозиторий на GitHub, коммит на каждом шаге | История изменений = возможность откатиться |

Отклоняться от стека — по явной причине (ограничение клиента, готовая инфраструктура), не по умолчанию.

## 2. Архитектурный паттерн «заявка → одобрение → оплата → доступ»

Переиспользуемая схема для любого B2B/B2C онбординга с фильтрацией и оплатой (клубы, курсы, закрытые сообщества, whitelabel-доступы):

1. Клиент заходит в Mini App / веб-форму → заполняет заявку (лендинг → форма → страница успеха).
2. Бэкенд кладёт заявку в БД, бот/уведомление сообщает админу.
3. Админ через отдельную CRM/admin-webapp принимает или отклоняет.
4. Если принято — клиенту летит ссылка на оплату (реализуется как отдельный webhook-эндпоинт).
5. После подтверждения оплаты — выдаётся доступ, статус в CRM обновляется.

Статусная модель: `новая → в процессе → отклонена / ждёт оплаты → оплачено → доступ выдан`.

При старте похожего проекта — не проектировать схему с нуля, а адаптировать эту.

## 3. Как ставить задачи ИИ-агенту (Claude Code / Codex) на новом проекте

- **Не давать один гигантский промпт.** Дробить на логические блоки, между блоками — проверка:
  1. Инфраструктура: подключение к серверу, Docker, Caddy, GitHub-репо, тестовая HTTPS-страница.
  2. Frontend + backend + БД — одним блоком (это связанные вещи).
  3. Админка/CRM + вебхуки + оплата — отдельным блоком.
- **Первым запросом фиксировать стек и принципы в правила проекта** (AGENTS.md/CLAUDE.md/`.cursor/rules`) — «всё в докере, всё через Caddy, no ручных зависимостей» — чтобы агент не отклонялся дальше по ходу работы.
- Требовать, чтобы **агент сам тестировал результат** (Playwright на проде), а не верить сводке на слово.
- Просить сводку после каждого блока: что сделано, что установлено, рабочая ссылка.
- Промпт-цепочка для сложных кусков: сначала в топовой модели с расширенным мышлением (ChatGPT extended / аналог) сформировать серию самостоятельных промптов под задачу → по одному скармливать кодящему агенту.
- Приём для экономии лимитов: заархивировать репозиторий → закинуть в мощную модель → «найди баги/точки роста, выдай 10 самостоятельных промптов, каждый закрывает одну проблему» → эти промпты по очереди в очередь агенту.
- Инженерный принцип: по шагам, с проверкой на каждом шаге; не наращивать функциональность поверх непроверенного фундамента.

## 4. Инфра-чеклист для российских проектов с Telegram

- Сервер — российский (обязателен по 152-ФЗ при работе с рос. бизнесом/ПДн, это и аргумент продажи).
- Telegram Bot API не работает напрямую из РФ → исходящий трафик с сервера должен идти через VPN.
- Входящее SSH-соединение — напрямую (не через VPN), чтобы сессия не рвалась и оставалась стабильной.
- Домен: A-запись на IP сервера у регистратора (reg.ru и т.п.) — занимает ~5 минут, финальный штрих перед сдачей.

## 5. Бизнес-приёмы (защита маржи и переговоры)

- **Лимит правок в договоре/переписке**: например, 3 бесплатных круга правок, дальше — доплата за отдельные правки. Фиксировать текстом до старта работ.
- **Ценовой референс**: система класса «Mini App + backend + БД + admin/CRM + вебхуки + оплата» рыночно оценивается в районе 100 000 ₽ при фриланс-найме; при грамотной постановке задач ИИ-агенту собирается за часы. Использовать как опорную точку при оценке похожих внедрений, не как готовую цену — сверяться с фактической сложностью и пакетом.
- Роадмап «последних доработок» перед сдачей — обычно один промпт на каждую: подключить домен, подключить реальную кассу (например Robokassa), уведомления об оплате, рекуррентные платежи. Держать этот список под рукой, чтобы не забыть в чек-листе сдачи.

## Как использовать

- При старте проекта с кастомной разработкой (не типовая amoCRM/МойСклад-интеграция) — сверяться с этим файлом перед тем, как формулировать промпты агенту.
- При появлении нового приёма из практики — дополнять этот файл, а не создавать параллельный.
